# 01. 통계표 읽는 법

통계표(=테이블)는 DP팀이 테이블 가이드를 받아 만든 문항별 집계표다. `.xls`(BIFF8 OLE2) 로 온다.
**보고서의 모든 숫자는 여기서만 나온다.** 제작본이나 원자료에서 다시 계산하지 않는다.

실측 대상: `projects/2026_에스원_건물현황실사/02_비상주/input/비상주_통계표_0821_1925.xls` (90표 / 배너 15~45열 가변)

---

## 1. 파일 구조

시트가 2장이다.

| 시트 | 내용 |
|---|---|
| `목 차` | 표 번호(1..N) + 표 제목. **이게 보고서 페이지 목차의 원본**이다 |
| `Table` | 표 90장이 세로로 이어 붙은 한 장의 시트 |

표와 표 사이는 **빈 행 1줄**로만 구분된다. 표 경계는 A열의 제목행(`SQ1.` `A7.` `응답자 특성` 등)으로 찾는다.

---

## 2. 표 1장의 물리적 레이아웃

```
행 +0   제목행            A열: 'A7. 중요 관리 업무_1순위'
행 +1   배너 그룹 헤더     B열:'전체'  C열:'용도'  I열:'권역'  O열:'관리 운영 방식' …
행 +2   배너 세부 헤더                 C~H:'공동주택'…'기타 용도'  I~N:'도심권'…'분당구'
행 +3   Base for %        A열:'Base for %'  B열:'(500)'  C열:'(50)' …   ← 전부 문자열
행 +4~  데이터 행          A열:'  4) 시설 및 설비 유지보수…'  B열:28.4  C열:26.0 …
행 +n         계          A열:'      계'  B열:100.0 …                   ← 앞 공백 6칸
행 +n+1 요약 행           【BOT2】 → 【SoSo】 → 【TOP2】 → [5점 평균]
(빈 행 1줄)
```

### 열 구조 — 표1만 예외
| | 행 라벨 | 전체 | 배너 |
|---|---|---|---|
| **일반 표** | A열 1칸 | **B열** | C열~ |
| **표1 (응답자 특성)** | A열(특성군) + B열(보기) **2칸** | **C열** | D열~ |

⚠ 파서에 오프셋 분기가 필요하다. 표1은 항상 첫 표이고 항상 `응답자 특성` 이다.

> "테이블 맨 처음은 항상 응답자 특성으로 시작해요. 이 응답자들이 어떤 특성을 가지고 있는지에 나타난 표거든요." (녹취 20:30)

### 배너 (열 = 교차분석 축)

★ **열 수는 표마다 다르다.** DP가 표마다 base 0 인 배너 범주를 통째로 빼기 때문이다.
비상주 실측: 전체 배너 열 **15~45** (41열이 58표로 최빈), 보고서 IN 열 **6~17** (17열이 61표).
표42(B8)·표56(C4-1)에는 오히려 배너군이 **하나 더** 붙어 있다 (`가장 중요한 위탁 서비스`, `우선 도입 희망 업무` — 각 7표).

**→ 절단선은 열 위치가 아니라 그룹명으로 판정해야 한다.** 위치로 자르면 깨진다.

아래는 41열인 표(최빈)의 예시다:

| 배너군 | 셀 수 | 열 |
|---|---|---|
| 전체 | 1 | B |
| 용도 | 6 | C~H |
| 권역 | 6 | I~N |
| 관리 운영 방식 | 4 | O~R |
| ══ **절단선** ══ | | |
| 건물 연면적 | 4 | S~V |
| 소유 형태 | 5 | W~AA |
| 지역지구 | 6 | AB~AG |
| 건물 준공연도 | 4 | AH~AK |
| 입주사 수 | 5 | AL~AP |

> "오빠가 보고서에 쓸 거는 용도부터 관리 운영 방식까지만 보고서에 들어갈 거예요. 이 뒤는 (…) 아무리 유의미해도 안 쓸 거예요." (07:44~08:24)

**IN = 그룹명이 `전체` · `용도` · `권역` · `관리 운영 방식` 인 열** (이 표에서는 17열).
절단선은 `일부 외부 전문업체 위탁` 직후 ↔ `400평 미만` 직전이지만, **경계를 열 번호로 기억하지 않는다.**

절단 근거는 통계 목적이 아니라 **보고서 목적**이다.
> "보고서상으로 크게 중요하지 않다고 보는 거죠." (09:33) / "입주자 수는 걔네가 건물 하는 애들한테 중요한 거지 (발주처)한테 중요한 건 아니니까" (09:38)

배너 구성 자체는 연구팀이 데이터를 보고 미리 정한 암묵지이고 **보고서에 근거를 적지 않는다** (09:57~10:08).

## 3. 숫자 서식 — ★ 저장값이 아니라 표시값을 쓴다

| 대상 | number format | 자릿수 |
|---|---|---|
| % | `###0.0` | 소수 **1자리** |
| 평균 | `###0.00` | 소수 **2자리** |
| Base | (문자열) | `(500)` 형태, 숫자가 아니다 |

**셀에 저장된 값은 반올림되지 않은 부동소수다.**

```
표시:  8.4        저장: 8.391608391608392
표시: 76.4        저장: 76.4
표시:  3.83       저장: 3.825174825174825
```

전체 열은 n=500이라 대부분 1자리로 딱 떨어지지만, 배너 셀은 분모가 143·82 같은 수라 무한소수가 된다.

> **보고서 수치는 반드시 서식 적용 후 값(=반올림된 값)을 쓴다.** 저장값을 그대로 쓰면 합계가 안 맞고, 멘트와 차트 라벨이 어긋난다.

소수점 규칙의 출처:
> "한 자리 무조건 한 자리 소수점은 다 한 자리. 아 근데 5점 척도 100점 전환 척도는 두 자리까지 들어가긴 해요." (12:23)
> "평균 몇 점 평균 이거는 소수점 두 자리까지 나와요." (32:47)

NPS도 2자리다 — SKEE 실측 `추천 의향은 -17.86점(NPS 점수)으로 미흡한 수준임`.

## 4. 행 규약

### 4-1. 응답 0인 보기는 행 자체가 삭제되어 온다
A8 척도 표 실측: `2) 불만족` → `3) 보통` → `4) 만족` → `5) 매우 만족`.
**`1) 매우 불만족` 행이 없다.** 응답이 0이기 때문이다. 보기 번호가 건너뛴 채로 오면 그대로 둔다.
(LG 가이드에서도 `1) 1전혀 그렇지 않다` → `3) 3` 처럼 `2) 2` 가 결번인 블록이 있다)

### 4-2. 값이 0인 셀은 빈칸으로 온다
0.0 이 아니라 아예 빈 셀이다. 제작가이드로 옮길 때 매크로 `lovelySeoyeon` 이 이걸 `-` 로 치환한다.

### 4-3. `계` 행은 단일선택 표에만 있다
| 표 종류 | `      계` |
|---|---|
| 단일선택 (구성비 합 100) | **있음** |
| 중복응답 · 순위 1~N순위 | **없음** |
| TOP2 Summary · Mean Summary | **없음** |

### 4-4. 보기 라벨의 선행 공백
| 위치 | 형태 |
|---|---|
| 일반 데이터 행 | `  4) 시설 및 설비 유지보수…` — **앞 공백 2칸** |
| Summary 표 데이터 행 | `1) 임대차 계약, 공실 관리…` — **공백 없음** |
| `Base for %` | 공백 없음 |
| `      계` | **앞 공백 6칸** |

제작가이드로 옮길 때 **이 공백을 그대로 유지한다.**

## 5. 표 종류별 판별

| 종류 | 판별 신호 |
|---|---|
| **응답자 특성** | 첫 표. 제목이 `응답자 특성`. 행 라벨 2열 |
| **척도** | 요약 행 `【BOT2】`·`【SoSo】`·`【TOP2】`·`[5점 평균]` 존재. 7점이면 `【BOT3】`·`【TOP3】`·`[7점 평균]` |
| **순위** | 제목이 `…_1순위` 인 표와 `…_1~N순위 (중복응답)` 인 표가 **쌍**으로 존재 |
| **중복응답** | 제목에 `(중복응답)`. `계` 행 없음. 값 합이 100 초과 |
| **Summary** | 제목이 `…_TOP2 Summary` / `…_Mean Summary`. 척도 문항 여러 개의 대표값만 모은 표 |
| **단일선택** | 위 어디에도 안 걸리고 `계` = 100.0 |

> "전혀 공감하지 않는다, 이 바텀투 소소 탑 얘가 있으면 척도 문항이에요." (32:20)

### 척도 요약행의 정의
- 5점: `【BOT2】` = 1+2점, `【SoSo】` = 3점(보통), `【TOP2】` = 4+5점
- 7점: `【BOT3】` = 1+2+3점, `【SoSo】` = 4점(보통), `【TOP3】` = 5+6+7점

> "밑에 3개 1 2 3점. 소소는 보통이다." / "탑 3는 5 6 7점" (32:29~32:36)

## 6. 정렬 규약 — DP가 이미 정렬해서 준다

실측으로 확인된다.

| 표 종류 | 정렬 |
|---|---|
| **단일선택 · 척도** | **보기 번호 오름차순** (`2) 불만족` → `3) 보통` → `4) 만족` → `5) 매우 만족`) |
| **중복응답 · 순위** | **전체 값 내림차순** (A7 1순위 표: 28.4 → 20.4 → 16.0 → 12.8 → 9.6 → 8.0 → 4.8) |
| **Summary** | 원 문항 보기 번호 순 |

★ **순위 문항은 `_1순위` 표와 `_1~N순위` 표의 보기 순서가 다르다.**
1순위 표는 1순위 값으로, 1~3순위 표는 1~3순위 값으로 각각 내림차순 정렬돼 있다.
> "이거 얘 1순위랑 3순위랑 순서가 보기 순서가 당연히 다르겠죠." (29:04)

제작가이드에서 두 표를 한 페이지로 합칠 때는 **1~N순위 기준 순서를 채택**한다 (→ `guide/12`, `guide/13`).

## 7. 서브베이스 검증

베이스가 문항마다 다르다. 서브베이스 표는 설문지의 BASE 정의(`A1=1-3` 같은 것)로 걸러진 응답자 수다.
`part 3 목차(연구부 확인용)` 시트의 `구성 및 BASE` 열이 그 정의를 담는다.

**검증 방법**: 서브베이스들의 합이 상위 베이스와 맞는지 본다.
- 상호배타 분기: `A1-1(불만족·보통) + A1-2(만족) = 전체`
- 조건 분기: `A3-1(85) = 17.0% × 500` 처럼 상위 문항의 해당 보기 비율과 일치

불일치하면 DP의 산출 기준이 설문지 정의와 다른 것이다. 그 경우 **Base 문구를 실제 산출 기준으로 고쳐 적는다** (예: `1순위 기준` → `1~3순위 내에 응답한 자`).

## 8. 통계표에 없는 것을 만들어야 할 때

척도 문항이 연속 5개 이상인데 `TOP2 Summary` / `Mean Summary` 표가 없으면 **직접 만든다.**

> "만약에 이걸 내가 (…) 누락했었으면 이거 가지고 따로 만들었어야겠어."
> "이거 가지고 탑투값 하나씩 긁어 붙여 놓으셔야 되죠." (50:30~50:50)

각 척도 표의 `【TOP2】` 행과 `[5점 평균]` 행을 긁어 한 장의 요약표로 조립한다.
이게 요약·결론의 핵심 소재다 (→ `guide/14`).

---

## 9. 파싱 주의

- `.xls` 는 **진짜 BIFF8 OLE2** (`D0CF11E0A1B11AE1`) 다. HTML 위장 파일이 아니다.
- `xlrd` 2.x 로 읽는다. 서식(number format)을 읽으려면 `formatting_info=True` 가 필요하다.
- 표시값 계산: `format_str` 이 `###0.0` 이면 `round(v, 1)`, `###0.00` 이면 `round(v, 2)`.
- Base 셀은 **문자열** `(500)` 이므로 `int(v.strip('()').replace(',',''))` 로 벗긴다.
