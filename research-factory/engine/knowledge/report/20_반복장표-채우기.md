# 20. 반복 장표 채우기 【업무 B】

제작본이 회신된 뒤 첫 작업. 제작팀이 대표 1장만 만들고 나머지는 **양식만 복제해 비워 놓는다.**
그 빈칸을 우리가 채운다.

> "지금 얘랑 얘랑 양식이 똑같잖아요. 그래서 얘는 안 만들어줘요." (녹취 11:38)
> "얘네가 여기 설명 자기들이 설명 쳐. (…) 우리가 각자 디자인을 다르게 해야 되면 '우리 못해, 너네가 해줘' 하고 (…) 지들 하기 힘드니까 '너네가 해' 이렇게 하는 거야." (53:26~53:43)

---

## 1. `Data 입력` 메모 = 채우라는 표식

제작본 슬라이드 **상단(top ≈ 0)** 에 빨간 직사각형 도형으로 붙어 온다.

> "그냥 복제한 다음에 그걸 표기를 또 데이터 입력 이렇게 하나 보네." — "이거 제작팀이 이 정도는 해줘. 데이터 입력 여기다 해야 된다." (11:43~11:47)

LG 제작본 실측: 99장 중 메모 72개 / 71장, **`Data 입력` 이 붙은 슬라이드 64장**.

### ★ 메모가 없을 수도 있다
**SKEE 제작본 126장에는 메모가 0개다.**
제작가이드에 멘트까지 다 써 두면 반복 장표 요청 자체가 사라진다.

> "여기에다가 멘트까지 쓸 수 있다 했잖아. 그래서 만약에 그렇게 하면은 제작본에 넘어올 때는 이제 그 반복 장표 채워주세요만 나오겠죠. 그럼 그 채우는 작업만 하면 끝이." (52:55~53:07)

**→ `Data 입력` 메모가 항상 있다고 가정하지 않는다.**
메모가 0건이면 클론 패밀리를 **형태로 탐지**한다 (아래 §3).

---

## 2. 메모 탐지

```python
def find_memos(slide):
    for sh in slide.shapes:
        if not sh.has_text_frame:
            continue
        if (sh.top or 0) > 0:          # 상단 밖이면 본문 도형이다
            continue
        t = sh.text_frame.text.strip()
        if t:
            yield sh, t
```

**정확 일치로 찾지 않는다.** 제작팀 표기가 흔들린다 (`보기갯수 동일` / `보기 개수 동일합니다.` / `보기 개수 유지`).

| 탐지 | 부분 문자열 |
|---|---|
| 채우기 대상 | `Data 입력` |
| 장분리 | `장 분리` 또는 `장분리` |
| 보기 개수 힌트 | `보기` + (`개수` 또는 `갯수`) |
| 빈칸 유지 | `범례만큼 데이터가 없을때` |
| 정렬 | `정렬` |
| 제작팀 질문 | `해주세요` / `확인해주세요` 로 끝남 |

메모 전량은 **학습 데이터**다. `engine/learning/observations.jsonl` 에 적재한다 (→ `guide/15`).

## 3. 클론 패밀리 식별

같은 양식의 슬라이드 묶음이다. 대표 1장은 채워져 있고 나머지는 비어 있다.

**메모가 있으면**: `Data 입력` 슬라이드 = 채울 대상. 바로 앞의 채워진 슬라이드 = 템플릿.

**메모가 없으면** 형태로 묶는다:

| 키 | 값 |
|---|---|
| `layout_name` | 예: `3_master-1` |
| 차트 시그니처 | `chart_type_id` + `real_series_count` + `overlap` + valAx 범위 |
| 표 시그니처 | `n_rows` × `n_cols` + `banner_group_row` 텍스트 |
| shape 이름 집합 | `소제목` / `Qu` / `Base/Unit` / `차트 N` / `표 N` |

이 4개가 같으면 같은 패밀리다. 패밀리 안에서 **차트 계열 값이 비어 있거나 `???` 인 슬라이드**가 채울 대상이다.

## 4. 채우기 절차

```
① 슬라이드 ↔ 통계표 매핑
② 통계표에서 값 추출 (서식 적용 후 값)
③ 차트 계열 값 주입
④ 표 셀 값 주입
⑤ Base/Unit 문자열 갱신
⑥ 멘트 확인 (비어 있으면 → report/21)
⑦ 수치 전수 검수 (→ report/22)
```

### ① 매핑 — ★ 두 덱이 다르다

| 덱 | 조인 키 | 근거 |
|---|---|---|
| LG | **문항코드** | 본문 79장 전부 `소제목` shape 에 `A1.` `BA1-1)` `C2.` 형태로 있다 |
| SKEE | **slide_title + sub_title** | 본문 슬라이드에 `소제목` shape 자체가 **없다**. 덱 전체에서 문항코드 매치 0건 |

**→ 문항코드 우선, 없으면 타이틀+서브타이틀로 폴백한다.**

⚠ 1:1이 아니다. LG 가이드는 시나리오 7~15 표 **63개를 헤더 블록 없이** 붙여 놨다 (1840~2876행).
매핑 실패는 `MAP` 태그로 따로 집계한다.

### ② 값 추출
통계표 셀은 무한소수 원값을 담고 표시 서식(`###0.0` / `###0.00`)이 반올림한다.
**반드시 서식 적용 후 값을 쓴다.** 반올림은 `ROUND_HALF_UP` (banker's rounding 아님).

### ③ 차트 주입 (python-pptx)
```python
from pptx.chart.data import CategoryChartData
cd = CategoryChartData()
cd.categories = categories
for name, values in series:
    cd.add_series(name, values)
chart.replace_data(cd)
```

**주의**
- `replace_data` 는 계열 색·라벨 서식을 유지한다. 계열 **개수**가 바뀌면 색이 어긋난다
- 척도 `+-세로막대` 는 **부정 계열을 음수로** 넣는다. numFmt `0.0;0.0;\ ` 가 음수 부호를 숨긴다
- 순위 겹침막대는 **긴 값(1~N순위)이 먼저**, 1순위가 나중
- `범례만큼 데이터가 없을때는 빈칸으로 유지해주세요` — **0을 넣지 말고 `None`**

### ④ 표 주입
```python
cell = table.cell(r, c)
cell.text_frame.paragraphs[0].runs[0].text = value   # run 을 갈아끼워 서식 유지
```
`cell.text = ...` 는 서식을 날린다. **run 단위로 교체한다.**

- `(Base)` 행은 문자열 `(500)` 형태. n<30 이면 LG 덱은 `(8*)` 처럼 별표를 붙인다
- 값이 0인 셀은 빈칸으로 둔다

### ⑤ Base/Unit
- 위치로 찾지 않는다. **다단 슬라이드에서는 T=17.13 우측정렬이 아니다.**
- 텍스트 패턴 `[Base:` 로 찾는다
- 각주는 프로젝트마다 다르다. LG 덱은 `*Too small base(n<30)` 하나뿐이다

## 5. 제작본을 읽을 때의 함정

| # | 함정 | 실측 | 대응 |
|---|---|---|---|
| DP-001 | **placeholder idx 를 믿으면 안 된다** | SKEE는 sub=idx13 / ment=idx12 인데 **LG는 79장 전부 반대** (idx12 = sub_title at T=2.62, idx13 = 빈 ment at T=3.42) | **위치(top_cm)** 로 판정 |
| DP-002 | SKEE 덱에는 문항코드가 없다 | `소제목` shape 부재, 매치 0건 | 타이틀+서브타이틀 폴백 |
| DP-003 | 메모가 없을 수 있다 | LG 71건 / SKEE 0건 | 형태 기반 클론 탐지 |
| DP-004 | Base 박스 위치 가변 | 다단 슬라이드 | 텍스트 패턴으로 탐색 |
| DP-005 | **제작팀이 제목을 바꾸기도 한다** | `2. 건설사 대비 당사 수준` → `2. 경쟁사 대비 당사 수준` | 제작본 ≠ 가이드. 제목 불일치는 오류가 아니라 변경 이력 |

또한 **표 열 수가 슬라이드마다 다르다** — LG 본문 표 실측 8/9/11/12/15/16/17/24열.
표 전체 폭 32.0cm 만 고정이고 열 너비는 슬라이드마다 다시 잡혀 있다.
열 수를 상수로 가정하지 않는다.

## 6. `fill_deck.py` 설계

```
입력: 제작본 .pptx + tables.json + slide_facts.json
    ↓
① 슬라이드 전수 스캔 → classification / join_key / 차트·표 시그니처
② 메모 수집 → observations.jsonl (학습 데이터)
③ 채울 대상 선별
     메모 있음 → `Data 입력` 슬라이드
     메모 없음 → 클론 패밀리 중 값이 빈/`???` 인 슬라이드
④ join_key 로 통계표 매핑 (실패는 MAP 태그로 리포트)
⑤ 차트·표·Base 주입
⑥ 저장 + 검수 리포트
출력: 최종 .pptx + 검수리포트.md
```

**원본을 덮어쓰지 않는다.** `in/` 의 제작본은 그대로 두고 `out/` 에 새로 쓴다.
생성 직후 스냅샷을 `out/.baseline/` 에 남긴다 — 사람이 손으로 고친 diff 가 곧 학습 데이터다.
