# 15. 제작팀 지시어 사전 【업무 A】

제작팀은 **완전 수작업**이고 AI를 쓰지 않는다. PPT를 모르는 사람도 알아볼 수준의 지시가 필요하다.

> "걔네들이 정말 수작업으로 하는 거야." (녹취 34:21)
> "그 PPT 아예 모르는 애들도 할 수 있게 설명해 주는" (53:43)
> "저거 그냥 그 제작팀이 알아보게 쓰면 돼요." (34:16)

**통제 어휘가 아니다.** 사람이 읽으므로 표현이 흔들려도 통한다.
다만 우리는 **일관되게** 쓴다 — 일관돼야 자동 생성과 검증이 가능하다.

---

## 1. 우리가 쓰는 어휘 (제작가이드 → 제작팀)

### 1-1. 행 단위 수식어
데이터 행의 **"블록 값 열"**(= 행 라벨 열 바로 왼쪽)에 적는다.

| 문자열 | 어느 행에 | 뜻 | 실측 LG/SKEE |
|---|---|---|---|
| **`그래프 상단 Text`** | `【TOP2】`·`【TOP3】`·`[N점 평균]` | 그 값을 그래프 **위에** 숫자로 표시 | **77 / 86** |
| `100%세로막대` | 3점 리코드 각 행 | 그 행들을 100% 세로막대 계열로 | — / 45 |
| `text` | `[5점 평균]` | 차트가 아니라 텍스트로 | — / 14 |
| `가로막대` | 패널 제목 행 옆 | 그 패널을 가로막대로 | — / 24 |
| `세로막대` | 패널 제목 행 옆 | 그 패널을 세로막대로 | — / 1 |
| `그래프 색` | 데이터 행 | 계열 색 별도 지정 | — / 2 |
| `각 그래프마다 base 표기` | 패널 | 패널·행마다 base 를 따로 표기 | — / 1 |
| `그래프 상단에 평균 표 표기` | 평균 열 | 평균을 상단 표로 | — / 3 |

### ★ `그래프 상단 Text` — 안 적으면 안 나온다

이게 이 업무에서 가장 중요한 단일 어휘다.

> "탑이랑 평균은 이렇게 이런 식으로 위에 빼요. 저걸 빼는 방법은 이 앞에 그래프 상단 텍스트 이렇게 적어놓으면 쟤네가 위에다 빼놔요." (33:10)
> "만약에 내가 이거를 안 썼어. 그럼 얘가?" — "안 나와. 이게 안 나와요." (33:52)
> "왜지? 이렇게 있는데 왜 안 나오지?" — "요청을 안 했으니까." (33:54)

**조직 내부 신호다.**
> "그러니까 보낼 때 약간 신호인 거지." — "맞아. 조직 내부 신호네." (34:24)

`【BOT】`·`【SoSo】` 에는 붙이지 않는다.
> "바텀이랑 소소는 안 중요하잖아요. 탑이 중요하잖아요. 긍정적 얼마나 긍정적인지를 보고 싶은 거잖아." (32:47)
> "소소까지는 필요가 없어요." (34:40)

**오타 검출기가 붙어 있다.** `본문` 시트에 `cellIs equal "그래프 상단 Text"` → 빨간 글자 조건부서식이 걸려 있다.
정확히 입력하면 글자가 빨개진다. **안 빨개지면 오타다.**

연구원은 이걸 수식으로 자동화했다.
> "수식을 걸 때 나는 그냥 여기 이 다음 셀이 탑이 있거나 평균이라는 단어가 있으면 그래프 상단 텍스트로 적어줘." (33:26)

우리도 같은 규칙으로 자동 삽입한다: **행 라벨이 `TOP` 또는 `평균` 을 포함하면 붙인다.**

### 1-2. 레이아웃 지시
패널 옆 **빈 셀**에 적는다.

| 문자열 | 실측 | 뜻 |
|---|---|---|
| `1/3 공간만 만들어주세요` | SKEE 13 | 패널이 슬라이드의 1/3만 차지 |
| `하단에 1/3 공간만 만들어주세요` | SKEE 5 | 위치까지 지정 |
| `1/2 공간만 만들어주세요` | SKEE 1 | |
| `1/3 공간만 만들어주세요 (불만족 정성 사유)` | SKEE 1 | 괄호로 용도 부기 |
| `참고 이미지` | SKEE 1 | 옆에 붙인 이미지를 참고 |
| `TEXT 박스` | SKEE 2 | 표가 아니라 텍스트 박스로 |

### 1-2-1. 요약 교차분석 패널의 Chart type (R-145, 2026-08-24)

| Chart type 칸 | 표 모양 | 제작팀이 그리는 것 |
|---|---|---|
| `배너 : 가로 누적 100% 막대 그래프 (행 = 관리 운영 방식 집단, 각 행 Base 100%)` | 행 = 전체·집단, `Base for %` 열, 열 = 보기 | 행마다 막대 하나, 보기를 누적. 막대 합 100 |
| `배너 : 가로 묶음 막대 그래프 (행 = … 집단, 각 행 Base 100%)` | 같음(열 = 선별 보기·TOP2) | 행마다 묶음 막대. 합은 100 이 아니다(중복·TOP2) |
| `배너 : 표 (관리 운영 방식)` | 열 = 집단(본문 배너 표와 같은 방향) | 표 그대로. **차트로 바꾸지 않는다** |

`[군 이름]` 행은 구분 머리(값 없음) — 막대를 그리지 않는다. 열 머리가 `[평균 : 만원]`·`【TOP2】` 면 그래프 상단 Text.

### 1-3. 자유 서술 지시
정형화되지 않은 요청은 그냥 문장으로 쓴다. `Chart type` 칸에 적는다.

실측:
```
제목 - 내용 형태의 박스 3개 -> 총결론 박스 하나 구성 부탁드립니다.
+/- 5점 척도 (9,10점을 0보다 위로 넣어주세요)
좌 : IPA, 우: 가로 겹침 막대
```

요약·결론은 표를 붙이고 배치만 지시하면 된다.
> "표 하나 갖다 붙이고 어디다 쓸 건지 그냥 적어놓으면 돼요. 전체 원 그래프 이쪽에다가, 전체 가로 여기에다가" (41:13)

### 1-4. 빈칸은 `-` 로 채운다
매크로 `Sub lovelySeoyeon()` (Module1) 이 선택 영역의 눈에 빈 칸을 전부 문자열 `-` 로 바꾼다.
제작팀이 빈칸을 "값이 없음"인지 "적는 걸 잊었음"인지 헷갈리지 않게 하려는 것이다.
SKEE 본문에 `-` 가 수백 개 박혀 있다.

## 2. 제작팀이 우리에게 쓰는 어휘 (제작본 → 우리)

제작본 슬라이드 **상단(T≈0)** 에 빨간 직사각형 도형으로 붙어 온다.

**LG 제작본 99장 중 메모 72개 / 71장.** `Data 입력` 이 붙은 슬라이드 **64장**.
**제작가이드에 멘트까지 다 써 두면 반복 장표 요청 자체가 사라진다** (52:58 인터뷰).
⚠ 이 항목의 덱 근거였던 「SKEE 제작본 126장에 메모 0개」는 **성립하지 않는다** — `engine/refs/예시_제작본_SKEE만족도_0127.pptx` 는 이름과 달리 **최종본**이다(코퍼스 `1-5. skee 만족도 보고서 최종본.pptx` 와 126/126장 텍스트 완전일치, PPT 팀 반송 G-2 · 가이드 팀 재확인 2026-08-24). 최종본은 5사례 전부 메모 0건이라 「메모 0」은 「최종본을 봤다」는 뜻일 뿐이다. 인터뷰 인용만 근거로 남긴다.

### 전문 (LG 제작본 실측)

| 메모 | 개수 | 뜻 / 우리가 할 일 |
|---|---|---|
| `Data 입력` + `*겹치는 레이블은 조정 필요합니다.` | 33 | 값 넣고 레이블 겹침을 손으로 조정 |
| `Data 입력` | 19 | **여기 채우세요** = 반복 장표 표식 |
| `Data 입력` + `보기갯수 동일` | 4 | 앞 장과 보기 개수가 같으니 그대로 복제 |
| `Data 입력` + `보기갯수 조정 완료` | 1 | 제작팀이 이미 맞춰놨다 |
| `Data 입력` + `장 분리` + `보기 개수 동일합니다.` | 1 | 배너가 많아 두 장으로 쪼갬 |
| `Data 입력` + `보기 개수 동일합니다.` | 1 | 동일 의미 (표기 흔들림) |
| `Data 입력` + `장 분리` | 1 | |
| `Data 입력` + `보기 개수 유지` | 1 | |
| `Data 입력` + `1차 송부 후 수정` | 1 | 재송부 이력 |
| `Data 입력` + `1차 송부 후 전체 base 수정` | 1 | |
| `Data 입력` + `*겹치는 레이블은 조정 필요합니다.` + `범례만큼 데이터가 없을때는 빈칸으로 유지해주세요` | 1 | **0을 넣지 말고 빈칸으로** |
| `Data (TOP2/BOT2) 수정` | 1 | TOP2/BOT2 값만 다시 넣어라 |
| `장분리` | 1 | |
| `보기항목에 코드번호가 있어서 왼쪽 정렬했습니다.(기본은 우정렬)` | 1 | 보기 라벨에 `1)` 이 있으면 좌정렬 |
| `보기 순서 확인해주세요` | 1 | 정렬 근거를 되묻는 것 |
| `잘 모르겠다` + `위치 하단으로 조정했습니다.` | 1 | `잘 모르겠다` 보기의 위치 처리 |
| `1차 송부 후 범례색 수정` | 1 | |
| `1차 송부후 범례 위치 조정` | 1 | |
| `첫번째 행을 나눠서 셀을 미리 만들어 놓아야 매크로 사용이 편리하고, 점선 모양이 유지됨` | 1 | 제작팀 내부 메모 |

### 읽는 법

| 메모 유형 | 의미 |
|---|---|
| `Data 입력` 계열 | **우리가 채운다.** 반복 장표. → `report/20` |
| `보기갯수/개수` 계열 | 클론 패밀리 힌트 — 앞 장과 행 수가 같다 |
| `장 분리` / `장분리` | 배너 열 초과로 슬라이드를 쪼갰다. 두 장에 나눠 넣는다 |
| `1차 송부 …` 계열 | 이전 회차 수정 이력. 우리가 할 일은 없다 |
| `~해주세요` / `~확인해주세요` | **제작팀의 질문이다.** 답하거나 고쳐서 회신 |
| `~했습니다` / `~완료` | 제작팀이 이미 처리했다는 통지 |

### 표기 흔들림에 주의
`보기갯수 동일` / `보기 개수 동일합니다.` / `보기 개수 유지` — 같은 뜻인데 세 가지로 쓴다.
`장 분리` / `장분리` 도 마찬가지다.
**메모 탐지는 정확 일치가 아니라 부분 문자열(`Data 입력`, `장 분리`|`장분리`, `보기`+`개수`|`갯수`)로 한다.**

## 3. 어휘 확장 절차

새 지시어가 필요하면:
1. 기존 어휘로 표현 가능한지 먼저 본다
2. 안 되면 **자유 서술로 쓴다** — 사람이 읽으므로 문장이어도 된다
3. 두 번 이상 쓰이면 `engine/learning/RULES.md` 에 어휘로 등재하고 이 문서에 반영한다

제작본에서 **새 메모**가 발견되면 `fill_deck.py` 가 전량 수집해
`engine/learning/observations.jsonl` 에 넣고, `/회고` 가 규칙 후보로 올린다.
