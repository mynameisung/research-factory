# 노하우 — 보고서작성

연구원이 `/보고서작성` 을 쓰다가 얻은 요령을 카드로 쌓는 곳이다. 규칙(RULES.md)보다 가볍다. 근거 한 줄과 상황만 있으면 올린다.
`/개선공유` 가 이 파일의 새 카드를 PR 로 올리고, 관리자가 **채택**(그대로 둔다) · **승격**(규칙·지식·도구로 옮긴다) · **보류**(사유를 적는다)를 정한다.
규칙 수준(같은 상황이 오면 반드시 또 고쳐야 하는 것)이면 여기가 아니라 `/회고` 로 카드를 올린다.

카드 형식:

```
### K-보고서작성-001 · <한 줄 제목>
- 날짜 · 조사: 2026-09-10 · <프로젝트/조사>
- 상황: <어느 경로(A 마감·B 직접 제작·C 재반영)·어느 장표에서>
- 노하우: <다음에 그대로 따라 할 수 있게>
- 근거: <파일·장표 번호·검수 결과 또는 실측값>
- 상태: 제안 | 채택 | 승격 → R-nnn / <도구> | 보류(사유)
- 올린 사람: <GitHub 아이디>
```

번호는 이 파일의 마지막 번호 다음이다. 같은 요령이 이미 있으면 새 카드 대신 그 카드의 「근거」에 사례를 한 줄 보탠다.

### K-보고서작성-004 · 요약·결론 검수는 수치 대조가 아니라 「해석 비약」 체크리스트로 본다
- 날짜 · 조사: 2026-10-07 · 건물관리 실태 조사 보고서(송부 전 최종 검수)
- 상황: 결과 장표 값은 데이터와 전부 일치했지만, 요약·결론 문장에 근거보다 센 해석이 여럿 있었음
- 노하우: 요약·결론 문장마다 아래를 확인한다. ① 대상·응답 방식이 다른 두 문항(단수 n=275 vs 중복 n=76)을 비교해 「옮겨 간다」고 쓰지 않았나 — 같은 응답자로 다시 계산해 '전환'인지 '확장'인지 가른다 ② 금액은 평균만 쓰지 말고 중앙값·하한 미만 비율을 같이 본다(평균 27만원이지만 58%가 25만원 미만) ③ 가격을 안 보여 준 가정형 문항을 「수요 확인」으로, 실제 행동 문항(선정 방식)을 「선호」로 쓰지 않았나 ④ 기준표상 '긍정'(70%대)을 「낮다」로 쓰지 않았나 ⑤ 1명 차이 순위·동률을 순서로 단정하지 않았나 ⑥ 한 문장 안에서 서로 충돌하지 않나(「가격이 아닌 … 하한 진입가로 시작」) ⑦ 차트와 반대로 읽히지 않나(「가격대가 단일하지 않음」인데 차트는 최빈 구간이 전부 같음). 반대로 지적할 때도 조심: 타깃 문장을 반박하기 전에 그 교차집단(예: 입주사 10개+ × 직접·내부 관리, n=39)을 직접 계산한다 — 전체 집단만 보고 반박하면 틀린다. n≥30 은 유효 표본(*는 30 미만)이고, 제언에 「추가 검증 필요」를 넣는 것은 제언이 아니다
- 근거: 검수 지적 63건을 원데이터로 재계산해 34건으로 거름(12건 철회). 철회 사례가 위 '조심' 항목
- 상태: 제안

### K-보고서작성-005 · 검수 메모는 슬라이드 밖 「딱지」로 달고, 송부본 대비 변경은 기존→변경→사유로 단다
- 날짜 · 조사: 2026-10-07 · 건물관리 실태 조사 보고서
- 상황: 연구원이 「엑셀로 보기 힘들다, 본문은 고치지 말고 도형으로 메모 달아 달라」, 이어서 「팀장 컨펌용으로 송부본 대비 무엇이 바뀌었는지 딱지로」 요청
- 노하우: 메모는 슬라이드 오른쪽 바깥(편집 화면에서만 보이고 슬라이드쇼·PDF 에 안 나옴)에 노란 바탕·빨간 테두리·빨간 9pt 글씨 사각형으로, 한 건에 「확인 ▶ [등급] 위치 / 현재 / 수정안(굵게, 그대로 붙여 넣을 문장) / 근거(수치)」. 도형 이름을 '확인딱지'처럼 하나로 통일하면 송부 전 선택 창에서 한 번에 지운다. 세로로 넘치면 옆 열로 넘긴다. 변경 컨펌용은 「변경 ▶ [흐름/워딩/데이터] / 기존(송부본) / 변경 / 사유」로 쓰고, 메시지 방향이 바뀐 [흐름]만 빨강, 수치만 바뀐 [데이터]는 회색, 형식 문제는 파랑으로 구분하고, 목차 장표에 변경 요약 딱지 하나를 둔다. 저장 전에 기존 도형 XML 이 그대로인지 비교해 딱지 외 변경이 없음을 확인한다
