# 노하우 — 설문지작성

연구원이 `/설문지작성` 을 쓰다가 얻은 요령을 카드로 쌓는 곳이다. 규칙(RULES.md)보다 가볍다. 근거 한 줄과 상황만 있으면 올린다.
`/개선공유` 가 이 파일의 새 카드를 PR 로 올리고, 관리자가 **채택**(그대로 둔다) · **승격**(규칙·지식·도구로 옮긴다) · **보류**(사유를 적는다)를 정한다.
스킬은 시작할 때 이 파일을 읽는다. 그러니 카드는 짧게, 「언제 · 무엇을 · 왜」만.

카드 형식:

```
### K-설문지작성-001 · <한 줄 제목>
- 날짜 · 조사: 2026-09-17 · <프로젝트/조사>
- 상황: <어떤 구조화 양식·어떤 고객 요청에서>
- 노하우: <다음에 그대로 따라 할 수 있게>
- 근거: <파일·행 좌표 또는 고객 피드백>
- 상태: 제안 | 채택 | 승격 → R-nnn / <도구> | 보류(사유)
- 올린 사람: <GitHub 아이디>
```

번호는 이 파일의 마지막 번호 다음이다. 같은 요령이 이미 있으면 새 카드 대신 그 카드의 「근거」에 사례를 한 줄 보탠다.

---

### K-설문지작성-001 · 전년도 설문을 개정할 때는 로직 표기를 하우스 규칙으로 일괄 변환한다
- 날짜 · 조사: 2026-10-06 · 가전 정기조사(트래킹) 설문 개정
- 상황: 타 대행사가 쓰던 전년도 설문에 고객 메모를 반영해 올해 설문을 만드는 작업. 옛 설문은 대상 조건을 `[PROG: B9=1번 응답자만 질문]` 처럼 PROG로 쓰고, 범위는 `[PROG: 소수점 없이 만원 단위, range 20~300]` 처럼 PROG 안에, 파이핑은 `(SQ7 응답 제시)` · `(C2번 응답값)` 처럼 제각각이었다
- 노하우: 문항을 고치는 김에 표기도 전부 바꾼다 — 「OO 응답자만 질문」 PROG 는 지우고 문항 위 `[BASE: 조건 | 사람말]` 로, 범위는 `[RANGE: a-b]` 한 줄로 분리(금액이면 `[PROG: 소수점 없이 만 원 단위 응답, 한글 표기 같이 제시]` 동반), 파이핑은 `[#SQ7 응답값#]` 로. PROG 한 줄에 대상 조건과 다른 지시가 섞여 있으면 조건만 BASE 로 옮기고 나머지는 PROG 로 남긴다. 고친 줄은 붉은색. BASE 가 빠진 문항이 하나라도 있으면 실사팀이 로직을 못 건다
- 근거: 개정본 161개 문항에 BASE 를 새로 달고 파이핑 47곳 · RANGE 19곳을 바꿈. 연구원이 앞 6쪽을 직접 이 방식으로 고쳐 보여 준 기준을 나머지에 적용
- 상태: 제안

### K-설문지작성-002 · 「이미지 함께 제시」 문항은 같은 이미지라도 그 문항 밑에 다시 넣는다
- 날짜 · 조사: 2026-10-06 · 가전 정기조사(트래킹) 설문 개정
- 상황: 구입 의향자 문항을 구입자 문항에서 복제하면서 `[PROG: 용량 이미지 함께 제시]` · `[PROG: E5-1 이미지 함께 제시]` 처럼 지시만 있고 이미지는 앞 문항에만 있었다
- 노하우: 실사팀은 문항 단위로 화면을 짜므로 「앞 문항과 동일」로 두지 말고 이미지(표째)를 그 문항 바로 아래에 다시 넣고 PROG 는 `[PROG: 아래 이미지 함께 제시]` 로 쓴다. docx 에서 표를 복제할 때는 `wp:docPr id` 를 새 번호로 바꾼다(겹치면 Word 가 복구 메시지를 띄운다). 받은 파일에 이미지가 아예 없으면 메모로 고객에게 요청한다
- 근거: 개정본 AF4-4(용량 이미지) · E5-4(도어 이미지)에 재삽입. 연구원이 SQF9 에 이미지를 다시 올려 둔 것을 기준으로 함
- 상태: 제안
