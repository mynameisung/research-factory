## 2. 무엇을 왜 고쳤나

### 2-1. 근인 셋 — 전부 "산출물을 하나로 접었다"

| 접은 것 | 실제 | 그래서 생긴 실패 |
|---|---|---|
| 한 문항 = 한 슬라이드 | 배너가 넘치면 **두 장**으로 갈린다 | MAP 4장 누락 + BASE 파생 1건 |
| 정렬 = 그래프 것 | 표 행에도 **똑같이** 걸린다 (유형별 분기) | 표 행 순서 A5 · C2 |
| 상단 Text = 라벨 하나 | 매체가 **둘**이고 표기가 다르다 | 라벨 표기 36건 전패 |

### 2-2. MAP-050 · 장분리 — 쪼개지는 건 문항이 아니라 배너다

가이드 4블록(`C2-1/C2-2/C2-3` · `C3` · `C3-1/C3-2/C3-3` · `C4`)의 배너가 **27열**이다 —
`1순위 · 1+2+3순위 · 나이(4) · 가구 구성(2) · 선호 유형(사후)(4) · 시나리오별(15)`.
제작팀은 이걸 **11열 + 16열 두 장**으로 나눴다.

결정적 증거는 2장째의 표다. `s82/s84/s86/s88` 의 `(Base)` 행 값이 가이드 `P~AD` 열
(시나리오별 15배너)과 **전량 일치**하고, 배너군 헤더 문자열까지 일치한다.

| 예측 | 2장째 배너군 | 정답 슬라이드 헤더 |
|---|---|---|
| `C2-1/C2-2/C2-3` ch2 | `C2 1+2+3순위 시나리오별` | s82 ✔ |
| `C3` ch2 | `C2 1+2+3순위 시나리오별` | s84 ✔ |
| `C3-1/C3-2/C3-3` ch2 | `C3 1+2+3순위 시나리오별` | s86 ✔ |
| `C4` ch2 | `C2 1순위` | s88 ✔ |

라운드1 이 "두 장이 완전 동일" 이라고 본 것은 **차트만** 본 것이다. 이 유형은 차트가 전체 값만
그리고 배너는 표로 가므로, 배너만 갈리면 **차트는 두 장에 똑같이 들어간다.** 정상이다.

- 판정 신호는 **열 수**다(R-057 "그래도 안 되면 장분리" 의 실행 규칙).
- 가드 3종을 모두 만족할 때만 나눈다 — ① 2단 배너 헤더 실재 ② 다열 배너군 2개 이상
  ③ 떼어 낼 마지막 배너군 3열 이상. 가드를 빼면 SKEE 의 1단 헤더 지표비교표(24열)가 잘못 쪼개진다.
- LG 본문 82블록 전수에서 **27열 4건 = 전부 2장 / 22열 이하 78건 = 전부 1장.** 분리가 완전하다.

### 2-3. SORT-045 · 정렬은 표 행에도 걸린다 (유형별 분기)

갈림길은 하나다 — **보기가 카테고리축인가, 계열인가.**

| 보기의 위치 | 유형 | 표 행 순서 |
|---|---|---|
| 카테고리축 | 가로막대 · 가로겹침막대 · 순위 | **= 차트 옵션축** (값 내림차순 · 기타 최하단 동시 적용) |
| 계열 | 척도 발산 · 등급 사다리 누적 100% | **통계표 순서 유지** (그래프는 쌓는 순서라 달라도 맞다) |

검수관이 짚은 "44건이 두 순서가 다르다" 중 **41건은 달라야 맞는 것**이었다.
"전부 같게" 도 "전부 다르게" 도 오답이다.

라벨 위생(`N) ` 접두 제거)도 표 행에 적용했다 — 제작본 표에도 접두가 없다.
가이드 그리드(.xlsm)의 행 순서는 또 다른 산출물이라 `guide_grid_row_order` 로 분리해 냈다.
이제 행 순서 산출물이 **3종**이다: 가이드 그리드 / 차트 옵션축 / 제작본 배너표.

### 2-4. TT-010 · 상단 Text 는 매체가 둘이고 표기가 다르다

| 매체 | 유형 | 위치 | 표기 |
|---|---|---|---|
| 표 상단 행 | 척도(+-세로막대) 36장 | 표 top 6.17 · 차트 top 7.12 (표가 위) | `TOP3(%)` · `7점 평균(점)` + 배너별 값 |
| 독립 TextBox | 누적 100% 5장 | 막대 좌우 끝에 겹침 (BOT L=6.67 · TOP L=22.61, T=9.17) | `【BOT2】` · `【TOP2】` + 다음 줄 수치 |

통계표(가이드) 센티널 라벨 `【TOP3】` · `[7점 평균]` 은 **통계표 표기**다. 그대로 옮기면 안 된다.
척도 36장이 전패한 이유가 이것이고, 한 예측 안에서 브래킷이 `【】`/`[]` 로 섞이던 것도 함께 해소됐다.

산출물도 라벨 배열에서 **레코드 배열**로 바꿨다 —
`{label, source_label, kind, medium, placement, unit, banner, value}`.
`value` 를 실은 것은 검수관 제안 R-B · R-MENT-010 을 받은 것이다. 멘트 렌즈가 인용할 수치가
없어서 "구현해도 채점 불가" 로 분류됐던 41장이 이걸로 풀린다.

## 4. 고치지 않기로 한 것

### 4-a. `s84` Base 표기 (`3개 문항 응답`) — 정답지 오기로 등재

`s83`(1장째)은 `중복`, `s84`(2장째)는 `3개 문항 응답` 이다. 가이드 `C3` 블록의 Base/Unit 은
`중복` 하나뿐이고, s84 의 표 전체 열 `(Base)` 도 **(100)** 이다. `3개 문항 응답` 은 base 가 300일 때
쓰는 표기라 n=100 과 모순된다. 이웃 `s85·s86`(전체 300)이 그 문자열을 쓴다 → 복붙 흔적.

**반례로 확인**: 같은 장분리 구조인 `s87 / s88`(C4)은 두 장 모두 `중복` 으로 일치한다.
즉 "장분리하면 2장째 Base 정의가 바뀐다" 는 규칙이 아니다.

→ 규칙으로 승격하지 않는다. `GOLDEN_SET §5-h-1` 등재, BASE 렌즈에서 s84 제외.
대안 해석(배너군 n 합이 300 이면 `3개 문항 응답`)은 결정적 관찰이 1건뿐이라 `OPEN_QUESTIONS Q-BASE-01`.

### 4-b. `s25` 의 TOP2 / BOT2 값이 가이드와 뒤바뀐 것 — 손대지 않는다

가이드는 `【TOP2】=40.0`(보기번호 3·4), 제작본은 `TOP2(%)=60.0`(의미상 상위 1·2)이다.
제작팀 메모가 **`Data (TOP2/BOT2) 수정`** 으로 붙어 있다 — 제작팀이 이 셀을 문제로 올린 것이다.
어느 쪽이 최종인지 확정할 수 없으므로 예측기는 **가이드 값을 그대로 싣는다**(가이드가 우리 입력이다).
라벨 표기 채점에는 영향이 없다. → `GOLDEN_SET §5-h-2` · `OPEN_QUESTIONS Q-TOPTEXT-01`.

### 4-c. `s83`(C3 1장째) 표 행 라벨 — 예측이 옳다

s83 의 `data_row_labels` 15개가 `s80`(C2)과 **바이트 단위로 동일**하다(= C2 의 정렬 결과).
그러나 C3 의 1+2+3순위 내림차순은 `15. 공간형 반응하고 변화하는 집(41) → 3. 공간형 고령화 주택(35) → …`
로 전혀 다르다. s83 은 차트도 표도 미기입 스켈레톤이다.
→ `s93` 과 같은 계열의 복제 잔존물. `GOLDEN_SET §5-h-3` 등재, SORT 표 행 렌즈에서 제외.

### 4-d. 검수관 제안 `MAP-060`(시나리오 7~15 표 상속) — 구현하지 않음

가이드 orphan 표 63개(시나리오 7~15)는 **제작본에 대응 슬라이드가 아예 없다**(GOLDEN_SET §5-e).
검증할 정답이 0장인 구간에 규칙을 만들면 반례를 만날 방법이 없다. 라운드1 의
`Q-SORT-04`("통과가 아니라 미측정") 를 그대로 유지한다. 검수관 자신도 이 구간을 `0/0 충족`
으로 집계했다 — 실패가 없는 게 아니라 측정이 없는 것이다.

### 4-e. 검수관 제안 `SORT-012`(보기 개수만큼 그래프 슬롯·표 행 분할) — 근거 없음

무엇을 몇 개로 나누라는 것인지 제작본에서 대응 관찰을 찾지 못했다. 장분리의 실제 축은
보기 수가 아니라 **배너 수**였다(§2-2). 규칙을 만들지 않는다.

### 4-f. 검수관 제안 `R-F`("본문 슬라이드 수 = 고유 문항코드 수 가정 유지") — **기각**

반례가 이번 라운드의 주제 그 자체다 — 정답 본문 **79장 ↔ 고유 문항코드 75개**.
이 가정이 라운드1 에서 정답 4장을 결함으로 몰아낸 원인이다.
조인 키는 `question_code` + `chapter` 여야 한다 → `chart_rules.yaml#scoring_hygiene.denominator` 에 명문화.

### 4-g. 검수관 제안 `R-E`(소제목 문항코드를 단독 조인 키로 신뢰하지 마라) — 이미 반영돼 있음

`R-091`(조인 키는 문항코드 우선, 없으면 타이틀+서브타이틀)과 `GOLDEN_SET §5-b`(s63 오타)가
이미 다루고 있다. 채점기는 s63 을 보정해 조인한다. 새 카드를 만들지 않는다.

### 4-h. 멘트 렌즈 — 이번에도 G1 에서 채점하지 않는다

검수관 판정("채점 불가 — 모수 0")과 라운드1 결론이 일치한다. 정답 결손(LG 본문 79/79 `top_ment` 공백)
과 예측 결손(생성 미구현)이 겹쳐 빈칸-빈칸이다. 다만 두 가지를 처리했다:

- **덱 프로파일 개념 도입** (검수관 제안 R-MENT-040) — "멘트 없는 덱" 은 결함이 아니다.
  `scoring_hygiene.lens_scope.deck_profile` 에 자동 SKIP + 모수 0 보고를 명문화.
- **산출물 스키마 결손 해소** (R-MENT-010) — `graph_top_text[].value` / `.unit` / `.banner` 를 실었다.
  "구현해도 채점 불가" 였던 41장이 이걸로 대조 가능해진다. 멘트 **생성기**는 여전히 만들지 않았다 —
  검증 표본이 없는 채로 붙이면 환각 위험만 들어온다.

### 4-i. 차트타입 판정 규칙 — 한 글자도 바꾸지 않았다

TYPE 은 교정 전에 이미 75/75 였다. `decision_table` 의 `when` 은 손대지 않았고
`then` 에 매체 정보만 덧붙였다. 늘어난 4장(장분리 2장째)은 기존 CT-030 이 그대로 맞혀
**79/79** 가 됐다.

## 5. 여전히 측정되지 않은 것 (다음 라운드 전 처리)

1. **정답지 미기입 스켈레톤 29장 (79장 중 37%)** — SORT 그래프 축 실질 커버리지가 **50/79**.
   라운드1 은 22장이라 봤으나 장분리 2장째 3장을 포함해 다시 세면 29장이다.
   순위 문항 다수가 이 구간이라 SORT-030 재측정이 여전히 좁다 → `GOLDEN_SET §5-h-4`.
2. **원 · 표 계열 차트타입** — 본문 노출 0회. CT-040 / CT-010 은 3라운드째 미검증.
3. **장분리 임계** — 22 와 27 사이 어디인지 모른다. 24열짜리가 나오면 판정이 갈린다 → Q-MAP-01.
   비상주 프로젝트의 배너 17열·TA Pool 23개 구 배너가 곧 이 규칙을 실전에서 때린다(Q-001 · Q-002).
4. **3장 이상 장분리** — 관측이 2장뿐이라 "마지막 배너군 1개만 분리" 로 좁혀 뒀다.
5. **멘트 전 렌즈** — G2 이관 필요. 이번에 대조 데이터 스키마는 열어 뒀다.
6. **G2(SKEE) 정식 채점** — 스모크만 돌렸다(70예측, 회귀 없음). 척도 덩어리 순서가 LG 와 반대이므로
   G2 채점 전에 **Q-SORT-01 을 결정해야 42장이 통째로 FAIL 나지 않는다.** 라운드1 이후 미해결.
