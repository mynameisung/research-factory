## 구조 결손

### SD-001 · 채점기가 차트타입별 축 정의를 안 가졌다 〔2회차 해소〕
**증상 3건 이상 같은 뿌리** — 표 행 순서·헤더행수·보기 수 세 축이 척도 19장에서 전부 오탐(54건).
1회차의 누적 100% 오탐 2건도 같은 뿌리였다.

**뿌리** — R-113 이 이미 규정한 갈림길(**보기가 카테고리축인가 계열인가**)을 채점기가 안 따랐다.
차트타입마다 보기가 가는 자리가 다른데 축을 하나로 뭉뚱그렸다.

| 차트타입 | 보기의 자리 | 표에 보기 행 | 차트 범주 |
|---|---|---|---|
| 가로막대 · 겹침막대 | 범주축 | O | 보기 |
| 누적 100% | **계열** | O (+TOP2/BOT2) | 「전체」 1개 |
| ±세로막대(척도) | **계열** | **X** (범례 1행) | **배너 열** |

**해소** `AXIS_SPEC` + `chart_family()` 도입. 54건 → 0건, 1회차 회귀 없음.

### SD-002 · R-105 를 반쪽만 구현했다 〔미해소 — 사람 판단 필요〕
우리 `set_row_count` 는 데이터영역을 **상수 3,096,000 EMU** 로 쓴다. LG 실측은
「표 총높이 11.0cm **−** 실제 헤더 높이」다. 평소엔 헤더가 2.4cm 라 같은 값이지만,
**배너가 많아 라벨 행이 커지면 달라진다.**

| | 헤더 | 데이터영역 | 결과 |
|---|---|---|---|
| LG s17 (16열) | 2.4 | 8.6 | 총 11.0 ✅ |
| LG s97 (24열) | **3.1** | **7.9** | 총 11.0 ✅ |
| 우리 (18열) | 1.3 고정 → 자람 | 8.6 고정 | 총 11.0 **초과** ❌ |

**이것이 R-PPT-006(배너 18열에서 차트가 한 행 밀림)의 진짜 해법이다.**
배너 축약명을 받는 게 아니라, 라벨 행을 필요한 만큼 키우고 데이터영역을 줄이면 된다.

## 재개 방법 (세션 교체 후)

```bash
python engine/learning/golden_loop/compare.py "LG홈로봇" <lo> <hi>   # 결과 out/cmp_*.json
python engine/tools/predict_golden.py engine/refs/guide_blocks_SKEE.json        engine/learning/golden_loop/out/pred_G2.json                   # G2 는 예측본부터
```

**대기 중: 5번(G1 요약 s8~s13 · 결론 s14)부터.** 요약 구간은 본문과 축이 다르다
(패널 다중 · 표 없음) — `compare.py` 에 분류 분기를 두어야 한다.

시작 전에 꼭 알 것 둘:
1. **정답이 없는 장이 많다.** G1 본문 79장 중 유효 49장(라벨 빔 25 · 값만 빔 5).
   `is_unfilled()` 가 라벨과 값을 **둘 다** 본다. 요약·결론에도 같은 함정이 있는지 먼저 본다.
2. **차이 0건은 배울 게 없다는 뜻이 아니라 축이 모자란다는 뜻이다.** 3회차가 그랬다 —
   기존 축으로 0건이었는데 축 4개를 늘리자 구조 결손 하나와 관행 4건이 나왔다.

채점기를 고쳤으면 이전 구간 전부로 회귀를 돌린다:
```bash
for r in "17 36" "38 57" "58 77" "78 97"; do
  python engine/learning/golden_loop/compare.py "LG홈로봇" $r
done
```
