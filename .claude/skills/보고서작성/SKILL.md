# 보고서작성 (업무 B)

리서치 통계표를 **보고서 PPT**로 완성한다. 들어오는 길이 둘이다.

| | 경로 A — 제작본 마감 | 경로 B — 직접 제작 |
|---|---|---|
| 시작점 | 제작팀 회신 `.pptx` | 예시 덱(다른 고객사) + 제작가이드 산출물 |
| 몸통 | 비어 온 반복 장표 채우기 | 브랜드 치환 → 골격 조립 → 전량 주입 |
| 도구 | `fill_deck.py --scan/--fill` | `rebrand.py` · `deckbuild.py` · 프로젝트 빌드 스크립트 |
| 위험 | 제작팀 메모 오독 · 클론 매칭 실패 | **이전 고객사 자산 유출** · 패키지 파손 |

인자: 조사 폴더 경로. 예 `/보고서작성 projects/2026_에스원_건물현황실사/02_비상주`

## 이 업무의 헌법 3

이걸 어기면 나머지 절차가 전부 헛돈다.

1. **PPT 팀은 문장을 짓지 않는다.**
   멘트·제목·서브타이틀·Base 라벨의 정본은 업무 A 산출물(`slide_facts.json`)이다.
   여기서는 **옮겨 심기만** 한다. 결함을 발견하면 고치지 말고 반송한다(§반송).
   여기서 고치는 순간 두 팀 산출물이 어긋나고 대조가 불가능해진다.

2. **없는 숫자를 만들지 않는다.**
   통계표에 없으면 비우고 보고한다. 차트 카테고리 수가 안 맞아도 **맞추려고 지어내지 않는다**
   (응답 0인 보기는 통계표에서 행이 통째로 삭제돼 있다).

3. **생성은 스크립트, 판단은 에이전트, 결정은 사람.**
   매번 전부 잡혀야 하는 검사(수치·패키지·라벨 규칙)에 에이전트를 쓰지 않는다 —
   28장 중 27장만 잡는 날이 온다. 판단이 필요한 곳에만 쓴다(§검증 6로).

# 경로 A — 제작본 마감

## A1. 수령 · 현황 파악

제작본을 `2_보고서작성/in/` 에 놓고:

```bash
python engine/tools/fill_deck.py --scan <in/{조사}_제작본_YYMMDD.pptx>
```

`--scan` 이 보고하는 것:
- 총 슬라이드 수 · 분류별 집계 (표지/목차/간지/조사개요/요약/결론/본문/부록)
- **`Data 입력` 계열 메모가 붙은 슬라이드 목록** ← 채워야 할 대상
- **클론 패밀리** — 구조가 동일한 슬라이드 묶음 (레이아웃 + 차트타입 + 표 크기로 판정)
- 제작팀 메모 전문 — `장분리`, `보기갯수 동일`, `범례만큼 데이터가 없을때는 빈칸으로 유지해주세요`,
  `보기 순서 확인해주세요` 등. **지시가 섞여 있으니 전부 읽는다**
- 비어 있는 자리 — `???%`, `내용을 입력하세요`, 빈 데이터 시리즈

사용자에게 요약 보고하고, 제작팀 메모 중 **판단이 필요한 것**을 짚어준다.

## A2. 반복 장표 채우기

```bash
python engine/tools/fill_deck.py --fill <in/제작본.pptx> <work/tables.json> <out/{조사}_보고서_최종_YYMMDD.pptx>
```

- `Data 입력` 메모 슬라이드를 클론 대표와 매칭 → 문항코드로 표를 찾아 차트 시리즈·배너 셀 주입
- 소수점 — % 1자리, 평균·NPS 2자리
- 척도 문항의 부정 계열은 **음수로** (±세로막대)
- 순위 겹침막대는 1+N순위 계열이 order=0, 1순위가 나중 (overlap=100) — R-109
- **제작팀 메모는 지우지 않는다** — 검수 후 사람이 지운다
- `범례만큼 데이터가 없을때는 빈칸으로 유지` → 시리즈 개수 고정, 값만 `None`

클론 패밀리 매칭이 애매하면 자동으로 넘기지 말고 **멈추고 물어본다.**
잘못 채운 장표는 검수에서 잡기 어렵다.

## A3. 멘트 보강

제작가이드에 멘트를 미리 써 보냈다면 대부분 들어가 있다. **비어 있는 것만** 채운다.
- `guide/13_멘트-작성규칙.md` 의 패턴 A~D + 수준어 사다리
- 1행 = 전체값 기준, 2행 = 배너 튀는 값
- **숫자는 `tables.json` 에서만 가져온다.** 화면에서 읽거나 계산하지 않는다

요약·결론 텍스트는 업무 A에서 확정한 것을 옮긴다. 새로 만들어야 한다면 **업무 A가 덜 끝난 것**이므로
사용자에게 말한다(헌법 1).

→ **§검증 6로** 로 간다.

# 경로 B — 직접 제작

제작팀 없이 우리가 덱을 만든다. 다른 고객사 예시 덱을 템플릿으로 쓰므로
**유출 방지가 품질보다 먼저**다.

## B1. 브랜드 치환

```bash
python engine/tools/rebrand.py --src <예시덱.pptx> --profile <클라이언트> --out work/_중간_브랜드적용.pptx
python engine/tools/rebrand.py --src <산출물> --audit-only     # 잔재 감사
```

- 로고는 **높이 고정·너비 재계산**. 늘여 끼우면 CI「비례 임의 변경」 위반이다
- CI 공식색만 규정색이다. 파생색을 만들었으면 **코드 주석에 "CI 규정 아님"을 남긴다**
- 감사는 `brand` 0건이어야 한다. `content`(본문 카피)는 다음 단계 소관이라 남아 있어도 정상
- 중간 산출물은 `_` 접두 + `_archive`. 이름이 완성본처럼 읽히면 안 된다

## B2. 골격 조립

`deckbuild.py` 로 예시 덱에서 필요한 장만 남기고 복제·재배열한다.

- `keep_only` → `clone_slide` → `reorder` → `delete_slides`
- 본문 도너는 **차트 형태 종류만큼만** 가져온다. 형태가 같으면 서식도 같으므로
  장마다 다른 도너를 고를 이유가 없다
- 도너는 이전 고객사 텍스트를 달고 있다. **주입을 끝내고 반드시 삭제**한다
- `gc_orphans` 는 선택이 아니다 — 지운 슬라이드의 원문·차트·엑셀 데이터가 파일에 남으면
  **다른 고객사 자료가 납품물에 실려 나가는 정보 유출**이다

## B3. 전량 주입

장표마다: 제목 · 서브타이틀 · 멘트 · Qu · Base/Unit · 소제목 · 표 · 차트.

- 플레이스홀더는 **idx 로 부르지 말고 위치(top)로 판정**해 idx 를 얻는다 — R-090.
  idx 의 뜻이 덱마다 뒤집힌다(LG 12=서브/13=멘트, SKEE 반대). 좌표를 레이아웃에서
  상속하는 슬롯이 있으므로 레이아웃까지 거슬러 읽는다
- 표 행 수는 `deckops.set_row_count` (R-105 높이 재분배 · R-107 첫/중간/마지막 서식)
- 표 열 수는 배너 수에 따라 **장마다 다르다**(실측 6~18열). 라벨·「전체」 열 폭은 보존하고
  배너 열만 재분배하며 **폭 총합을 지킨다** — R-095
- 라벨 줄바꿈은 `textfit.wrap_ko` (R-108 수식어구를 쪼개지 않는 자리)
- 차트 프레임(graphicFrame)은 **한 바이트도 건드리지 않는다** — R-106
- 이전 고객사 전용 아이콘·사진이 있으면 색만 바꾸지 말고 **내용을 바꾼다**.
  새 자산을 지어내는 일이므로 사용자 승인을 받는다
- 제작팀 메모 도형은 이름이 아니라 **위치·모양으로 판정**해 제거한다

→ **§검증 6로** 로 간다.

# 검증 6로 — 기계 4 + 에이전트 2

양 경로 공통. 기계는 매 빌드, 에이전트는 배치해서 돌린다.

## V1 패키지 〔기계 · 매 빌드〕

`deckbuild.save_checked` 가 `sync_content_types → refresh_app_xml → validate` 를 돌리고
**fatal 이 있으면 저장 자체를 막는다.** 그 뒤 PowerPoint COM 으로 실제로 연다.

> **zipfile 로 열린다고 PowerPoint 가 연다는 보장이 없다.** 반드시 COM 으로 확인한다.

fatal 은 "PowerPoint 가 거부한다"가 아니라 **"이대로 납품하면 안 된다"**로 정의돼 있다 —
유령 슬라이드(장이 조용히 사라짐)·blip 댕글링(그림 자리가 오류 상자)은 열리지만 fatal 이다.
엔진을 고쳤다면 `python engine/tools/deckbuild.py --selftest` 로 회귀를 확인한다.

## V2 수치 전수 대조 〔기계 · 매 빌드〕

```bash
python engine/tools/verify.py --deck <out/최종.pptx> <work/tables.json> <out/검수리포트.md>
```

- **덱의 모든 수치가 통계표 원본과 1:1 일치하는가** ← 하나라도 틀리면 실패
- Base 표기 형식과 값. **`base_n` 이 전체 표본보다 작은데 라벨이 「전체」면 오류다** —
  "500명 중 300명"으로 읽히는 오독을 만든다
- 멘트 줄 길이 상한 (정본 정책. 실측 근거: 멘트 상자 한 줄 = 한글 74자 @32.0cm·12pt)
- `Qu:` 텍스트가 설문지와 일치하는가 · 소제목 문항코드가 실제 문항과 맞는가
- 미기입 잔존(`???`, `내용을 입력하세요`, 빈 시리즈) · 소수점 자릿수

`report/22_검수-체크리스트.md` 도 함께 돌린다.
덱 저장(`deckops.Deck.save`)은 문서 위생(R-137)을 자동 적용한다 — 문서 속성의 개인 이름·템플릿 잔재·이전 작업자 흔적을 조직명으로,
본문의 보이지 않는 문자·전각 공백을 정리. `verify --deck` 의 V16 이 남은 것을 경고한다.

## V4 내용 위생 〔기계 · 매 빌드〕

```bash
python engine/tools/deck_lint.py <out/최종.pptx> --own "<이번 조사 주제어>"
```

V1 이 「PowerPoint 가 여는가」를 본다면 V4 는 **「사람이 보기에 틀린 데가 없는가」**를 본다.
검사는 전부 코퍼스 5사례 실측에서 나왔다(`engine/refs/corpus_20260824/ANALYSIS_PPT.md`).

- `PRODUCTION_MEMO`·`UNFILLED_MARKER` — **fatal, 빌드를 막는다.** 최종본 5벌 전부 0건이다(R-143).
  우리 템플릿이 LG 제작본(메모 72개)에서 왔으므로 장을 복제하면 딸려온다
- `TYPO_NEAR_DUP` — 한 덱이 같은 것을 두 이름으로 부르면 드문 쪽이 오타다(R-144).
  **정밀도 약 70%라 차단하지 않는다** — 사람이 판정한다. 빈도비 내림차순으로 나온다.
  실측: 납품된 최종본 5벌 **전부**에서 오타를 찾았다(`출입동제` 1회 ↔ `출입통제` 423회 등)

`build_body.py` 끝에서 자동으로 돈다. fatal 이면 거기서 멈춘다.

## V5 렌더 QA 〔에이전트 `deck-render-qa` · 챕터 단위 병렬〕

챕터 묶음이 완성될 때마다 돈다. 챕터당 에이전트 1개, 최대 6 병렬.

**주는 것**: 렌더 PNG 경로 + 장표 스펙 슬라이스(위치·제목·차트타입·표 크기·Base 문자열).
**주지 않는 것**: 통계표 원본 · 제작 코드 · 제작 대화.
의도를 알면 "의도대로 됐나"를 검사하게 되는데, 필요한 건 **"처음 보는 독자에게 어떻게 보이나"**다.

잡는 것: 음절 단위 줄바꿈 · 넘침/잘림 · 겹침 · 빈 값 · 서식 이질감 · 스펙 불일치.

## V6 적대 감사 〔에이전트 `deck-adversary` · 납품 전 + 대변경 후〕

**주는 것**: 산출 `.pptx` + 정본 전부(slide_facts · tables · questionnaire · 조사개요).
**주지 않는 것**: 제작 세션의 대화·의도·경위. 제작 논리를 알면 반증이 무뎌진다.

렌즈 3을 전부 돈다 — 콘텐츠(근거 없는 주장·한정구 탈락·측정하지 않은 결론) ·
패키지(validate 너머) · 브랜드/유출.
목표는 통과가 아니라 격추다. **반박에 실패한 것만 통과.**

## 에이전트 산출 계약 (V5·V6 공통)

- **수정하지 않는다.** findings JSON 으로만 보고하고, 처리(수정/반송/사람 판단)는
  오케스트레이터인 내가 결정한다
- **"안 봤음"과 "봤는데 없음"을 구분해 기록**하게 한다. 그래야 다음 감사가 이어받는다
- 결과는 `work/검수/` 아래 저장·병합한다

## 반송 — 정본 결함을 발견했을 때

헌법 1에 따라 **고치지 않고 반송**한다.

- `2_보고서작성/work/반송_가이드팀.md` 에 append. **이 파일은 PPT 세션만 쓴다**
- 항목마다 `R-PPT-NNN` 연번 + 심각도(높음/중/낮음) + 근거
- 가이드 팀은 자기 파일(`1_제작가이드/work/반송처리_로그.md`)에 처리 상태를 쓰고
  반영 완료를 메시지로 통지한다. 상태 칸 갱신은 통지받은 뒤 내가 한다
- **정본이 재빌드되면 덱도 재빌드한다.** 통지 전에 미리 빌드해 봐야 버린다

### 세션 간 규칙 — 한 파일 한 주인

| 소유 | 파일 |
|---|---|
| PPT 세션 | `2_보고서작성/**` (산출물·빌드 스크립트·HANDOVER·반송 대장) |
| 가이드 세션 | `1_제작가이드/**` · 정본 데이터(`slide_facts.json` · `tables.json`) |

상대 소유 파일은 **직접 수정하지 않고 메시지로 넘긴다.**
한 경로에 두 세션이 쓰면 나중 것이 이긴다 — 실제로 HANDOVER 가 덮여쓰인 적이 있다.

**소비 필드 계약**: 정본 스키마에 필드를 *추가*하는 건 안전하고, 기존 필드의
*이름·구조 변경*은 breaking 이므로 사전 통지를 받는다.
