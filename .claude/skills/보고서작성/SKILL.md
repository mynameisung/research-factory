- **`UPDATE: NONE`** 또는 **`DISABLED`** — 아무 말 없이 본 절차로 간다.
- **`UPDATE: UPGRADE_AVAILABLE <내판> <새판>`** — 먼저 `update_check.py whats-new <새판>` 으로 바뀐 점을 읽는다.
  `update_check.py config get auto_upgrade` 가 `true` 면 묻지 않고 `/업그레이드` 를 실행한 뒤 본 절차로 간다.
  아니면 AskUserQuestion 으로 묻는다 — 「report-factory **<새판>** 이 나왔습니다 (지금 <내판>). <바뀐 점 한 줄>. 올릴까요?」

  2. **앞으로는 자동으로** → `update_check.py config set auto_upgrade true` → `/업그레이드` → 본 절차
  3. **지금 말고 나중에** → `update_check.py snooze <새판>`. 출력의 next 값대로 「다음 알림은 24시간 뒤입니다」라고 알린다(두 번째는 48시간, 세 번째부터 1주일) → 본 절차
  4. **다시 묻지 않는다** → `update_check.py config set update_check false`. 「다시 켜려면 `config set update_check true`」 → 본 절차
- **`UPDATE: JUST_UPGRADED <이전판> <내판>`** — `whats-new <내판>` 을 읽어 「<내판> 으로 올라왔습니다: <바뀐 점>」 한 줄만 말하고 본 절차로 간다.
- **`UPDATE: CHECK_FAILED <이유>`** — 「판을 확인하지 못했습니다(<이유>). 그대로 진행합니다」 한 줄만 말하고 본 절차로 간다. 최신으로 읽지 않는다.
- **`MEMORY: <경로>`** — 그 `MEMORY.md` 를 읽는다. 「결정된 것」은 다시 묻지 않는다. 스킬이 끝날 때 세 절(결정된 것 · 지시의 요지 · 다음 세션이 알아야 할 것)을 갱신한다. `MEMORY_NEW: yes` 면 읽을 것이 없으니 끝날 때 채우기만 한다.
- **`MEMORY: NONE`** — 조사 폴더 인자가 없었다. 조사가 정해지는 즉시 조사 폴더를 인자로 이 명령을 다시 실행한다.
- **`PATHS: {…}`** — 역할 → 경로 JSON. 설문지·통계표·정본 JSON·제작본·최종보고서 같은 파일과 단계 폴더를 **여기서 찾는다.** 폴더 이름을 추측하거나 `input/` 을 뒤지지 않는다. 역할 하나만 필요하면 `paths.py <조사> --role <역할>`. `LAYOUT: v1` 이면 옛 배치이고 같은 역할 이름으로 풀려 있으니 그대로 쓴다(`paths.py migrate` 는 사람이 정한다). `LAYOUT: none` 이면 `paths.py new <프로젝트>/<조사>` 로 뼈대를 만든다. `files_all` 에 설문지나 통계표가 여러 벌 있으면 어느 것을 쓸지 사용자에게 확인한다.
- **`TRACKING: …`** 이 있으면 트래킹 조사다. `PREV_PATHS:` 의 이전 회차 통계표·최종보고서·제작가이드를 전차 비교의 정본으로 쓴다(전년 수치를 기억이나 추정으로 쓰지 않는다). 이전 회차가 `NONE` 이면 첫 회차이므로 비교 없이 간다.

리서치 통계표를 **보고서 PPT**로 완성한다. 들어오는 길이 셋이다.

| | 경로 A — 제작본 마감 | 경로 B — 직접 제작 | 경로 C — 정본 재반영 |
|---|---|---|---|
| 시작점 | 제작팀 회신 `.pptx` | 예시 덱(다른 고객사) + 제작가이드 산출물 | 완성된 덱 + 갱신된 정본 |
| 몸통 | 도형 이식 → 값 주입 | 브랜드 치환 → 골격 조립 → 전량 주입 | 값만 갈아 끼우기 |
| 도구 | `fill_deck --scan` · **`refill_deck`** | `rebrand.py` · `deckbuild.py` · 프로젝트 빌드 스크립트 | **`refill_deck`** |
| 위험 | 제작팀 개선 서식을 지움 · 더미를 값으로 오인 | **이전 고객사 자산 유출** · 패키지 파손 | 구조를 건드려 레이아웃이 깨짐 |

세 경로 모두 **차트는 「임베디드 데이터 시트에 값을 넣어」 고친다.** 표 위에 텍스트를
그리지 않는다 — 그러면 사용자가 차트를 더블클릭했을 때 옛 값이 그대로 있고,
막대 길이와 라벨이 어긋난다. `deckops.apply_chart` 가 차트 캐시와 워크시트를 함께 쓴다.

인자: 조사 폴더 경로. 예 `/보고서작성 projects/2026_에스원_건물현황실사/02_비상주`

# 경로 A — 제작본 마감

## A1. 수령 · 현황 파악

제작본을 `11_보고서/in/` 에 놓고:

```bash
python engine/tools/fill_deck.py --scan <in/{조사}_제작본_YYMMDD.pptx>
```

`--scan` 이 보고하는 것:
- 총 슬라이드 수 · 분류별 집계 (표지/목차/간지/조사개요/요약/결론/본문/부록)
- **`Data 입력` 계열 메모가 붙은 슬라이드 목록** ← 채워야 할 대상
- **클론 패밀리** — 구조가 동일한 슬라이드 묶음 (레이아웃 + 차트타입 + 표 크기로 판정)
- 제작팀 메모 전문 — `장분리`, `보기갯수 동일`, `범례만큼 데이터가 없을때는 빈칸으로 유지해주세요`,
  `보기 순서 확인해주세요` 등. **지시가 섞여 있으니 전부 읽는다**
- 비어 있는 자리 — `???%`, `내용을 입력하세요`, 빈 데이터 시리즈

사용자에게 요약 보고하고, 제작팀 메모 중 **판단이 필요한 것**을 짚어준다.

### A1-b. `--scan` 을 믿지 말고 **차트를 먼저 감사한다**

`--scan` 의 채움도(FILLED/EMPTY)는 **값이 있는가**만 본다. 제작팀은 껍데기를
「그럴듯한 숫자」로 채워 보낸다 — 실측: 가로막대 차트가 전부 `50.0`,
±세로막대가 다섯 계열 전부 `±20.0` 이었다. 둘 다 FILLED 로 읽혔고 표 검사도
통과했다(표만 보므로). 그래서 스캔 다음에 이걸 돌린다:

```bash
python engine/tools/refill_deck.py <in/제작본.pptx> <09_제작가이드/work/slide_facts.json> --audit-charts
```

실제로 잡아낸 것(에스원 2026-09-03, 차트 69개):
`C0` 차트 없음 36장 · `C9` 더미값 4장 · `C1` 값 불일치 15장 · `C8` 여분 계열 잔값 5장.

## A2. 정본 재반영 — `refill_deck` 이 정본 경로다

```bash
python engine/tools/refill_deck.py <in/제작본.pptx> <09_제작가이드/work/slide_facts.json>   --out <out/{조사}_보고서_{rev}_YYMMDD.pptx> --fit-rows
```

**`fill_deck --fill` 을 이 자리에 쓰지 않는다.** 그건 문항코드로 표를 찾으므로
장분리(같은 코드가 여러 장)에서 엉뚱한 표를 붙이고, Base 라벨을 제 판단으로
「전체」로 바꿔 「500명 중 300명」으로 읽히는 오독을 만든다(실측 s50 은
「웹 대시보드 n=44」 자리에 n=58 표를 매핑했다). `refill_deck` 은
**장표 순서가 정본과 1:1** 이라는 사실을 조인 키로 쓰고, Qu·소제목·배너 열 수를
교차 검증해 한 장이라도 어긋나면 **아무것도 쓰지 않고 멈춘다.**

### 원칙 — 구조는 덱이 진리, 값은 정본이 진리

행 수·열 수·계열 수는 덱에 이미 내려진 결정이다(꼬리 접기·배너 절단·범례 구성).
값만 갈아 끼우는 것이 기본이고, 구조가 어긋나면 멈춘다. `--fit-rows` 는
빈 껍데기를 채울 때만 쓴다. 행 수가 달라도 **라벨로 붙을 수 있으면 라벨로 붙인다** —
제작팀이 보기를 줄여 보낸 장표(「항목 10개만 작업」)에서 값만 바꾸는 유일한 안전한 길이다.

### 제작팀이 손본 것을 지우지 않는다

제작본은 우리 조립본보다 나은 자리가 있다. 값 주입이 그것을 지우면 후퇴다.
실측으로 확인된 넷:

| 제작팀 개선 | 지키는 방법 |
|---|---|
| 평균 행 분홍 강조 · 붉은 글씨 | 표 도형을 그대로 두고 값 셀만 쓴다 |
| (Base) 행 저베이스 별표 `(13*)` | **(Base) 행을 건드리지 않는다** |
| 각주 「*Too small base(n<30)」 | 정본 `base_note` 가 비어도 **그 줄을 지우지 않는다** |
| Base 라벨 별표 `(n=20*)` | 별표만 다르면 덱을 존중한다 |

각주는 **줄 구분 방식이 셋**이라 특히 조심한다 — 문단(`a:p`) · `<a:br/>` ·
**런 텍스트 안의 `\n` 문자**. 제작팀 회신본은 세 번째였다(문단 1개·br 0개인데 두 줄).
앞 둘만 보면 「한 줄 상자」로 읽히고, 그 줄을 갈아 끼울 때 각주가 통째로 사라진다.

### 도형이 없는 장 — 제작팀은 「18p 동일 포맷」 메모만 보낸다

실측 36장이 표·차트 도형 없이 왔다. 메모가 지정한 대표에서 뜬다
(열 수·차트타입이 대표와 일치함을 먼저 확인한다):

- **표는 제작본 대표에서** — 제작팀이 손본 서식이 따라온다
- **차트도 제작본 대표에서** — 데이터 라벨 위치·색을 정교하게 잡아 놨다.
  겹침막대는 1순위 값이 막대 안, 누적값이 막대 끝이다
- **±세로막대 차트만 우리 조립본에서** — 워크북이 수식으로 굴러가서
  (중립점 아래를 −1 로 곱한다) 값을 다시 계산해 넣을 수 없다
- 차트를 이식할 때 **배치를 통째로 빌린다** — graphicFrame 만 빌리면 막대가 어긋난다.
  막대 영역은 프레임 안의 **비율**(`plotArea/layout`)로 정해지므로, 폭이 다른
  프레임에 남의 비율을 얹으면 시작점이 밀려 **표의 라벨 열을 덮는다**
  (실측 0.2cm 밀려 「0개」가 「0기」로 잘려 읽혔다)
- 기존 차트를 바꿔 끼울 때는 **rels 까지 끊는다.** 도형만 지우고 관계를 남기면
  `chart_parts()[0]` 이 지운 유령을 계속 가리켜, 값 주입도 감사도 그것을 상대한다

### 순위 겹침막대 — 두 계열의 값은 배너 열이 아니다

```
누적(1+N순위) = row["cells"][0]          (전체 열)
1순위        = row["rank_first_total"]  (별도 필드)
```

`rank_columns` 의 인덱스를 `cells` 인덱스로 쓰면 「전체 열」과 「첫 배너 열」을
두 계열로 넣게 되어 **1순위가 누적보다 큰 그림**이 나온다. 파일은 멀쩡히 열리고
표 값도 전부 맞아서 V2 가 통과한다 — 그래서 위험하다. 차트 감사(`C3`)가 잡는다.
계열 순서는 긴 값(누적)이 order=0, 1순위가 나중(overlap=100) — R-109.

### 척도 범례는 문항마다 다르다

제작팀은 「범례」 텍스트 상자를 **대표 장에만** 만들어 둔다(실측 21장 중 2장).
상자를 복제해 넣되 **텍스트는 그 문항의 척도 라벨로 바꾼다** — 설문지가 정본이다.
만족도는 「매우 만족」, 추천의향은 「매우 추천 의향이 있다」다. 복제한 상자를 그대로
두면 추천의향 장에 만족도 범례가 실린다. 표 셀에 범례를 또 쓰면 두 벌이 겹친다.

### 그 밖에

- 소수점 — % 1자리, 평균·NPS 2자리
- 「전체」 열은 **평균 행만** 채운다 — 나머지 행은 차트가 그 자리를 덮는다(실측 23장 무예외)
- `범례만큼 데이터가 없을때는 빈칸으로 유지` → 계열 개수 고정, 값만 `None`(0 이 아니다)
- **제작팀 메모는 검수 중에는 남긴다.** 납품본에서만 `refill_deck.py --drop-memos` 로 걷는다
  (V4 가 `PRODUCTION_MEMO` 를 fatal 로 막는다)
- 제작팀이 **작업 지시를 그림으로** 붙여 보내는 경우가 있다(실측 s23: 「보기 개수 −1 로
  셀 분할」 안내가 33×17cm 전면 캡처). 본문 장의 전면 그림은 배경이 아니라 지시서다 —
  걷어낸다. 단 표지·간지·마지막 여백 장의 전면 이미지는 정상 디자인이다

클론 패밀리 매칭이 애매하면 자동으로 넘기지 말고 **멈추고 물어본다.**
잘못 채운 장표는 검수에서 잡기 어렵다.


## A3. 멘트 보강

# 경로 C — 정본이 갱신됐다 (덱 재반영)

통계표가 다시 왔거나 DP 가 값을 고쳐 보냈을 때. **덱을 다시 조립하지 않는다.**

```
tables.json 재파싱 → build_facts.py → slide_facts.json
    → refill_deck.py --out <새 rev>   (구조는 그대로, 값만 갱신)
    → refill_deck.py --audit-charts   (차트가 정본과 맞는지)
    → §검증 7로
```

### C1. 통계표 파싱 — 선지 번호를 먼저 뗀다

```bash
python engine/tools/parse_table_biff.py <새.xls> <work/_새정본/tables.json>
python engine/tools/strip_choice_numbers.py <work/_새정본> --apply
```

통계표가 「번호 있는 버전」으로 오는 일이 있다(실측 484행이 `1) 직접 알고 있음` 꼴).
번호를 안 떼면 기존 정본과 라벨이 달라져 **값 이식이 위치 매칭으로 떨어진다.**

### C2. 무엇이 바뀌었는지 먼저 센다

새 통계표와 기존 정본을 표별로 대조한다 — Base · 행 구성 · 값. 실측(2026-09-04)에서
90표 가운데 값이 바뀐 표는 **6개뿐**이었고, 그걸 알고 들어가면 검증에서 무엇을 봐야
하는지가 정해진다. 지난 회차에 **원본 `.xls` 를 직접 고친 이력**(오타 정정)이 있으면
새 통계표에 그 정정이 반영됐는지도 확인한다(실측: DP 가 반영해 보냈다).

### C3. 정본 갱신 — `refresh_facts` 로 값만 이식한다

```bash
python engine/tools/refresh_facts.py <slide_facts.json> <새 tables.json>   --out <slide_facts.json> --summary <summary_map.json> --allow-structure-change 37 --md <리포트>
```

**`build_facts` 를 다시 돌리지 않는다.** `slide_facts.json` 은 그 산출물 그대로가
아니고 그 뒤에 손질이 여러 겹 얹혀 있다 — 라벨 정정(「0」→「0층」) · 파이핑 치환 ·
선지 번호 제거 · 멘트 확정 · 목차 페이지 · 요약 설계 · **파생 구간 접기**
(R-PPT-008: A1 지상 층수 19행을 총 층수 구간 6행으로). 옵션 기록이 남아 있지 않으므로
재실행은 그 손질을 전부 잃는다. 실측으로 확인했다 — 69장 전부 재현 실패.

- **행은 라벨로 붙인다.** DP 가 보기 순서를 바꿔 보내는 일이 있고(실측 A6·D10-1 에서
  두 보기의 자리가 서로 바뀌었다), 위치로 이식하면 **라벨은 옛 순서·값은 새 순서**가
  되어 두 보기의 수치가 맞바뀐다. 파일은 멀쩡하고 채움도도 정상이라 눈으로는 안 보인다
- **구조가 바뀐 장은 손대지 않고 보고한다.** 보기가 추가·삭제되면 장표 행 수가
  달라지는 일이라 사람이 정한다(`--allow-structure-change <표번호>`)
- **파생 구간을 쓰는 표는 기존을 지킨다.** 새 통계표로 덮으면 원본 행 수로 돌아가
  장표가 물리적으로 안 들어간다. `tables.json` 을 갈아 끼울 때 그 표만 병합한다

### C4. KPI 요약표 — 재생성은 사람이 만든 표를 잃는다

`make_kpi_summary.py` 는 **표9001·9002 두 개만** 만든다. 9003~9006(최상위 응답률 ·
가격 제시 전·후 · 중요도와 위탁률 · 위탁 중인 업무)은 사람이 설계해 얹은 표다.
재생성으로 파일을 덮으면 **넷이 사라진다**(실측: 6표 → 2표). 재생성한 뒤
백업에서 되붙이고, 원표가 바뀐 자리만 갈아 끼운다. 선지 번호 제거도 함께 건다.

### C5. 덱 갱신 → 요약·결론 → 검증

```bash
python engine/tools/refill_deck.py <덱> <slide_facts.json> --out <새 rev> --fit-rows
python engine/tools/refill_deck.py <새 rev> <slide_facts.json> --audit-charts
python engine/tools/verify.py <새 rev> <tables.json> --mode deck --facts … --questionnaire …
python engine/tools/verify.py <summary_map.json> <tables+KPI.json> --mode summary --facts …
```

**`--mode summary` 는 덱이 아니라 정본을 본다.** 요약 근거 좌표
(`claims[].evidence[]` = 표·행·열·값)를 통계표와 대조하므로, 통계표가 바뀌면
그 값도 갱신해야 한다 — 안 하면 덱을 올바르게 고쳐도 검증이 계속 치명으로 잡는다.
`refresh_facts --summary` 가 근거값과 **표본 수 표기**(패널 `base_n` · 문장의 「N곳」)를
함께 맞춘다. 수치가 든 문장은 뜻이 달라질 수 있어 목록만 내고 사람이 본다.

**요약 장표는 refill_deck 이 손대지 않는다** — 한 장에 패널 여럿이 서고 두 표를 한
그래프에 겹치기도 해서다. 근거 좌표가 가리키는 자리만 짚어 갈아 끼운다. 그때
**카테고리만으로 차트를 고르면 안 된다**: 같은 보기 목록을 쓰는 다른 표의 차트가
같은 장에 있어 그것까지 덮는다(실측: 표32 위탁률 차트를 표18 중요도 값으로 덮었다).
현재 값이 그 표의 값과 반올림 수준으로 맞는 차트만 고른다.

- 멘트는 기본으로 **보존**한다(`--overwrite-ment` 를 주지 않는다). 값이 바뀌어
  멘트도 다시 써야 하면 정본(업무 A)에서 고쳐 내려오는 것이 정상 경로다 — 헌법 1
- 값만 바뀐 경우에도 **차트 감사를 다시 돌린다.** 표는 맞고 차트는 틀린 상태가
  이 업무에서 가장 자주 나오는 결함이다
- 척도(±세로막대) 차트는 워크북이 **수식으로** 굴러간다. 부호를 만드는 수식이
  하우스마다 다르다 — 단항 마이너스(`=-B11`)와 곱셈(`=B14*-1`)이 둘 다 쓰이고,
  입력 블록 표식도 「▼데이터 입력」·「▼데이터 입력칸」 두 꼴이다. 한쪽만 보면
  **부호가 사라지거나 입력 블록이 옛 값으로 남는다**(둘 다 실제로 물렸다)

  대표의 `(500)` 이 그대로 온다. 문항 응답자가 286·262 명인 장표 4곳에서 걸렸다.
  「500명 중 …」 으로 읽히는 오독이고 저베이스 경고도 사라진다. V2 는 값 셀만 보아
  통과시켰다 → `refill_table` 이 (Base) 행을 정본으로 갱신하게 고쳤다
- **새로 생긴 보기가 안 실렸다** — 라벨 매칭이 덱 7행을 정본 8행 중 7개에 붙여
  버려 새 보기가 조용히 빠졌다 → `--fit-rows` 를 준 자리에서는 행 수 맞추기가
  라벨 매칭보다 **먼저**다. 제작팀이 의도적으로 줄인 장표는 `--keep-rows` 로 뺀다

대조기가 지적하는 장이 있으면 **대조기 자체를 먼저 의심한다.** 기대값 계산 규칙이
주입 규칙과 어긋나면 멀쩡한 덱이 전부 불일치로 잡힌다 — 순위 겹침막대의 두 계열은
「전체」 열에 겹쳐 그리는 것이지 배너 열이 아니고(누적=`cells[0]` · 1순위=
`rank_first_total`), ±세로막대 표는 지표 행이 위·배너 헤더가 아래로 뒤집혀 있다.

## 반송 — 정본 결함을 발견했을 때

헌법 1에 따라 **고치지 않고 반송**한다.

- `11_보고서/work/반송_가이드팀.md` 에 append. **이 파일은 PPT 세션만 쓴다**
- 항목마다 `R-PPT-NNN` 연번 + 심각도(높음/중/낮음) + 근거
- 가이드 팀은 자기 파일(`09_제작가이드/work/반송처리_로그.md`)에 처리 상태를 쓰고
  반영 완료를 메시지로 통지한다. 상태 칸 갱신은 통지받은 뒤 내가 한다
- **정본이 재빌드되면 덱도 재빌드한다.** 통지 전에 미리 빌드해 봐야 버린다

### 세션 간 규칙 — 한 파일 한 주인

| 소유 | 파일 |
|---|---|
| PPT 세션 | `11_보고서/**` (산출물·빌드 스크립트·HANDOVER·반송 대장) |
| 가이드 세션 | `09_제작가이드/**` · 정본 데이터(`slide_facts.json` · `tables.json`) |

상대 소유 파일은 **직접 수정하지 않고 메시지로 넘긴다.**
한 경로에 두 세션이 쓰면 나중 것이 이긴다 — 실제로 HANDOVER 가 덮여쓰인 적이 있다.

**소비 필드 계약**: 정본 스키마에 필드를 *추가*하는 건 안전하고, 기존 필드의
*이름·구조 변경*은 breaking 이므로 사전 통지를 받는다.
