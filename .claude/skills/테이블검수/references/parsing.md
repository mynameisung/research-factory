# 파일 읽기와 블록 분할

## 포맷별 처리

| 포맷 | 처리 |
|---|---|
| `.docx` | `scripts/read_docx.py` — 문단·표를 문서 순서대로, 색·취소선·형광펜 포함 |
| `.xlsx` / `.xlsm` | `scripts/dump_tables.py` |
| `.xls` (구형 BIFF8) | `dump_tables.py` — xlrd로 읽는다. **변환 요청하지 않는다** (DP실이 `.xls`로 내는 경우가 흔하다). `pip install xlrd` 필요 |
| `.csv` / `.tsv` / `.txt` | `dump_tables.py` — utf-8-sig → cp949 → utf-8 순으로 인코딩 시도 |
| `.doc` (구형) | **변환 요청.** 추측해서 읽지 않는다 |
| `.hwp` / `.hwpx` | **변환 요청** — "Word(.docx)나 Excel(.xlsx)로 저장해 주세요" |
| `.pdf` | 테이블 원본으로는 부적합. 원본 엑셀을 요청한다 |

`.xls`는 파일 시그니처를 먼저 본다 — `d0cf11e0`이면 진짜 BIFF8이라 xlrd로 읽힌다.
`<html`이나 `PK`로 시작하면 확장자만 `.xls`인 HTML·xlsx이므로 그때는 변환을 요청한다.

```bash
python -c "print(open(r'<파일>','rb').read(8).hex())"
```

변환을 요청할 때는 무엇이 왜 필요한지 한 줄로 말하고, 그동안 할 수 있는
다른 파일 검수는 먼저 진행한다.

## `dump_tables.py` 사용 순서

```bash
# 1. 전체 훑기 — 블록 수, 문번, N이 상식적인가
python scripts/dump_tables.py 테이블.xlsx --list

# 2. 표본 확인 — 반드시 2~3개는 원본 격자로 본다
python scripts/dump_tables.py 테이블.xlsx --block 0
python scripts/dump_tables.py 테이블.xlsx --block 12

# 3. 특정 문항 찾기
python scripts/dump_tables.py 테이블.xlsx --list --grep Q11

# 4. 대조용 전체 덤프
python scripts/dump_tables.py 테이블.xlsx --json -o tables.json
```

**2단계를 건너뛰지 마라.** 블록 분할이 어긋난 채로 대조하면 경보 수백 건이
한꺼번에 뜨고, 그중 진짜는 하나도 없다.

### 분할이 어긋났을 때

| 증상 | 조치 |
|---|---|
| 블록 수가 문항 수보다 훨씬 많음 | 표 중간 빈 행이 구분자로 잡힘 → `--sep-rows 2` |
| 블록 수가 문항 수보다 적고 한 블록에 표 여럿 | 표 사이에 빈 행이 없음 → `--title-regex`로 제목 행을 기준 삼거나 시트별로 나눠 처리 |
| 문번이 비어 있음(`-`) | 제목 표기가 기본 정규식과 다름 → `--title-regex` 조정 |
| 라벨이 곳곳에 빈칸 | 병합 셀 → 기본값이 채우기 켬. 꺼져 있으면 `--no-fill-merged` 제거 |
| N이 엉뚱한 값 | 사례수 행 판별 실패 → `--block`으로 확인 후 수동 지정 |

기본 문번 정규식:

```
(?:^|[\[\(\s])((?:S|D|B|F|A|Q|문)?Q?\s*\d+(?:\s*[-_.]\s*\d+)*)\s*[.)\]]?
```

`Q1`, `SQ2-1`, `DQ3`, `A1_2`, `문5`, `[Q7]`, `1.` 를 잡는다. 그룹 1이 문번이다.

## 블록 구조 읽기

`dump_tables.py`가 블록마다 내놓는 것:

| 키 | 의미 | 주의 |
|---|---|---|
| `qcode` | 제목에서 뽑은 문번 | 빈 문자열이면 정규식 조정 필요 |
| `title` | 첫 비어 있지 않은 행 전체 | 제목이 두 줄로 쪼개져 있으면 뒤가 잘린다 |
| `base_label` | 앞 6행 중 base 힌트가 있는 행 | 없으면 빈 문자열 |
| `n_row` / `total_n` | 사례수 행 위치와 첫 값 | 가중사례수 행이 별도로 있으면 어느 쪽인지 확인 |
| `n_values` | 사례수 행의 전체 숫자 | 배너 열별 사례수. 합 = 전체 N 검증에 쓴다 |
| `row_labels` | 사례수 행 아래의 라벨들 | **평균·표준편차·TOP2 행이 섞여 있다.** 보기 수로 그대로 세지 마라 |
| `rows` | 원본 격자 그대로 | 최종 근거는 항상 이것 |

### 사례수 행 판별 규칙

첫 열 라벨이 다음으로 시작하는 행을 사례수 행으로 본다:
`사례수` `응답자수` `Base` `전체` `계` `합계` `표본수` `n수` `(명)`

두 개 이상 잡히면 **첫 번째**를 쓴다. 가중치 프로젝트에서 `사례수` / `가중사례수`가
나란히 있으면 어느 것을 읽었는지 리포트에 명시한다.

### 배너(열) 구조 읽기

사례수 행 위쪽 행들이 배너 헤더다. 보통 2~3층으로 병합돼 있다.
병합 셀 채우기가 켜져 있어야 각 열이 어느 배너 그룹에 속하는지 알 수 있다.

첫 표에서 배너 열 목록을 확정한 뒤, **모든 표가 같은 열 구조인지** 확인한다.
`n_cols`가 다른 블록을 찾으면 그것부터 본다.

## 큰 파일 다루기

- 시트가 많으면 `--sheets` 로 나눠 읽는다
- `--json` 전체 덤프는 원본 격자를 통째로 담아 커진다. 파일로 받고(`-o`),
  대조는 코드로 돌린다. JSON 전문을 컨텍스트에 올리지 마라
- 블록이 200개를 넘으면 `--list` 결과부터 파일로 받아 문번 목록만 뽑아 쓴다
