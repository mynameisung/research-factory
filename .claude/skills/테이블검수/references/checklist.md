# 검수 항목별 판정 기준

이 문서가 판정의 기준선이다. 매 회차 여기 적힌 대로 본다.
애매하면 `이상`이 아니라 `확인필요`다.

---

## 1. 쿼터 일치 확인 (응답자 특성)

**무엇을 보나** — 설문지의 쿼터(할당)표와 테이블의 응답자 특성 표가 맞는가.

확인 순서:

0. **가이드 개요의 총 표본수와 테이블 전체 N을 먼저 맞춘다.** 여기가 어긋나면
   그 아래 모든 검증의 기준선이 틀린 것이므로, 다음 단계로 가기 전에 확정한다.
1. 설문지에서 쿼터 축을 찾는다 (성별 / 연령 / 지역 / 그 밖의 선별 조건).
   교차 할당(성×연령 12셀)인지, 각각 독립 할당인지 구분한다. **이걸 잘못 보면 전부 틀린다.**
2. 테이블의 응답자 특성 표에서 셀별 사례수를 뽑는다.
3. 셀별로 목표 vs 실제를 대조한다.
4. **합계 검증** — 각 축의 셀 합이 전체 N과 같은가.
5. **배너 합 검증** — 다른 문항 표에서도 배너 열의 사례수 합이 전체 N과 같은가.
   여기서 어긋나면 배너 정의 자체가 틀린 것이므로 전 문항에 영향을 준다.

| 상황 | 판정 |
|---|---|
| 가이드 개요 총 표본수 ≠ 테이블 전체 N | 이상 (치명) — 기준선 오류. 먼저 확정한다 |
| 셀별 사례수 = 목표 | 적합 |
| 셀별 사례수 ≠ 목표, 오차 범위 합의 없음 | 이상 |
| 셀별 사례수 ≠ 목표지만 "±N 허용" 합의가 있고 그 안 | 확인필요 (합의 내용 기재) |
| 축 합계 ≠ 전체 N | 이상 (치명) |
| 배너 열 합 ≠ 전체 N | 이상 (치명) — 배너 정의 오류 |
| 쿼터 셀 사례수 0 | 이상 — 0건이 나올 수 없는 셀이다 |
| 설문지에 쿼터 지시가 없음 | 미검증 (사용자에게 목표 할당표 요청) |

**주의** — 가중치 적용 여부는 **가이드 개요에서 읽는다**(`guide.json`의 `meta.weighted`).
적용된 프로젝트면 쿼터는 **가중 전 실사례수**로 본다. 테이블에 사례수/가중사례수 두 행이
있으면 어느 쪽을 읽었는지 리포트에 명시한다.
가이드에 "미적용"이라 적혀 있는데 테이블에 가중사례수 행이 있으면 → 확인필요.

## 2. Base 확인 (모든 문항)

**모든 문항이다.** 이상 없는 문항도 `01_문항별검수`에 "적합"으로 한 줄 남긴다.

**숫자보다 정의가 먼저다.** 순서를 지킨다:

1. 설문지에서 그 문항의 base 지시문을 찾아 **문장으로 적는다**
   → "Q6에서 1~3번 응답자"
2. 그 문장을 **기대 사례수로 환산한다**. 환산의 근거는 앞 문항의 테이블이다
   → "블록 19(Q6)의 보기 1+2+3 = 742"
3. 테이블의 base 표기 문구와 사례수를 읽는다
   → "Base: 최근 이용 경험자 / N=758"
4. 셋을 나란히 놓고 판정한다.

| 상황 | 판정 |
|---|---|
| 정의 일치 + 사례수 일치 | 적합 |
| 정의 일치 + 사례수 불일치 | **이상** — 가장 중요한 이슈 유형 |
| 정의 불일치 (표기 문구가 설문지 조건과 다름) | 이상 |
| base 표기가 아예 없음 | 이상 (경미) — 표기 추가 요청 |
| 복수응답 문항에서 base가 응답수(사례수 아님)로 잡힘 | 이상 — %기준이 통째로 달라진다 |
| 정의를 설문지에서 찾을 수 없음 | 확인필요 |

**복수응답 문항의 함정** — base가 "응답자 수"인지 "응답 수"인지 확인한다.
백분율 합이 100%를 크게 넘으면 응답자 기준(정상), 정확히 100%면 응답 기준이다.
가이드 지시와 다르면 이슈다.

**척도 문항의 함정** — TOP2/BOTTOM2·평균의 base가 본 보기의 base와 같은지 본다.
"모름/무응답"을 제외하고 평균을 낸 경우 base가 줄어드는데, 가이드에 그 지시가
없으면 확인필요다.

## 3. 로직 Check (base/prog 로직 반영)

설문지에서 base 로직·prog 로직을 전부 뽑아 `04_Base로직` 시트에 한 줄씩 올린다.
**설문지에 적힌 로직 문장을 그대로 옮긴다.** 요약하지 않는다 — 근거가 돼야 한다.

잡아야 하는 유형:

| 유형 | 증상 | 확인법 |
|---|---|---|
| **스킵 미반영** | 조건부 문항인데 base가 전체 N | 조건 문항의 해당 보기 합과 대조 |
| **스킵 과반영** | base가 기대보다 작음 | 조건에 없는 추가 필터가 걸림 |
| **이탈자 포함** | 종료 대상이 집계에 남음 | 완료자 수 = 전체 N인지 |
| **배타 보기 처리** | "없음"·"모름" 선택자가 후속 문항에 남음 | 배타 보기 응답수만큼 base가 줄었는가 |
| **루프 문항 base** | 브랜드별·항목별 반복 문항의 base가 전부 동일 | 각 루프의 진입 조건별로 달라야 정상 |
| **최소/최대 선택 수** | 복수응답 평균 선택 수가 지시 범위 밖 | 응답 합 ÷ base |
| **역방향 참조** | 뒤 문항 base가 앞 문항 base보다 큼 | 조건부 문항은 절대 늘어날 수 없다 |

**핵심 규칙 — 조건부 문항의 base는 조건 문항의 base보다 클 수 없다.**
크면 무조건 이상이다. 이건 계산으로 전수 검증이 가능하니 반드시 돌린다.

설문지에 로직이 명시돼 있지 않으면, 테이블에서 관측된 사례수 변화를
**문장으로 되돌려 사용자에게 확인받는다**:

> "Q9의 base가 213명입니다. Q8에서 4~5번을 고른 213명만 받은 것으로 보입니다. 맞습니까?"

이건 이슈가 아니라 `확인필요`다. 답을 받으면 그게 다음 회차의 근거가 된다.

## 4. Code 일치 확인

설문지의 보기 코드·문구와 테이블의 행 라벨을 **쌍으로** 대조한다.
`06_보기코드대조` 시트에 문항×보기 단위로 남긴다.

| 유형 | 판정 |
|---|---|
| 코드·문구 모두 일치 | 적합 |
| 문구 불일치 (의미 같음, 표기만 다름) | 이상 (경미) — 보고서 표기 통일 필요 |
| 문구 불일치 (의미 다름) | 이상 (중요) |
| 코드값 불일치 (설문지 9=기타, 테이블 8=기타) | 이상 — 원자료 매핑 오류 가능성 |
| 보기 순서 뒤바뀜 | 이상 |
| 척도 역코딩 (1=매우만족인데 테이블은 1=매우불만족) | 이상 (치명) — 결과 해석이 뒤집힌다 |
| 넷팅 방향 오류 (TOP2에 4~5 대신 1~2가 묶임) | 이상 (치명) |
| 공백·괄호·단위 표기만 다름 | 확인필요 — 기록은 하되 판정은 사용자 몫 |

**역코딩과 넷팅은 눈에 안 띄면서 가장 치명적이다.** 척도 문항은 예외 없이
"보기 1번이 무엇인가"와 "TOP2가 어느 보기의 합인가"를 확인한다.
TOP2 값이 실제로 해당 두 보기의 합과 같은지 **산술로 검증**한다.

## 5. 문번 확인 (넘버링 누락)

1. 설문지의 문번을 순서대로 나열한다.
2. 가이드의 표 번호를 순서대로 나열한다.
3. 테이블의 블록 문번을 순서대로 나열한다 (`dump_tables.py --list`).
4. 세 목록을 대조한다.

| 유형 | 판정 |
|---|---|
| 설문지·가이드에 있는데 테이블에 없음 | 이상 (치명) — 표 누락 |
| 테이블에만 있음 | 확인필요 — 파생표·추가 요청표일 수 있다 |
| 문번 중복 (같은 문번 표가 둘) | 확인필요 — 분할 산출인지 중복인지 |
| 순서 뒤바뀜 | 이상 (경미) |
| 문번은 있으나 하위 문항 누락 (Q5는 있고 Q5-1 없음) | 이상 |
| 오픈형 문항 표 없음 | 확인필요 — 별도 코딩표로 빠지는 게 보통 |

**주의** — 블록 분할 실패로 두 표가 한 블록에 뭉치면 문번이 통째로 누락된 것처럼
보인다. 누락 후보는 반드시 `--grep 문번`으로 원본에서 재확인한 뒤 확정한다.

## 6. 행·열 구조 / 보기 중복·누락

가이드가 기준이다. 없으면 설문지가 기준이다.

**행(Row) 검수**

- 한 표에 **문항이 두 개 이상 섞여 있지 않은가** — 서로 다른 문항의 보기가 한 표에 있으면 이상
- **보기 번호 중복** — 한 문항 안에 같은 코드가 두 번 나오면 이상
- **보기 누락** — 설문지에 있는데 테이블에 없는 보기
  - 해당 셀 값이 **0이면** → `07_미출력보기` 시트로. **이슈 아님**
  - 0이 아니거나 확인 불가면 → 이상
  - 단, 필수 단수응답 문항의 보기가 전부 0이거나, 쿼터 셀이 0이면 → 이상
- **합계 검증** — 단수응답은 보기 합 = base. 복수응답은 보기 합 ≥ base
  - 단수응답인데 보기 합 ≠ base → 이상 (무응답 행이 있는지 먼저 확인)
- **부가 행** — 평균·표준편차·TOP2·BOTTOM2·넷팅 행이 가이드 지시대로 있는가.
  이 행들을 보기로 세지 않도록 주의한다 (오탐 1순위)

**열(Column, 배너) 검수**

- 배너 열 수·순서가 가이드와 같은가
- **전 문항에 동일 배너가 적용됐는가** — 중간에 열이 늘거나 줄면 이상
- 배너 셀 정의가 설문지 문항과 맞는가 (예: 연령 배너가 실제 연령 문항 기준인가)
- 배너 각 열의 사례수 합 = 전체 N (1번 항목과 중복 검증이지만 전 문항에서 돌린다)
- 소수점 자릿수, 백분율 기준(행%/열%)이 가이드 지시와 같은가

## 오탐 제거 (Phase 5)

원시 경보를 그대로 올리지 않는다. 유형별로 묶어 표본을 원본 격자(`--block N`)로
재확인하고, 제외한 건수와 사유를 `false_positives`에 남긴다.

| 증상 | 진짜 원인 | 확인법 |
|---|---|---|
| 보기 라벨 불일치 대량 | 병합 셀이 빈칸으로 읽힘 | `--block N`으로 원본 확인 |
| Base 불일치 대량 | 가중사례수 열을 사례수로 읽음 | N 행이 둘인지 확인 |
| 문번 누락 대량 | 블록 분할 실패로 표가 뭉침 | `--sep-rows 2` 재실행 |
| 행 수 불일치 | 평균·표준편차·넷팅 행을 보기로 셈 | 행 라벨 목록 직접 확인 |
| 보기 누락 | 응답 0건이라 DP 미출력 | 정상. 07 시트로 |
| 소수점 표기 차이 | 반올림 방식 차이 | 가이드 지시 확인 후 대개 제외 |

## 심각도 기준

| 심각도 | 기준 | 예 |
|---|---|---|
| **치명** | 결과 해석이 뒤집히거나 표가 통째로 없음. 재산출 필수 | 표 누락, 역코딩, 스킵 미반영, 배너 정의 오류 |
| **중요** | 수치가 틀림. 재산출 필요 | base 사례수 불일치, 보기 합 ≠ base, 넷팅 산술 오류 |
| **경미** | 수치는 맞으나 표기가 틀림 | 문구 불일치, base 표기 누락, 순서 뒤바뀜 |
| **확인필요** | 의도인지 오류인지 판단 불가 | 설문지에 근거 없는 base, 테이블에만 있는 표 |
