# 설문지 명세(`spec.json`)와 가이드 명세(`guide.json`)

Phase 1·2의 산출물. 이 두 파일이 대조의 **기준선**이다.
직접 읽고 쓴다 — 설문지 포맷은 회사·연구원마다 다르므로 정규식 파서는 만들지 않는다.

---

## `spec.json` — 설문지에서 뽑는다

```json
{
  "meta": {
    "file": "OOO_설문지_final.docx",
    "target": "전국 만 20~59세 남녀",
    "method": "온라인"
  },
  "quota": [
    { "axis": "성별", "cell": "남성", "target": 500 },
    { "axis": "성별", "cell": "여성", "target": 500 },
    { "axis": "성×연령", "cell": "남성 20대", "target": 125 }
  ],
  "questions": [
    {
      "code": "Q7",
      "order": 12,
      "title": "지난 1개월간 이용한 브랜드를 모두 선택해 주십시오.",
      "type": "복수",
      "base": {
        "text": "Q6에서 1~3번 응답자",
        "depends_on": "Q6",
        "condition": "Q6 in [1,2,3]",
        "source": "설문지 p.5"
      },
      "prog": [
        { "kind": "배타", "text": "99번(없음) 선택 시 다른 보기 선택 불가" },
        { "kind": "최소", "text": "최소 1개 이상 선택" }
      ],
      "options": [
        { "code": "1", "label": "A브랜드" },
        { "code": "2", "label": "B브랜드" },
        { "code": "99", "label": "기타", "kind": "기타" }
      ],
      "scale": null,
      "net": []
    },
    {
      "code": "Q8",
      "order": 13,
      "title": "이용 만족도는 어떠하십니까?",
      "type": "척도",
      "base": { "text": "Q7 응답자 전원", "depends_on": "Q7", "condition": "Q7 answered" },
      "prog": [],
      "options": [
        { "code": "1", "label": "매우 만족" },
        { "code": "5", "label": "전혀 만족하지 않음" }
      ],
      "scale": { "points": 5, "direction": "1=긍정", "mean": true },
      "net": [
        { "name": "TOP2", "codes": ["1", "2"] },
        { "name": "BOTTOM2", "codes": ["4", "5"] }
      ]
    }
  ]
}
```

### 필드 규칙

| 필드 | 규칙 |
|---|---|
| `code` | 설문지 표기 그대로. `Q7`, `SQ2-1`, `A3_2` |
| `order` | 설문지 등장 순서. 문번 누락 검증의 기준 |
| `type` | `단수` / `복수` / `순위` / `척도` / `숫자` / `오픈` / `순위복수` |
| `base.text` | **설문지 문장 그대로 옮긴다.** 요약 금지 — 리포트의 근거가 된다 |
| `base.condition` | 기계 검증용으로 정규화한 조건식. 못 쓰면 `null` |
| `base.source` | 페이지·문단 위치. 이슈 근거 칸에 그대로 들어간다 |
| `prog[].kind` | `스킵` / `이탈` / `배타` / `표시조건` / `최소` / `최대` / `로테이션` |
| `options[].code` | 코드값. 문자열로 통일한다 (`"1"`, `"99"`) |
| `options[].kind` | `기타` / `없음` / `모름` / `배타` — 없으면 생략 |
| `scale.direction` | `1=긍정` 인지 `1=부정` 인지. **역코딩 검증의 유일한 근거다** |
| `net` | 넷팅 정의. 없으면 빈 배열 |

### 설문지를 읽을 때 놓치기 쉬운 것

- **색·취소선으로 표기된 로직** — `read_docx.py`가 `[color=FF0000]…[/]`로 표시해 준다
- **표 안에 들어 있는 보기 목록** — 척도 문항은 표로 그려진 경우가 많다
- **문항 앞 대괄호 지시문** — `[Prog: Q8=4,5인 경우만]`
- **하위 문항** — `Q5-1`, `Q5_2`. 상위만 잡고 넘어가면 문번 누락을 못 잡는다
- **루프 문항** — "Q7에서 선택한 브랜드 각각에 대해". 브랜드 수만큼 표가 나온다

로직이 설문지에 없으면 `"text": "명시 없음"`으로 적는다. 지어내지 않는다.

## `guide.json` — 테이블가이드에서 뽑는다

```json
{
  "meta": {
    "file": "OOO_테이블가이드.xlsx",
    "total_n": 1000,
    "weighted": "미적용",
    "weight_vars": [],
    "target": "전국 만 20~59세 남녀",
    "method": "온라인",
    "wave": "단일 차수",
    "source": "개요 시트 B3:B9"
  },
  "banner": [
    { "group": "전체", "cells": ["전체"] },
    { "group": "성별", "cells": ["남성", "여성"] },
    { "group": "연령", "cells": ["20대", "30대", "40대", "50대"] }
  ],
  "tables": [
    {
      "order": 12,
      "code": "Q7",
      "title": "지난 1개월간 이용 브랜드 (복수응답)",
      "base_text": "최근 1개월 이용 경험자",
      "rows": ["보기 1~12", "기타", "없음"],
      "net_rows": [],
      "banner": "기본",
      "pct_base": "응답자",
      "decimals": 1
    }
  ]
}
```

| 필드 | 쓰임 |
|---|---|
| `meta.total_n` | **조사 개요의 총 표본수.** 쿼터 판정과 전 문항 base 검증의 기준선 |
| `meta.weighted` | 가중치 적용 여부. 적용이면 `weight_vars`와 함께, 사례수/가중사례수 중 어느 행을 읽을지 결정 |
| `meta.wave` | 차수·비교 테이블 여부. 열 구조가 달라진다 |
| `meta.source` | 개요를 읽은 위치(시트·셀). 리포트 근거 칸에 그대로 쓴다 |
| `banner` | 배너 열 구조. 전 표에 동일 적용됐는지 검증 |
| `tables[].order` | 가이드 순서. 테이블 블록 순서와 대조 |
| `rows` / `net_rows` | 행 구성 대조. 넷팅 행을 보기로 세지 않도록 분리해 적는다 |
| `banner` | `기본` 외 다른 배너를 쓰는 표가 있으면 그 이름 |
| `pct_base` | `응답자` / `응답` — 복수응답 % 기준 |

**총 표본수와 가중치 적용 여부는 여기가 출처다.** 설문지가 아니라 가이드에서 읽는다.
`spec.json`에는 넣지 않는다 — 값이 두 군데 있으면 어느 쪽을 봤는지 알 수 없게 된다.
가이드 개요에 없는 항목만 사용자에게 묻는다.

**가이드가 없으면** `guide.json`은 만들지 않는다. `05_행열구조` 시트에
"가이드 미수령 — 설문지 기준으로 대조함"이라 적고 `08_검증범위`에도 남긴다.
이때는 총 표본수·가중치 적용 여부를 사용자에게 직접 묻는다.
가이드가 있는 척 추정하지 않는다.
