## PREAMBLE — 본 절차보다 먼저 실행한다

```bash
python "$(git rev-parse --show-toplevel)/research-factory/engine/tools/preamble.py" --skill 제작가이드 <조사 폴더 인자가 있으면 그대로>
```

한 번의 호출이 새 판 확인·활성 조사 지정·조사 메모리 위치·실행 기록을 처리하고 `KEY: 값` 줄로 답한다. 줄마다 이렇게 한다.

- **`UPDATE: NONE`** 또는 **`DISABLED`** — 아무 말 없이 본 절차로 간다.
- **`UPDATE: UPGRADE_AVAILABLE <내판> <새판>`** — 먼저 `update_check.py whats-new <새판>` 으로 바뀐 점을 읽는다.
  `update_check.py config get auto_upgrade` 가 `true` 면 묻지 않고 `/업그레이드` 를 실행한 뒤 본 절차로 간다.
  아니면 AskUserQuestion 으로 묻는다 — 「research-factory **<새판>** 이 나왔습니다 (지금 <내판>). <바뀐 점 한 줄>. 업데이트 내역: <`RELEASE_NOTES:` 링크>. 올릴까요?」
  (`RELEASE_NOTES_SKIPPED:` 가 있으면 「건너뛴 판의 내역」으로 그 링크들도 붙인다)
  1. **지금 올린다** → `/업그레이드` → 본 절차
  2. **앞으로는 자동으로** → `update_check.py config set auto_upgrade true` → `/업그레이드` → 본 절차
  3. **지금 말고 나중에** → `update_check.py snooze <새판>`. 출력의 next 값대로 「다음 알림은 24시간 뒤입니다」라고 알린다(두 번째는 48시간, 세 번째부터 1주일) → 본 절차
  4. **다시 묻지 않는다** → `update_check.py config set update_check false`. 「다시 켜려면 `config set update_check true`」 → 본 절차
- **`UPDATE: JUST_UPGRADED <이전판> <내판>`** — `whats-new <내판>` 을 읽어 「<내판> 으로 올라왔습니다: <바뀐 점>. 업데이트 내역: <`RELEASE_NOTES:` 링크>」 두 줄만 말하고 본 절차로 간다. 링크는 마크다운 링크로 붙여 누를 수 있게 한다(달라진 점 · 새로 써볼 수 있는 것 · 기능 설명이 그 페이지에 있다). `RELEASE_NOTES_SKIPPED:` 가 있으면 건너뛴 판의 링크도 함께.
- **`MIGRATE: …`** (있을 때만) — 0.5.0 폴더 이름 변경(`report-factory/` → `research-factory/`)의 뒷정리 결과다. 「옮김」뿐이면 「조사 폴더를 새 폴더로 옮겼습니다(옛 경로도 그대로 쓸 수 있습니다)」 한 줄만 말하고 본 절차로 간다. 「열린 파일 때문에 못 옮김」이나 「아직 옛 폴더에 있다」면 엑셀 등 열린 파일을 닫게 한 뒤 `python "$(git rev-parse --show-toplevel)/research-factory/engine/tools/migrate_folder.py"` 를 다시 부르고, 옮겨질 때까지 본 절차로 가지 않는다. 「옛 쪽을 남김」이면 두 파일을 비교해 보여 주고 사용자가 고르게 한다. 「권한 문제」·「대리 파일에 로컬 수정」은 줄에 적힌 대로 처리한다.
- **`UPDATE: CHECK_FAILED <이유>`** — 「판을 확인하지 못했습니다(<이유>). 그대로 진행합니다」 한 줄만 말하고 본 절차로 간다. 최신으로 읽지 않는다.
- **`MEMORY: <경로>`** — 그 `MEMORY.md` 를 읽는다. 「결정된 것」은 다시 묻지 않는다. 스킬이 끝날 때 세 절(결정된 것 · 지시의 요지 · 다음 세션이 알아야 할 것)을 갱신한다. `MEMORY_NEW: yes` 면 읽을 것이 없으니 끝날 때 채우기만 한다.
- **`MEMORY: NONE`** — 조사 폴더 인자가 없었다. 조사가 정해지는 즉시 조사 폴더를 인자로 이 명령을 다시 실행한다.
- **`PATHS: {…}`** — 역할 → 경로 JSON. 설문지·통계표·정본 JSON·제작본·최종보고서 같은 파일과 단계 폴더를 **여기서 찾는다.** 폴더 이름을 추측하거나 `input/` 을 뒤지지 않는다. 역할 하나만 필요하면 `paths.py <조사> --role <역할>`. `LAYOUT: v1` 이면 옛 배치이고 같은 역할 이름으로 풀려 있으니 그대로 쓴다(`paths.py migrate` 는 사람이 정한다). `LAYOUT: none` 이면 `paths.py new <프로젝트>/<조사>` 로 뼈대를 만든다. `files_all` 에 설문지나 통계표가 여러 벌 있으면 어느 것을 쓸지 사용자에게 확인한다.
- **`TRACKING: …`** 이 있으면 트래킹 조사다. `PREV_PATHS:` 의 이전 회차 통계표·최종보고서·제작가이드를 전차 비교의 정본으로 쓴다(전년 수치를 기억이나 추정으로 쓰지 않는다). 이전 회차가 `NONE` 이면 첫 회차이므로 비교 없이 간다.

사용자 입력과 손 편집은 훅이 같은 `_memory/` 폴더에 자동으로 남긴다(`knowledge/02_프로젝트-메모리.md`). 이 블록은 스킬 본문의 어떤 규칙보다 먼저다.

## Step 0 — 오리엔테이션 (예외 없음)

**작업을 시작하기 전에 반드시 한다.** 건너뛰지 않는다.

보고서는 결국 **의뢰인이 알고 싶은 것에 답하는 문서**다. 방향을 잘못 잡으면 뒤 작업이 전부 무의미해진다.

### 0-1. 프로젝트 폴더에 `ORIENTATION.md`가 이미 있으면
읽고 **변경사항만** 확인한다. 전체 재질문은 하지 않는다. 바로 Step 1로.

### 0-2. 없으면 — 의뢰인 의도 자료를 정독한다
`00_협의/` 에서:
- `공통_시장조사개요.docx` — 조사 목적 · 대상 · 기간 · 조사방법 · 표본 구성 · 조사항목
- `공통_입찰공고문_RFP.docx` — 발주처가 정의한 조사항목. 가격·표본 조항도 본다
- `공통_킥오프회의록_*.docx` — 왜 이 조사를 하는지, 무엇이 중요하다고 합의됐는지
- `공통_ToKnowList_*.xlsx` — **의뢰인이 알고 싶은 것 목록. 요약·결론이 답해야 할 질문이다**

해당 조사 폴더에서:
- `03_설문지/*_설문지_*.docx` — 파트 구성과 문항
- `07_테이블/*_통계표_*` — 표 개수, 배너 구성, 베이스

### 0-3. 읽은 것을 요약해 제시한다
```
■ 조사 목적        (한 문단)
■ 의뢰인이 알고 싶은 것   (To Know List에서, 번호 매겨 나열)
■ 조사 성격        사실확인형(인사이트 없음) / 인식조사형(인사이트 필요)
■ 요약·결론        필요 / 불필요  ← 근거와 함께
■ 통계표 현황      표 N장 · n=N · 배너 N열
■ 예상 분량        약 N페이지
```

### 0-4. 방향성 질문 (`AskUserQuestion`)
상황에 맞게 고른다. 기본 후보:
- **To Know List 우선순위** — 어느 항목을 보고서가 가장 강하게 답해야 하나
- **목차 묶음 방식** — 설문지 파트 그대로 갈지, 병합·분리할지
- **배너 사용 범위** — 통계표 배너 중 보고서에 쓸 범위 (PPT 열 제약이 있다)
- **인사이트 방향** — 요약·결론을 어느 쪽으로 몰 것인지 (해당 시)
- **이번 건 특수사항** — 표본 부족, 누락 요약표, 배너 불일치 등 사전에 발견한 이슈

### 0-5. `ORIENTATION.md` 기록
답변과 그 근거를 조사 폴더에 저장한다. 이후 단계와 `/회고`가 이걸 참조한다.

## Step 1 — 입력 파싱

```bash
python engine/tools/parse_questionnaire.py <설문지.docx> <work/questionnaire.json>
python engine/tools/parse_table_biff.py  <통계표.xls>  <work/tables.json>
```
`.xlsx` 통계표면 `parse_table_xlsx.py`.

파싱 직후 `python engine/tools/table_lint.py work/tables.json --out work/검수/table_lint.md` 를 돌려 라벨 중복·오기를 잡는다.
파서는 경고를 내지 않는다(2026-08-24 실측: D4 라벨 중복이 파서 경고 0건으로 통과했다). 정정은 `work/표라벨정정.json` 에 선언하고 `apply_table_fixes.py` 로 적용한다.

파싱 후 **정합성부터 본다**:
- 표 개수 = 목차 개수인가
- 서브베이스 합이 상위 베이스와 맞는가
- 설문지 BASE 정의와 통계표 실제 base가 일치하는가 (불일치는 흔하다 — DP가 다른 기준으로 잡은 경우)
- `n<30` 표가 몇 장인가 → 이 표들은 % 인용을 피하고 멘트 패턴 D를 쓴다

**선지 번호판 통계표면 정규화한다.** 보통은 선지에 번호 없는 버전으로 오는데, 행 라벨이
`1) 직접 알고 있음` 꼴로 파싱됐으면 번호 있는 버전이다:
```bash
python engine/tools/strip_choice_numbers.py <work_dir>          # dry-run 먼저
python engine/tools/strip_choice_numbers.py <work_dir> --apply  # 백업 자동
```
- 특수코드는 **3자리**까지 온다 (`998) 없음`) — 도구가 처리하지만, 적용 후 자릿수 무제한
  정규식으로 잔여 0을 재확인한다 (에스원 건에서 2자리 가정이 7곳을 놓쳤다)
- 도구는 제거 후 **같은 표 안 라벨 중복**을 검사하고 충돌 시 중단한다. 충돌 = 설문지
  보기 라벨 오타 신호다 (에스원 D4: 보기 2·4 가 같은 문장). 척도 구조(BOT2/TOP2)로
  정정 근거가 명백하면 정정하고 **연구원 통보 목록에 올린다**

**누락된 요약표를 확인한다.** 척도 문항이 5개 이상 연속인데 `_TOP2 Summary` / `_Mean Summary` 표가 없으면 요약·결론에서 쓸 재료가 없는 것이다:
```bash
python engine/tools/make_kpi_summary.py <work/tables.json> <work/KPI요약표_직접생성.xlsx>
```
각 표의 `【TOP2】`·`[N점 평균]` 행을 긁어 요약표를 만든다.

**seq 확보** — 목차 배정표의 `seq` 열은 build_facts 의 접기 순번이다. 목차 전에 한 번 돌린다:
```bash
python engine/tools/build_facts.py <work/questionnaire.json> <work/tables.json> <work/slide_facts_pre.json> --kpi <work/KPI요약표_직접생성.json>
```
(전 도구는 `PYTHONUTF8=1` 로 실행한다 — cp949 콘솔에서 깨진다.)

## Step 2 — 목차 설계 〔담당: `guide-toc`〕

`guide/10_목차-설계규칙.md` 를 따른다. **배너 절단선도 이 담당의 산출이다** (쌍 산출물 —
그룹명 화이트리스트로, R-055~057·R-089). 담당에게는 문항 목록·표 목차·표별 요약
통계(base·보기 수·전체값 — 순위 쌍은 **1~N순위 표**에서)·ToKnowList 요지를 `work/toc_brief.md` 로 준다.
초안 → 기계 게이트 `verify.py <work/목차_초안.md> --mode toc --questionnaire … --facts <slide_facts_pre.json>`
(전수성 검증식·한 어절·seq/P 정합·표↔source_tables·BASE n·제외 사유) → `guide-judge` 심사 → **사람 확정**.
R-023 예외④로 표를 빼기로 하면 `build_facts --exclude-tables "60=사유"` 로 재접기(seq 재번호)하고 목차를 갱신한다.
자기참조 배너(대각 100%·단일 범주 n=base)는 룰엔진 `rules.self_referential_banner_groups` 가 자동 제외한다.

**Part Ⅰ·Cover 는 `guide-front`** 가 제안 JSON 을 낸다 (조사개요·RFP 원문 + 표1 대조).
목차.md 병합과 빌드 인자 반영은 메인이 한다 — 담당은 파일을 직접 쓰지 않는다.

```
Part Ⅰ. 조사 개요     1. 조사 목적  2. 조사 설계  3. 응답자 특성
Part Ⅱ. 요약 및 결론   (요약 N장 → 결론/제언)     ← 불필요한 조사면 통째로 생략
Part Ⅲ. 조사 결과     (본문)
```

- **통계표 1장 = PPT 1페이지**. SQ는 전부 제외
- 슬라이드 타이틀 / 서브 타이틀을 여기서 만든다. 서브 타이틀은 **문항 몇 개를 아우르는 축약어**
- 설문지 파트를 1차 기준으로 삼되 **맹신하지 않는다** — 유의미하면 분리, 무의미하면 병합
- 순위 문항은 `_1순위` + `_1~N순위` **두 표가 한 페이지**

### ★ 목차의 4대 제약 (`guide/10` §2-3)

**① 전수성** — 설문지 **모든 문항**이 `part 3 목차(연구부 확인용)` 에 배정돼야 한다.
보고서에서 뺀 문항(SQ, 인지 여부 등)도 **뺐다고 명시**한다. 조용히 빠뜨리지 않는다.

**② 한 어절** — 슬라이드·서브 타이틀에 `및` / `/` 로 두 개념을 잇지 않는다.
`1) 상호작용 및 역할 분담 체계` ✗ → `1) 상호작용` / `2) 역할분담` ✓

**③ MECE** — ②는 ③의 결과다. **`및` 을 쓰고 싶어졌다면 한 꼭지에 두 개념을 욱여넣은 것이다.**
그때는 문구를 다듬지 말고 **항목을 쪼갠다.**

**④ 결론의 출처** — Part Ⅱ 결론·제언은 **같은 Part 의 요약 꼭지에서만** 나온다.
요약에 없던 근거를 결론에서 처음 꺼내지 않는다.

> ⚠ 예시 파일의 목차는 ②를 지키지 않는다. **사용자 규칙이 예시보다 우선한다** —
> 예시는 포맷의 근거이지 작명의 근거가 아니다.

**확정 전 체크리스트**
- [ ] 전 문항이 배정됐거나 제외 사유가 적혀 있다
- [ ] `및` / `/` 로 이은 항목이 없다
- [ ] 한 문항이 두 꼭지에 중복 배정되지 않았다
- [ ] (Part Ⅱ 있을 때) 결론의 모든 항목이 요약 꼭지로 되짚어진다

목차 초안을 `work/목차.md` 로 쓰고 **사용자 확정을 받는다.** 여기서 틀리면 전부 다시 해야 한다.

## Step 3 — 본문 블록 생성

```bash
python engine/tools/build_facts.py  <work/questionnaire.json> <work/tables.json> <work/slide_facts.json> --toc <work/목차.md>
```

룰엔진이 결정론적으로 채우는 것 (AI가 손대지 않는다):
- 차트타입 — `guide/chart_rules.yaml`
- 베이스 `[Base: …(n=NN)/ Unit: %]`
- `Qu:` 문항 텍스트 — 설문지에서 그대로
- 데이터 행 정렬 — 전체값 내림차순, 단 시계열·고정 보기순서면 원래 순서 유지
- `그래프 상단 Text` 배치 — Top·평균 행
- 배너 유의차 — 배너셀 vs 전체 2-proportion z-test → |차이| 랭킹

**AI는 멘트 문장화만 한다.** 룰엔진이 준 숫자 팩트를 하우스 스타일 문장으로 옮긴다. `guide/13_멘트-작성규칙.md` 의 패턴 A~D와 수준어 사다리를 따른다.
**숫자를 새로 계산하거나 추정하지 않는다.** `slide_facts.json` 에 없는 수치는 쓰지 않는다.

**멘트 수용 게이트는 `verify.py <샤드반환.json> --mode ments --facts <slide_facts.json> --json <결과>`** —
≤60자·ㅁ종결(꼬리 괄호 허용)·보기명 원문·수치⊆슬라이스·배너 인용⊆룰엔진 후보(R-065)·수준어 사다리.
장 단위 **경고**(guide/15 §1-9): 순위형 첫 줄 「(1~N순위 기준)」 한정구 · 장당 ≤3줄 · 동률(ties) 묶음 · 배너명 따옴표 금지 —
경고는 반려가 아니라 재발주 판단 재료다(메인이 본다).
수용분만 `멘트_확정.json`({ments:[{seq,lines}]})에 모아 `build_facts --ments` 로 주입한다.

**선택 — 하이브리드 초안(사용자 지시 2026-08-23)**: `python engine/tools/clova_draft.py <work>` 가 CLOVA(HCX-007)로 멘트
초안을 쓰고 같은 게이트에 걸어 수용분(`work/검수/clova_draft_accepted.json`)과 반려 패킷(`work/샤드/재발주_clova.json`)으로 가른다.
반려·누락분만 `guide-body-ment` 가 ment_facts 로 접지해 다시 쓴다(숫자·보기명이 틀리면 Claude 가 고친다). 수용률이 낮으면
(비상주 실측 3/69) Claude 단독과 같으므로 로그의 수용률로 계속 쓸지 판단한다. 요약·결론에는 쓰지 않는다(`30_외부LLM-CLOVA.md`).

**멘트 문장화는 `guide-body-ment` 샤딩으로** — 샤드(장 묶음)별 명시 ID 배정, 담당은
자기 샤드의 팩트 슬라이스만 본다. 샤딩 단위는 양방향: 표 N장→장 1개(순위·매트릭스)는
묶음이 한 샤드, 표 1개→장 N개(R-089 배너 분리)도 같은 표는 같은 샤드. 반환 ID 를
검산해 누락은 재발주하고, 수용은 검증기(≤60자·ㅁ종결·라벨 원문·수치 ⊆ 슬라이스)가 결정한다.
chart_type null·미구현 팩트는 담당이 decisions 로 올린다 — 문장화 금지 (R-088).

**문장 정책 (`guide/17` §문장 정책 — PPT 팀과의 계약)**
- 모든 멘트 줄 **≤60자** · 개조식 ㅁ받침 종결. 근거: PPT 멘트 상자 한 줄 실측 74자 —
  63~74자 구간은 줄바꿈 복불복이 된다
- **보기명은 행 라벨 원문 그대로** 작은따옴표 인용. 축약·의역 금지 (금지 사고 유형).
  길면 라벨을 줄이지 말고 **나열을 절단**(후순위 인용을 떨굼)하거나 **줄을 나눈다**
- 문장 생성을 에이전트에 병렬로 맡길 때는 **기계 검증기로 수용을 결정한다**
  (길이 · 종결 · 보기명 라벨 일치 · 수치가 원문의 부분집합)

**정본 스키마 — 소비자(PPT 팀)가 읽는 필드다 (`guide/17` §소비 계약)**
- `base_label` — **base < 전체인 장은 군 이름 필수.** `[Base: 전체(n=3)]` 은 금지다
  ("500 중 3"으로 오독된다). 근거는 questionnaire 의 base_condition 주해에서 파생하고
  표본 단위(건물/응답자)를 지킨다. base_unit 문자열도 `[Base: {군 이름}(n=…)…]` 로
- `short` — 문항 약칭 하나로 단일화 (테이블가이드 「문항명(요약본)」 계열). 한 문항이
  이름을 세 개 갖게 두지 않는다
- 기존 필드의 이름·구조 변경은 breaking — PPT 팀 사전 통지 후에만

## Step 4 — 요약·결론 블록 (필요한 조사만) 〔담당: `guide-summary`(총괄) → `guide-summary-slide` × 꼭지 수 → `guide-summary-reviewer` → `guide-client-review`〕

`guide/14_요약결론-작성규칙.md` · `guide/15_한국어-문장지침.md`.

- **`guide-summary`(총괄 · 설계 + 결론)** — 시야는 **본문 헤더 전수**에서 시작하고(R-201·R-221) 후보가 서면 그 표를 연다 — 통계표를 전수 스캔하지 않는다.
  인사이트는 정의상 헤드라인 밖에 있으므로(R-073) 후보 발굴은 넓게, 등재는 근거셀로만. 꼭지를 나누고 표를 배정하고 패널·claims 를 세운다. 돌아온 So what 을 이어
  서사를 만들고 **결론 및 제언을 자기 손으로 쓴다**(R-208 — 결론은 꼭지 사이를 넘나드는 판단이라
  한 꼭지만 본 담당은 세울 수 없다). 패널은 **상위·격차 행만** (`· 상위 N` / `· 행 'A'|'B'` —
  구간형·척도·보기 2~4개는 전 행).
  게이트: `verify.py <summary_map.json> <tables.json> --mode summary` · `… --mode conclusion`
- **`guide-summary-slide`(꼭지당 하나 · 병렬)** — 배정된 꼭지 **하나의 표만** 깊게 읽고, 그 표들이
  함께 무엇을 뜻하는지를 2~3줄로 쓴다(R-206). 한 담당이 전 꼭지를 몰아 쓰면 1위 값만 옮기게 된다.
  헤드라인 상한은 **렌더 한 줄 74자**이고 **수치를 넣어도 된다**(R-205 — R-130 폐기).
- **`guide-summary-reviewer`(장인 검토)** — 설계·문장·결론을 통째로 읽고 인사이트 가치·논리 사슬·
  설득력·규칙 준수를 심사한다. findings 만 — 수정은 총괄이.
- **`guide-client-review`(의뢰인 심사 · R-214)** — **통과 판정을 받을 때까지 고친다.**
  기계 게이트와 장인 검토가 못 보는 자리 하나 —「이걸 읽고 내가 무엇을 정할 수 있는가」다.
  여섯 물음: 결정 가능성 · 값어치 · 근거 체력 · 읽는 값 · 전수성 · 흐름.

### 설계의 두 걸음 — 무엇을 묶고, 어디가 갈리는가 (R-219·R-221 · 2026-09-01)

**① 묶음 기준** — 표를 한 꼭지로 묶는 조건은 셋뿐이다. ㉠ 같은 대상의 다른 면 ㉡ 전제와 결과
㉢ 같은 자를 댄 두 지점(갭). 셋 중 어디에도 안 걸리면 **묶지 않는다.** 기본값이 「묶지 않는 것」이다 —
코퍼스 요약 20장 중 14장이 문항 하나 = 장 하나다. 패널 여섯 초과·제목 3어절 초과는 쪼개라는 신호다.
기준이 없으면 설계가 설문지 순서를 그대로 따라가고 요약이 본문의 축약본이 된다.

**② 축 지도** — 본문 멘트는 판단의 재료가 아니라 **지도**다(멘트 283줄 중 역접 구문 1줄).
배너 줄(「~별로 보면 …」)을 전수로 긁어 **축 × 집단 × 문항** 지도를 `work/축지도.json` 에 만들고,
한 집단이 여러 문항에 걸쳐 반복해 튀는 자리를 찾는다. 거기서 가설이 서면 그 표만 열어 확인한다
(전수 스캔이 아니라 표적 검증). 교차분석은 R-220 의 조건을 만족할 때만 건다.
실측 결손: 본문이 38회 짚은 권역 축을 확정본 요약이 0회 썼다.

### ③ 배너 발굴 — 눈으로 훑지 말고 발굴기를 돌린다 (R-230 · 2026-09-01)

축 지도가 「어디를 볼지」를 준다면 이것은 「그 안에서 무엇이 발견인지」를 준다.

```bash
python engine/tools/banner_insight.py work/tables.json --summary-map work/summary_map.json --groups 용도 권역
```

세 갈래로 찾는다 — **순위 역전**(그 집단의 1위 보기가 전체와 다르다) · 큰 편차 · 단조.
역전이 가장 값어치 있다. 정도의 차이가 아니라 **선택이 다르다**는 뜻이라 요약 한 줄이 된다.
과장을 막는 다섯 빗장(저베이스 제외 · 작은 보기 무시 · %p 와 z 동시 · **역전이어도 1·2위
격차 10%p 미만이면 역전이라 안 부름** · 군당 하나, 단 역전은 전부)이 걸려 있다.
**후보만 낸다** — 올릴지는 설계자와 사람이 정한다.

### ④ 그래프는 그리기 전에 심사받는다 (R-224·R-225·R-227 · 2026-09-01)

`verify.py --mode summary` 의 **V20** 이 `guide/summary_chart_rules.yaml` 로 패널 설계를
심사한다(근거: 납품 최종본 5벌 요약 차트 358개 실측 = `guide/19`). 값 대조를 통과해도 여기서 걸린다.

| 코드 | 막는 것 |
|---|---|
| SC-001 | **평균을 독립 그래프로 그리는 것.** 평균은 `그래프 상단 Text` 로 얹는 지표다 |
| SC-002 | **최상위(「매우」) 단독 차트.** 하우스는 TOP2 를 쓰고 TOP1 을 쓰지 않는다 |
| SC-003 | 요약 패널에 배너 **표**를 다는 것 — 배너는 차트의 축으로 올린다 |
| SC-006·007 | 한 꼭지 패널 2~4개 · 같은 그림 3회 이상 반복 |

지시어는 짧게 적는다 — `배너 : 가로 누적 100% 막대 그래프`. 괄호 부연(`(행 = … 각 행 Base 100%)`)은
표가 이미 말하므로 붙이지 않는다(R-227). 요약·결론 블록에는 문항 회색 줄을 두지 않는다(R-226).

그 뒤 `guide-adversary` 가 산출 xlsm 을 반증하고 **사람이 확정**한다. 병합은 `python engine/tools/merge_part2.py <work>`
(summary_map + conclusion_map → `목차.md` 첫 펜스 Part Ⅱ 항목 · `### 요약 꼭지` · `### 결론 및 제언` — 손으로 쓰지 않는다).
**교차분석 패널(R-145, 사용자 지시 2026-08-24)** — 헤드라인이 집단 차이를 말하면 근거 패널은 배너 교차여야 한다. 지시어는 `배너 가로 누적 100% 막대 (군)`(단일 응답·보기 전수) / `배너 가로 묶음 막대 (군)`(중복·TOP2·행 선별) — 빌더가 홈로봇 형식으로 **전치**(행 = 집단, 행마다 Base, 열 = 보기)한다. 차트를 그릴 패널에 `배너 표` 를 쓰면 열이 100% 인 표를 행 방향으로 쌓아 PPT 가 틀어진다. 절단선 밖 군(연면적·소유 형태·입주사 수)도 요약에는 쓴다. 교차 후보 탐색 패킷: `python engine/tools/crosstab_digest.py work --out work/crosstab` 으로 만든 `work/crosstab/_index.json` + `표N.json`(tables.json 에서 만든 군별 display 요약 — 담당 정의가 이 경로를 읽는다). xlsm 게이트: `verify --mode guide` V17 이 요약 패널의 모든 수치·Base 를 근거 표에 대조한다.

**설계의 출발점은 조사 목적이다(R-141)** — guide-summary 는 RFP·킥오프·ToKnowList(00_협의)에서 목적 매핑표(항목 × 문항 × 표 × 꼭지)를 먼저 만들고 부재 항목을 메운다. Part Ⅲ 대분류(R-140)는 ToKnowList 의 의뢰인 구분을 그대로 쓴다.

1. 본문 헤더를 전수로 이어 읽고 To Know List 와 대조한다 — 표는 후보가 섰을 때 연다(R-201·R-221)
2. 인사이트 후보를 뽑는다 — **예상과 다른 것**이 값어치가 있다
   - 중요할 줄 알았는데 '보통' 100% → 버린다
   - 안 중요할 줄 알았는데 90% → 채택한다
   - **전반 평가 vs 개별 평가의 갭** → 제언이 여기서 나온다
3. 보통 **3개** (1~4개 유동적)
4. 사용자 확정을 받는다
5. 제작가이드에 블록으로 쓴다 — 표를 붙이고 `전체 원그래프 이쪽에`, `전체 가로 여기에` 식 **배치 지시 + 베이스 n**
6. **결론(제언) 슬라이드는 표 없이 텍스트만**

**주장을 쓰기 전에 세 번 묻는다** (실측 사고: 「의사결정자가 개인 1인」 — 3단 비약)
① 그 주장을 지지할 **문항이 설문에 존재하는가** ② 근거 **셀 좌표**는 어디인가
③ 같은 정본 안에 **반대 증거**가 없는가. 하나라도 막히면 주장을 낮추거나 버린다.

**요약 패널 주제명은 측정을 왜곡하지 않는다** — 역할을 말하되(R-131),
한정구를 떨구지 말고(「무엇이 중요한가」✗ → 실제는 '관리 업무 중' 중요도),
표본 단위를 바꾸지 말라(「한 사람이 가진…」✗ — 표본 단위가 건물이면 건물로).
요약 헤드라인은 판단문이고 상한은 **렌더 한 줄 74자**이며 수치를 넣어도 된다 (R-205 — R-130 폐기).

## Step 5 — 출력 + 검증

```bash
python engine/tools/build_guide.py <work/slide_facts.json> <out/{조사}_제작가이드_YYMMDD.xlsm>        --toc <work/목차.md> --tables <work/tables.json> --questionnaire <work/questionnaire.json>        --overview <work/조사개요.json> --logo <00_협의/{클라이언트}로고.png>        --title "<조사명>" --date "<제출일>" --cover "C19=<클라이언트 챠트색>" --dash-empty
python engine/tools/verify.py      <out/…xlsm> <work/tables.json>        --facts <work/slide_facts.json> --questionnaire <work/questionnaire.json> --toc <work/목차.md>
```

⚠ **`--toc` 없이 만들면 구조 블록 22개(표지·목차·간지·조사개요·요약·결론)가 통째로 빠진다.**
본문 70장만 나오고도 검사는 전부 통과한다 — 검사는 블록 *안*을 보기 때문이다 (R-119).
⚠ **`--logo` 없이 만들면 Cover 에 예시사(LG전자) 로고가 그대로 남는다.**

**Cover 도 작성 대상이다.** 템플릿은 범용이라 프로젝트 값은 `--cover CELL=값` 으로 준다:
- `C4` 제목 · `C6` 제출일은 `--title`/`--date` 가 채운다 (R-127)
- `C19` 챠트 색상 — 클라이언트 브랜드색이 확정돼 있으면 선언한다
  (예: `"C19=에스원 Blue(#0033A0 · PANTONE 286C)"`). 미확정이면 중립 기본값 유지 + 연구원 확인 목록에
- `C14/C15` 테마글꼴 — 클라이언트 서체 규정이 공개돼 있지 않으면 맑은 고딕/Arial 유지
- 배너 너비·배너 분리·사례수 다중은 **LG 예시도 공란** — 제작팀 재량이므로 비워 둔다
- Cover 의 「검수 실행」 버튼이 보이는지 확인한다 — 빌드 복원 ①-b 가 지키지만,
  템플릿을 갈아엎었다면 drawing1 의 버튼 도형(a14 AlternateContent)이 살아 있는지 본다

`build_guide.py` 가 하는 일:
- `engine/templates/TEMPLATE_제작가이드.xlsm` 복제 (숨은 검증 시트 9종 + VBA 보존)
- `목차(보고서용)`, `part 3 목차(연구부 확인용)`, `본문` 채움
  · 연구부 확인용 시트는 **본문 한 장 = 한 행**이다. 문항을 묶지 않는다 — 이 시트의 쓰임이
    누락 검출이라 묶으면 빠진 문항이 묶음 안에 숨는다. 열: 챕터 / 서브 타이틀 / 문항 / **표** / 구성 및 BASE / P
- Cover 로고 교체 (`--logo`) — **가로세로비 유지**. CI 규정이 「비례 임의 변경」을 금한다
- `dimension` 선언을 실제 범위에 맞춤 — 빼먹으면 Excel 이 "내용에 문제가 있습니다" 를 띄운다
- 빈 셀은 **`-` 로 채운다** (`--dash-empty`, R-192). 플래그는 조사마다 `build.sh` 에 고정한다 — 손으로 다시 조립하다 잃는 사고가 실재했다(R-218). LG 송부본에 `-` 가 0개였던 것은 그 조사의 선택이지 기본값이 아니다
- **`out/.baseline/` 에 스냅샷** ← 학습 루프의 기준선. 사람이 이후 손으로 고치면 그 diff가 곧 학습 데이터
- `_` 접두 시트를 제거하고 수식을 평탄화한 **`_제작팀송부본`** 생성

`verify.py` 가 검사하는 것:
- **멘트의 모든 수치가 통계표 원본과 1:1 일치하는가** ← 환각 0 보장. 하나라도 틀리면 실패
- 슬라이드 수 = 목차 항목 수
- 베이스 정합
- `rules.yaml` 의 기계 판독 규칙
- **V16 문서 위생**(R-137) — 문서 속성의 개인 이름·템플릿 잔재, 본문의 보이지 않는 문자·이형 공백. `build_guide` 가 끝에서
  자동 정리하므로 경고가 남으면 빌드 바깥에서 손댄 파일이다 → `doc_hygiene.py clean --inplace`

**첫 5장을 먼저 보내 포맷 승인을 받은 뒤** 전량 진행할 것을 권한다.

**검증 5로** (`guide/17` §구성) — 기계 검사만으로 끝내지 않는다:
- 설계 산출물(목차·배너 설계·검사 사양)은 확정 전에 **guide-judge** 에이전트로 심사한다
  — 전제부터 심사한다 (실증: 폐기된 "14열 상한" 전제 적발)
- 제출 전·대변경 후에는 **guide-adversary** 에이전트로 산출 xlsm 을 반증한다
  — 좌표·라벨·부재·주장 4렌즈 (실증: MUTANT2 값 맞바꿈 · `998)` 잔존 검출)
- 두 에이전트에게 **제작 경위를 주지 않는다.** findings 만 받고 수정은 이쪽에서 한다

## 지켜야 할 것

- **AI는 숫자를 읽지 않는다.** 룰엔진이 팩트를 만들고 AI는 문장만 쓴다
- **차트타입은 자유 서술이다.** 제작팀이 사람 눈으로 읽으므로 띄어쓰기가 제각각이어도 되지만, `그래프 상단 Text` 같은 **신호어는 정확히** 써야 한다 (안 쓰면 그 값이 그래프에 안 나온다)
- **소수점** — % 는 1자리(`.0`도 유지), 평균·NPS는 2자리
- 규칙을 어겨야 할 상황이면 **왜 그런지 사용자에게 말하고** 판단을 받는다. 조용히 넘어가지 않는다
