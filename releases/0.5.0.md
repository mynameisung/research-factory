# research-factory 0.5.0 — 2026-09-18

이름이 **research-factory** 로 바뀌었고, 업무 흐름 ③ 설문지 구성을 `/설문지작성` 이 맡는다. 업그레이드한 뒤 **Claude 세션을 한 번 닫고 새로 연다.**

## 달라진 점

- **이름 변경** — 저장소는 `mynameisung/research-factory`, 안쪽 폴더는 `report-factory/` → `research-factory/`. 옛 주소로 받은 설치도 `/업그레이드` 한 번이면 된다. git 밖에 있던 조사 데이터(`projects/`)·코퍼스·인수인계 문서는 업그레이드 뒤 첫 스킬 시작 때 저절로 새 폴더로 옮겨지고, 옛 경로도 연결로 그대로 쓸 수 있다.
- **`/설문지작성` 신설** — 구조화 엑셀을 엠브레인 양식 설문지(.docx)로 바꾼다. 아래 기능 설명 참고.
- **설문지 파서 보강(/웹테스트·/제작가이드 공통)** — 표 안에만 있는 보기, 0·1 에서 시작하는 숫자 척도, `[최소 N개, 최대 M개 선택]` 을 읽는다. 로컬 설문지 7벌에서 척도 45문항·표 보기 2문항·복수 선택 24문항이 바로잡혔다. 이 문항들은 웹테스트 시나리오와 보기 대조 결과가 전과 달라진다.
- **`/개선공유` 가 PR 까지 확실히 올린다** — push 전에 gh 설치·로그인·쓰기 권한을 확인한다. gh 가 없는 PC 에서 브랜치만 올라가고 PR 이 안 생기던 문제다.
- 그 밖에 — setup 스모크에 설문지 자체 시험, 옛 배치(v1) 조사에서 통계표 자리에 구조화 엑셀이 잡히던 문제, `update_check` 하위 명령이 `--help` 를 판 이름으로 받던 문제, `build_facts --help` 오류.

## 새로 써볼 수 있는 것

- **`/설문지작성 <구조화.xlsx>`** — 구조화 파일(TKL 을 받았으면 그것까지)을 주면 설문명세 → .docx → 검수 → 반증 검토까지 간다. 결과는 조사 폴더의 `03_설문지/` 에 남는다.
- **`/웹테스트`** 를 표 보기·숫자 척도가 많은 설문지에 다시 돌려 보면 전에 놓치던 보기 대조가 잡힌다.

## 기능 설명

### /설문지작성 — 구조화 엑셀 → 엠브레인 양식 설문지

- **무엇을 하나** — 구조화·TKL·참고 시트를 읽어 문항 문장·보기·척도·BASE/PROG/RANGE·파이핑을 하우스 규칙대로 정한 설문명세(JSON)를 쓰고, 도구가 서식만 입혀 .docx 를 만든다.
- **언제 쓰나** — 기획팀·클라이언트에게서 구조화 파일을 받은 직후. "구조화 설문지로 바꿔줘", "설문지 만들어줘" 라고 하거나 구조화 .xlsx 를 주면 된다.
- **어떻게 검수하나** — `check_questionnaire` 가 Q-01~16(구조화 누락·BASE/파이핑 참조·코드 범위·파서 왕복)을 보고, `questionnaire-adversary` 가 빠진 문항·틀린 분기·겹질문·MECE 깨진 보기·척도 불균형을 반증 시도한다.
- **결과는 어디에** — `03_설문지/` 에 펼침본·설문명세·설문지 .docx·검수 결과. 옛 배치(v1) 조사도 같은 역할로 풀리므로 폴더를 옮기지 않아도 된다.

### 폴더 이름 변경 뒷정리 — migrate_folder

- 업그레이드 뒤 첫 입력이나 스킬 시작 때 저절로 돈다. 「옮김」이면 끝. 「열린 파일 때문에 못 옮김」이면 엑셀 등을 닫고 다시 스킬을 부른다.
- 옛 폴더 `report-factory/` 에 남는 연결(정션)과 대리 파일은 지우지 않는다. 옛 절대경로가 박힌 조사 스크립트가 그대로 돌게 하는 장치다.

## 주의할 점

- 업그레이드한 뒤 Claude 세션을 한 번 닫고 새로 연다. 훅과 스킬이 새 폴더 경로로 붙는다.
- 업그레이드 때 `report-factory/engine/tools/` 의 대리 파일에서 충돌이 나면 병합하지 않는다. 대리 파일을 되돌리고 로컬 수정은 `research-factory/engine/tools/` 의 같은 파일에 다시 적용한다(`/업그레이드` 가 대신 한다).
