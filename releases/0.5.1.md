# research-factory 0.5.1 — 2026-09-22

업그레이드가 끝나면 **업데이트 내역 링크**가 뜬다. 누르면 무엇이 달라졌고, 무엇을 새로 써볼 수 있고, 그 기능이 무엇인지 한 장으로 읽는다.

## 달라진 점

- **업데이트 내역 링크** — 「올릴까요?」 물음과 업그레이드 완료 줄에 그 판의 GitHub Release 링크가 함께 뜬다. 여러 판을 한 번에 건너뛰었으면 중간 판의 링크도 같이 준다.
- **판마다 한 장 `releases/<판>.md`** — CHANGELOG 의 한 줄 요약과 별도로, 연구원 언어로 「달라진 점 · 새로 써볼 수 있는 것 · 기능 설명 · 주의할 점」을 적는다. 같은 내용이 GitHub Release 페이지에 올라간다.
- **판 올릴 때 노트가 빠지면 잡는다** — setup 스모크와 `/개선공유` 선행 확인에 `release_notes.py check` 가 들어갔다. 관리자가 VERSION 을 올리면서 노트를 안 쓰면 설치 단계에서 걸린다.

## 새로 써볼 수 있는 것

- 스킬을 부를 때 새 판 안내에 링크가 붙는다. 링크를 눌러 읽고 「지금 올린다」를 고르면 된다.
- 지금 판의 내역을 다시 보고 싶으면:

```bash
python research-factory/engine/tools/release_notes.py show
```

- 링크만 다시 받으려면 `release_notes.py url`. 아직 안 받은 판의 내역은 `release_notes.py show <판> --remote`.

## 기능 설명

### 업데이트 내역 — release_notes.py

- **무엇을 하나** — `releases/<판>.md` 한 장을 GitHub Release(태그 `v<판>`) 로 올리고, 그 링크를 만든다. 프리앰블(`preamble.py`)이 `RELEASE_NOTES:` 줄로 링크를 주고, `/업그레이드` 는 보고 끝에 링크를 붙인다.
- **언제 보나** — 스킬 시작 때 「research-factory 0.5.1 이 나왔습니다 … 올릴까요?」 아래, 그리고 `/업그레이드` 가 끝난 뒤 「0.5.1 로 올라왔습니다 … 업데이트 내역: <링크>」.
- **관리자만** — `release_notes.py new <판>` 으로 틀을 만들고 채운 뒤 `check`, 병합·push 뒤 `publish`. 노트의 절 이름은 고정이다(check 가 본다).
- **부명령** — `url [<판>] [--from <이전판>]` · `show [<판>] [--remote]` · `check [<판>]` · `new <판>` · `publish [<판>] [--target <커밋>]`.

## 주의할 점

- 링크는 비공개 리포의 페이지라 GitHub 로그인이 필요하다. 초대받은 계정으로 로그인돼 있으면 바로 열린다.
- 0.5.0 이전 판은 GitHub Release 가 없고 `CHANGELOG.md` 에만 있다.
