# 02. 프로젝트 메모리 — 조사마다 따로 기억한다

연구원마다 맡는 조사가 다르고, 한 조사도 여러 세션에 걸쳐 진행된다. 그래서 기억은 리포 전체가 아니라
**조사 폴더 안**에 쌓는다. 리포 전체에 남기는 것은 규칙(`engine/learning/RULES.md`)뿐이고, 그것도
`/회고` 가 사람 승인을 받아 올린다.

## 어디에 무엇이 쌓이나

```
report-factory/projects/<프로젝트>/<조사>/_memory/
├─ MEMORY.md         정리본. 스킬이 시작할 때 읽고 끝날 때 갱신한다 (결정된 것 · 지시의 요지 · 다음 세션이 알아야 할 것)
├─ 사용자입력.jsonl   원문. 이 폴더에서 사용자가 입력한 지시 전부 (UserPromptSubmit 훅, capture_prompt.py)
├─ 편집기록.jsonl     원문. 사람이 산출물을 손으로 고친 이력 (PostToolUse 훅, capture_edit.py)
└─ 스킬실행.jsonl     어느 스킬을 언제 어떤 인자로 불렀나 (스킬 PREAMBLE 의 preamble.py 가 기록)
```

`projects/` 는 git 이 추적하지 않으므로 이 기록은 **그 PC 에만** 남는다. 고객 조사의 맥락이 리포로 새지 않는다.

## 활성 조사

훅은 어느 조사에 기록할지를 `report-factory/projects/.active`(한 줄, 조사 상대 경로)로 안다.
스킬이 조사 폴더 인자를 받으면 첫 단계에서 다음을 실행해 적어 둔다.

```bash
python report-factory/engine/tools/capture_prompt.py set-active <프로젝트>/<조사>
```

활성 조사가 없으면 `projects/_공통/_memory/` 에 쌓인다. 조사를 옮길 때 `set-active` 를 다시 하면 된다.

## 스킬이 지키는 것

1. **시작할 때** `_memory/MEMORY.md` 를 읽는다. 「결정된 것」은 다시 묻지 않는다.
2. **끝날 때** `MEMORY.md` 의 세 절을 갱신한다. 원문(`사용자입력.jsonl`)을 베끼지 않고 요지만 적는다.
3. `/회고` 는 `사용자입력.jsonl` 과 `편집기록.jsonl` 을 ★★★ 관찰 소스로 읽는다. 전에는 「대화에서 직접 지적한 것은
   파일에 안 남으니 반드시 물어서 받는다」였는데, 이제 훅이 남긴다.

## 리포 전체 기억과의 경계

| 무엇 | 어디 | 누가 올리나 |
|---|---|---|
| 이 조사에서 정한 것·남은 일 | `projects/<조사>/_memory/MEMORY.md` | 스킬 (자동) |
| 이 조사의 사용자 지시 원문 | `projects/<조사>/_memory/사용자입력.jsonl` | 훅 (자동) |
| 여러 조사에 두루 맞는 규칙 | `engine/learning/RULES.md` → `packs/` | `/회고` (사람 승인) |
| 도구·절차 개선 | `engine/tools`·`.claude/skills` | `/개선공유` PR (관리자 병합) |
