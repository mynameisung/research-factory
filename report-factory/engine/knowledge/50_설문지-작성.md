# 50 설문지 작성 — 구조화 엑셀 → 엠브레인 양식 설문지

업무 흐름 ③(설문지 구성). `/설문지작성` 이 읽는 지식이다. 근거는 연구원이 직접 만든 **구조화 → 설문지 3쌍**
(공공 성과조사 · 공공 만족도 조사 · B2B 시장 실태조사, 2025~2026)과 **설문지 로직 구성 예시 3벌**(B2B 리스트 조사 · 계약서 수집 · 비상주 서비스 수용도)이다.
원본은 고객 자료라 리포에 두지 않는다. 아래 규칙은 그 여섯 벌에 공통으로 나타난 것만 적었다.

```
TKL(있을 때만) ─▶ 구조화 엑셀 ─▶ 설문명세.json ─▶ 설문지 .docx ─▶ (온라인실사팀 구축) ─▶ /웹테스트
                  read_structure    Claude 작성       build_questionnaire
                                    check_questionnaire (구조화 대비 누락·로직·왕복)
```

## 1. 구조화 파일을 읽는 법

구조화는 조사마다 열이 다르다. `read_structure.py` 가 머리 행을 찾아 역할을 붙인다.

| 역할 | 흔한 머리말 | 설문지에서 쓰는 곳 |
|---|---|---|
| part | 대분류 · 파트 · PART | 파트 머리(검정 띠). `Part 2. 성과 지표` → `PART A. 성과 지표` 처럼 **영문 한 글자 코드**로 바꾼다 |
| section / attribute | 중분류(차원) · 주제 · 질문 / 소분류(속성) | 문항이 **무엇을 재는가**. 문장이 없으면 이걸로 문장을 짓는다 |
| code | 문번 | 문항번호의 출발점 (3절) |
| question | 문항 · Details | 문항 문장 초안. 구어·메모체면 하우스 문형으로 다듬는다 |
| options | 보기 | 보기 원안. `주관식` · `[대분류 기준 업종 제시]` 같은 지시도 들어온다 |
| format | 구성 · 응답 조건 · 응답유형 | 응답유형 (2절 표) |
| logic / base | 응답 로직 · 응답대상 · BASE | `[BASE:]` · `[PROG:]` 재료 |
| note | 비고 · 출처 · RFP 상 내용 · 구분 | 설문지에 옮기지 않는다. 판단 근거로만 읽는다 (예: `아웃 조건(4번 선택 시)` · `쿼터` · `출처: 설문2차`) |

반드시 같이 읽을 것
- **참고 시트** — 구조화 파일 안의 다른 시트(고객 메일 본문 · 이전 버전 · 설문지 초안 · To-know list · 응답보기). 고객의 추가 요청과
  **보기 초안이 여기 있는 경우가 많다**(만족도 조사: 구조화에는 `1개 선택` 만 있고 보기는 `ver4` · `설문지 초안` 시트에 있었다).
- **곁표** — 본표 오른쪽의 별도 표(예: 대륙별 국가 보기). `read_structure` 가 「곁표」로 따로 뽑는다.
- **안내 띠** — 여러 열을 가로지르는 병합 행(`[연도별 측정 - 23~25년]`). 그 아래 문항 전체에 걸리는 조건이다.
- **셀 색** — 노랑은 대개 핵심 지표(전반 만족도·문번 강조), 빨강은 삭제·보류 표시였다(실태조사: 빨간 행 = 「해당 문항 제외」).
  뜻이 비고에 없으면 **사람에게 묻는다.**
- **집계 시트** — `파트 | 문항 수` 같은 요약 시트는 문항이 아니다. `read_structure` 가 참고 시트로 둔다. 파트 구성 확인에만 쓴다.
- **열 밖 메모 · 역할 미상 열** — 행 끝의 코멘트(「"취업"은 애매 → 산단 근무 자체를 추천하냐로 바꾸기」)나 `구분` 같은 역할 미상 열의
  「개선점으로 변경」은 고객·연구원의 **수정 지시**다. 반영하고, 반영했다고 `meta.notes` 에 적는다.
- **본표 아래 메모** — 빈 행 뒤에 번호·파트 없이 붙은 줄(대안 문구 모음). 쓰면 그 문항 `src` 에, 안 쓰면 `skipped_src` 에 넣는다.
- **빈 칸** — 구성(응답형태)이나 응답대상이 빈 행은 같은 중분류 이웃 행의 패턴(예: 「속성 만족도 → 불만족 시 개선점」)을 따르고 `review` 를 단다.

정본이 여럿일 때: **본표는 뼈대**(무엇을 · 누구에게 · 어느 순서로), **응답 형식과 보기의 세부는 가장 구체적이고 최신인 곳**을 따른다.
본표의 구성 칸(`1개 선택`)은 자리표시인 경우가 많다. 고객 수정본·설문지 초안 시트가 같은 문항을 더 구체적으로 적었으면
(「개선이 필요한 부분을 **순서대로 최대 3곳**」 · 보기 목록) 그쪽을 따르고 `review` 에 출처 시트를 적는다
(만족도 조사 사례: 본표는 개선점 문항이 모두 `1개 선택` 이었으나 고객 수정본 `ver4` 의 「순서대로 3곳」대로 순위형이 됐다).
참고 시트끼리 다르면 최신(시트 이름의 버전·날짜가 큰 것, 고객 메일 본문의 요청)을 쓰고 다른 쪽을 메모에 남긴다.
본표보다 **오래된** 참고 시트(TKL 번호 체계·보기 시트가 본표와 어긋남)는 배경으로만 읽고 문항·보기의 근거로 쓰지 않는다.

TKL(To-Know-List)이 있으면 `00_협의/` 에서 읽고, 구조화 행마다 어느 TKL 항목에 답하는지 본다. TKL 항목이 어떤 문항에도 닿지 않으면
보고한다(추가 여부는 사람이 정한다). TKL 이 없는 조사가 더 많다 — 없으면 구조화가 유일한 정본이다.

## 2. 구조화 표현 → 설문 표기

| 구조화에 적힌 것 | kind | 설문지 표기 |
|---|---|---|
| `1개 선택` · 단일 · 보기만 있음 | single | `[1개 선택]` |
| `모두 선택` · 복수 · 해당 항목 모두 | multi | `[모두 선택]` |
| `최대 3개` (순서 없음) | multi + max | `[최소 1개, 최대 3개 선택]` |
| `1순위 필수, 3순위 선택` · `2순위 선택` · `3순위까지` · `순서대로 N곳` | rank | `[1순위 필수, 3순위 선택]` · `[1순위 필수, 2순위 선택]` · 모두 필수면 `[3순위 필수]` |
| 개선점 · 개선 필요 · 개선 시급 (불만족 후속) | rank | 「개선이 필요한 부분을 순서대로 N곳」 + `[1순위 필수, N순위 선택]` — 만족도 조사의 개선 문항은 모두 순위형이었다 |
| `중요한 순서대로 최대 N개` (목적 · 고려 요인) | rank 또는 multi+max | 순위가 기본. 분석에 순서가 필요 없으면 `[최소 1개, 최대 N개 선택]`(실태조사 사례). 어느 쪽인지 `review` 로 묻는다 |
| `5점 척도 (만족도)` · 만족도 · 기여도 · 의향 | scale | 가로 2행 표 + `[1개 선택]` (3절 프리셋) |
| `… + 6) 모름` · `6) 해당없음` | scale.extra | 척도 표 오른쪽 칸 `모름` |
| 여러 속성을 같은 척도로 | matrix | 행렬 표 + `[행별 1개 선택]` |
| `주관식` · `OPEN` · `직접 기입` | open | 빈 1칸 표 + `[직접 입력]` + 필요하면 `[PROG: 필수 입력 해제]` |
| `직접 기입(수치형)` · 금액 · 인원 · 연도 | number | `(          ) 단위` + `[RANGE:]` + `[직접 입력]` |
| `[#연도별]` · 연도마다 같은 질문 | number/open + columns | 연도 머리 2행 표 |
| `여부` · 예/아니오 | yesno | `1) 예  2) 아니오` 한 줄 |
| `자동 선택` · 리스트 정보 | — | `[PROG: 리스트에 따라 자동선택]` |
| `LIST` · 리스트 조사 (값을 보여 주기) | — | `[# LIST 파이핑 #]` |
| `LIST` 에서 고르기 · 드롭다운 · 지도 선택 | list | `[1개 선택]` + `[PROG: LIST Drop Down 형태로 제시]` · `[PROG: 지도 2단계 선택]` (보기는 없어도 된다) |
| 구성·응답대상 칸이 비어 있음 | 이웃 행 패턴 | 같은 중분류 이웃 행을 따르고 `review` |
| `~ 조사 종료` · `아웃 조건(n번 선택 시)` | option.terminate | 보기 뒤 빨간 `→ 조사 중단` · 입력형이면 `[PROG: … 조사 종료]` |
| `아웃 조건(중복 시)` | — | `[PROG: 사업자등록번호 기준 중복체크 필요]` |
| `쿼터` | quota | 번호 뒤 빨간 `[쿼터]` · 표지 쿼터 표 |
| 응답대상 `all` | — | BASE 없음 |
| 응답대상 `B2=1~3` · `B1=1~5, 7` | base | `[BASE: B2=1~3 | 사람말 설명]` |
| `~ 불만족` · `불만족 시` | base | `[BASE: X=1~3 | 보통 이하]` — **보통 포함이 하우스 관행** (만족도 조사 · 실태조사 · 서비스 수용도 예시가 모두 1~3) |
| `~ 만족 시` | base | `[BASE: X=4~5 | 만족]` |
| `이용경험자 대상` · `거주자 대상` | base | 경험·거주를 묻는 SQ 문항을 찾아 `[BASE: SQ5=2]` — 후보가 여럿이면 **그 조건을 직접 묻는 여부 문항**(거주 여부)을 복수 선택 문항의 보기(이용 시설 중 주거)보다 먼저 쓴다. **SQ 에 그 문항이 없으면 만든다** |
| `상품별 보기 구분` · `n번 응답자만 m번 보기 제시` | prog | `[PROG: B3=1~3 응답자만 4, 5번 보기 제시]`. 「구분」만 있고 어느 보기인지 없으면 같은 문항의 다른 상품 파트 비고를 따르고 `review` |
| 개수 표시가 없는 선택 문항 (이유 · 경로 · 목적) | single | 기본 `[1개 선택]`(가장 주된 것) + `review`. 문장에 「모두」·「순서대로」가 있으면 그에 따른다 |
| 순위 문항의 특정 순위 조건 | base | `[BASE: G3 1순위=1~3]` |
| 파이핑 대상이 응답자마다 다름 | text | `[#B1# or #G2#]` + `[PROG: B1=1~5, 7 응답자는 B1 보기 파이핑 / B1=6 응답자는 G2 보기 파이핑]` |
| `연도별 제외` | — | 연도 표 없이 한 번만 묻는다 |

## 3. 설문지 하우스 규칙

### 3-1 번호와 파트
- 순서는 **SQ → PART A, B, C … → DQ → (ED)**. 파트 머리는 `SQ. Screening Question` · `PART A. 제목` · `DQ. Demographic Question`
  (공공 조사는 `DQ. 응답자 특성` · `DQ. 배경 질문` 도 쓴다).
- 번호는 `파트코드 + 숫자` — `SQ1` · `A1` · 딸린 문항 `A1-1` · 그 아래 `A1-1-1`. **파트 코드와 접두가 같아야** `parse_questionnaire` 가 읽는다.
  구조화의 `Part 2` 는 `PART A` 로, 구조화 문번 `A1` 이 새 파트 체계와 맞지 않으면 번호를 새로 매기고 명세의 `src` 로 원래 행을 잇는다.
- 구조화 문번이 있으면 **가능한 한 유지**한다. 순서를 바꾸거나 문항을 넣고 빼면 다시 매기고, 바꾼 번호를 변환 메모에 적는다.
  다시 매기면 비고·응답대상·PROG 안의 옛 번호(`B3_무인경비 브랜드`)도 **새 번호로 모두 고쳐 쓴다**.
  (실태조사 사례: 공통 파트에서 상품 3개의 브랜드를 한꺼번에 묻던 구조화 `B3` 를, 설문지에서는 상품별 파트 첫 문항 `C1` · `D1` · `E1` 로 옮겼다.
  같은 공통 문항이라도 상품별로 답이 갈리는 것만 옮기는 판단이다 — 옮길지 애매하면 공통 파트에 두고 `review`.)
- 한 개념을 서비스·상품별로 반복하는 파트(서비스별 이용행태)는 파트를 나눠 같은 문항 틀을 되풀이하고, 파트 머리 아래
  `[PROG: Part C는 B2=1 응답자만 진행 | 설명]` 을 둔다.
- 흐름: 스크리닝(자격·쿼터·중단) → 인지 → 이용 현황 → 평가(속성 → 전반) → 불만·개선 → 향후 의향 → 응답자 특성.
  **전반 만족도는 속성 만족도 뒤**, 개선 우선순위는 전반 만족도 뒤에 둔다(만족도 조사).

### 3-2 문항 문장
- 합쇼체 의문문. 주어는 응답자 성격대로 **귀하(께서는)** · **귀사** · **귀 건물** — 한 설문에서 섞지 않는다.
- 끝은 `…입니까?` / `…하십니까?` 뒤에 한 칸 띄고 응답 표기. 지시가 필요하면 문장 안에 넣는다:
  `모두 선택해 주십시오.` · `중요한 순서대로 최대 3개까지 선택해 주십시오.` · `여러 브랜드를 이용하시는 경우 가장 사용금액이 높은 브랜드를 기준으로 응답해주세요.`
- 기준 시점·범위를 문장에 박는다(`2024년 12월말 기준으로` · `임시근로자, 일용직 등 모두 포함하여`). 구조화에 있으면 빼지 않는다.
- 핵심어는 **굵게**, 대비가 중요한 말은 __밑줄__ (`**가장**` · `__턴키 계약방식__`). 남발하지 않는다 — 문항당 1~2곳.
- 부연은 줄을 바꿔 `* …` 또는 `※ …`. 긴 정의(「물리보안이란」 · 컨셉 설명)는 **안내 박스**(`kind: info`)로 문항 앞에 두고
  `[PROG: 안내문 별도 페이지 제시]`.
- 한 문항에 한 가지만 묻는다(겹질문 금지). 유도어(「불편한 점을 말씀해 주세요」 앞에 평가 없이) 금지 — 불만 후속은 BASE 로 거른다.
- 앞 응답을 문장에 넣을 때는 파이핑 `[#A2 응답값#]` (리스트 값은 `[# LIST 파이핑 #]`). 파이핑 대상은 **앞 문항**이어야 한다.

### 3-3 보기
- `1) …` 번호. 기본은 한 줄에 하나. 짧은 보기(성별·예/아니오·혼인)는 한 줄에 2~4개(`cols`).
- **기타(      )** 는 끝. 그 뒤에 올 수 있는 것은 `없음` · `모름` · `이용 경험 없음` 같은 배타 보기뿐.
- 복수 선택의 `없음`류는 `exclusive: true` → `[PROG: n) 복수 선택 불가]` 가 붙는다.
- 명목형 보기 5개 이상은 **로테이션을 정한다**(`rotation: true` → `[PROG: 기타 제외 보기 Rotation]`). 순서가 의미 있는 보기
  (구간·빈도·학력·소득)는 `ordinal: true` 로 고정한다.
- 구간 보기는 겹치지 않게 `200~300만원 미만` 꼴, 끝은 `… 이상`. 경계값이 비지 않게 한다.
- 보기 설명은 콜론 뒤에: `1) 무인경비(출동경비) : 문열림/움직임 감지기 등을 …`.
- 만족 이유 · 불만족 이유처럼 **짝 문항의 보기는 1:1 대칭**으로 쓴다(「가격이 저렴해서 ↔ 가격이 비싸서」).
- 같은 보기 목록을 여러 문항이 쓰면 문구를 한 글자도 바꾸지 않는다(교차 분석 코드가 어긋난다).
- 보기를 구조화에 없이 **새로 지었으면** 그 문항에 `review` 를 단다(노란 번호).

### 3-4 척도
- **5점, 1 = 「전혀 …않다」 → 5 = 「매우 …하다」** 오름차순 — 만족·의향처럼 긍정 개념이면 1 = 부정 → 5 = 긍정이다.
  불안·불편처럼 **부정 개념**을 재는 척도도 같은 틀(1 = 전혀 불안하지 않다 → 5 = 매우 불안하다)로 두고, 그 척도를 쓰는 BASE 를 거기에 맞춘다(「불안한 응답자」 = 4~5). 구조화가 `1) 매우 만족 … 5) 전혀` 순이어도 설문지에서는 뒤집는다(실태조사: 구조화는 내림차순, 설문지는 오름차순).
- 라벨은 프리셋(`만족` · `동의` · `중요` · `추천` · `이용의향` · `구매의향` · `지속이용` · `기여` · `도움` · `이해` · `신뢰` · `매력` · `필요` · `인지`)을 쓰고,
  없으면 `labels` 로 직접 준다. 가운데는 `보통이다`.
- `모름` · `해당없음` 은 척도 밖 6번 칸(`scale.extra`). 전반 평가에서 `모름` 을 허용할지는 사람에게 확인한다.
- 여러 속성을 같은 척도로 물으면 행렬(`kind: matrix`). 행 순서 로테이션은 `[PROG: 행 Rotation]`.

### 3-5 로직 표기 (로직 구성 예시에서)
파란 글씨. `[BASE:]` 는 문항 **위**, `[PROG:]` · `[RANGE:]` 는 보기 **아래**.

| 표기 | 예 |
|---|---|
| BASE | `[BASE: A3=1 | 기업소유]` · `[BASE: B2=3,4 | 외부 위탁]` · `[BASE: C11=1~3 | 만족하지 않는 응답자]` · `[BASE: (B1-1 1)≠0) & (B1-1 3)≠0) | 오피스 입주 건물]` · `[BASE: SQ9 = 1 or 2]` · `[BASE: C1 ≥ 1개 이상 (없음 제외)]` |
| 조사 중단 | 보기 뒤 `→ 조사 중단` · `[PROG: 2002년생 이하 또는 1966년생 이상 조사 종료]` · `[PROG: 1), 2) 중 하나라도 미선택 시 조사 종료]` |
| 보기 제시 | `[PROG: B1-1 응답보기만 제시]` · `[PROG: B3 미응답 보기만 노출]` · `[PROG: A4의 인지 브랜드만 제시]` · `[PROG: SQ1 응답에 따라 해당 대분류만 제시 / 기타는 항상 제시]` |
| 배타·로테이션 | `[PROG: 7) 이용경험없음 복수 선택 불가]` · `[PROG: 기타 제외 보기 Rotation]` · `[PROG: 6-7 제외 보기 로테이션]` · `[PROG: 중분류 로테이션]` |
| 자동 처리 | `[PROG: SQ4 = 1)일 경우, SQ5=2) 자동 선택]` · `[PROG: … SQ9-4 = 1) 자동 선택 후 SKIP]` · `[PROG: A3=0인 경우 7번 자동선택]` |
| 반복 | `[PROG: A3~A3-1, A2 개수(자체 관리 제외)만큼 로테이션]` · `[PROG: SQ9에서 선택한 1) 부엌, 2) 욕실 보기별로 Rotation 하여 질문]` · `[PROG: 이후 연도별에 대한 부분은 A1 응답연도 ~ 2025년까지 질문]` |
| 입력 검증 | `[RANGE: 1 ~ 300]` · `[PROG: MIN: 1 / MAX: SQ2(연령) - 19]` · `[PROG: 합계 ≤ B1 응답값]` · `[PROG: (종료일자 – 시작일자) >= 2개월]` · `[PROG: 연도별 A5 >= A5-1]` · `[PROG: 2글자 이상]` |
| 입력 형태 | `[PROG: 숫자로 기입, 한글 표기 노출]` · `[PROG: 금액 한글로 표시]` · `[PROG: 지도 2단계로 제시; 시도 > 시군구]` · `[PROG: LIST Drop Down 형태로 제시]` · `[PROG: 사진 첨부 최대 5장까지 가능]` · `[PROG: 필수 입력 해제]` |
| 화면 | `[PROG: 안내문 별도 페이지 제시]` · `[PROG: 안내문 한 페이지로 노출, 5초간 노출]` · `[PROG: Part A 상단 계속 노출]` · `[PROG: 별도 페이지로 제시]` |
| 파이핑 | `[#A2 응답값#]` · `[# LIST 파이핑 #]` · `[# LIST 파이핑(수정 가능) #]` · `[#SQ9 응답값 병렬 제시#]` · `[# C1 응답 업무별 노출 #]` |
| 쿼터 | 번호 뒤 빨간 `[쿼터]`, 표지 `■ 조사 쿼터` 표, 필요하면 `[PROG: 시/군/구 단위까지 선택, 쿼터는 시/도 기준으로 설정]` |

BASE 조건은 **코드로** 쓰고 `|` 뒤에 사람말을 붙인다. 코드 값은 그 문항 보기 번호 안이어야 한다(`check_questionnaire` Q-04).
응답자 분류가 복잡하면(파트별 진입 조건) 파트 앞에 **참고 표**(`kind: table` — 정의 · 대상 조건 · 응답 파트)를 둔다(실태조사 「참고. 응답자 분류」).

### 3-6 입력형
- 숫자: `(          ) 명` + `[RANGE: 하한 ~ 상한]`. 금액은 단위(`원` · `만원` · `원/월`)와 `[PROG: 숫자로 기입, 한글 표기 노출]`.
  RANGE 는 구조화에 없으면 상식선으로 두고 `review` 를 단다.
- 여러 칸 입력(사업체명 · 사업자번호, 층수 · 엘리베이터)은 `fields` 표. 합계 칸은 `sum: true` + `[PROG: 합계]`.
- 연도별 입력은 `columns: ["2023년", "2024년", "2025년"]`.
- 서술형은 빈 박스. 선택 응답이면 `[PROG: 필수 입력 해제]`, 「없음」 체크가 필요하면 `[PROG: 없음 추가]`.

### 3-7 표지와 끝맺음
- **표지(기본)** — 로고·제목 표 아래 `■ 조사 대상자` (`- ` 줄들) · `■ 조사 방법` · `■ 샘플 수` · `■ 조사 쿼터`(표). 로직 구성 예시 3벌과 실태조사가 이 꼴이다.
- **인사말 박스(`meta.greeting`)** — 응답자가 표지를 직접 보는 공공·기관 조사(성과조사 · 만족도 조사)에 넣는다:
  조사기관 소개 → 조사 목적·의뢰기관 → 「통계법 제33조(비밀의 보호)」 문구 → 협조 부탁 → 문의처(담당자·연락처).
  담당자 이름·연락처는 **사람에게 받는다** — 지어내지 않는다. 모르는 자리는 `==[담당자·연락처 확인 필요]==` 처럼 노란 형광으로 비워 둔다.
  틀 (괄호 안만 바꾼다):
  ```
  안녕하십니까? 조사기관 마크로밀엠브레인입니다.
  본 조사는 (조사 목적)을 위하여 (의뢰기관)의 의뢰를 받아 실시하는 것입니다. 본 조사의 결과는 (활용처)에 기초자료로 활용될 계획입니다.
  귀하께서 응답하신 내용은 연구와 통계 목적으로만 사용되며, 통계법 제33조(비밀의 보호)에 따라 비밀이 보장됩니다.
  바쁘시더라도 잠시 시간을 내시어 설문에 참여해 주시면 감사하겠습니다.
  (조사 연월)
  ▣ 담당자 : ㈜마크로밀엠브레인 ==(이름) (직함)==
  ▣ 연락처 : ==(전화)==
  ```
- **끝맺음(`meta.closing`)** — 사례품이 있으면 `gift` 금액을 받아 `ED.` 수령 여부 + 개인정보 수집·이용 동의 박스. 없으면 `– 설문에 응답해 주셔서 감사합니다. –`.
  `closing: false` 면 끝맺음을 넣지 않는다(실사팀 기본 종료 화면을 쓰는 경우).

## 4. 설문명세.json

```jsonc
{
  "meta": {
    "title": "2026 ○○ 이용 실태조사",
    "cover": {"target": ["…"], "method": "온라인 조사", "sample": "총 500명",
              "quota_table": [["구분", "20대", "…"], ["남성", "60", "…"]], "extra": ["■ 조사 기간 : …"]},
    "greeting": "안녕하십니까? 조사기관 마크로밀엠브레인입니다.\n…",      // 선택
    "closing": {"gift": "5,000원 금액권"},                            // 또는 {"text": "…"} · false
    "skipped_src": ["구성안!55"],                                      // 반영하지 않은 구조화 행 (사유는 변환 메모에)
    "notes": ["…"]                                                    // 변환 메모 (사람이 볼 결정 사항)
  },
  "parts": [
    {"code": "SQ", "title": "Screening Question", "intro": "* …", "prog": ["…"],
     "items": [ /* 문항 또는 안내 */ ]}
  ]
}
```

문항 필드

| 필드 | 뜻 |
|---|---|
| `code` | 문항번호 (안내·본문 줄은 없음) |
| `kind` | `single` · `multi` · `rank` · `scale` · `matrix` · `number` · `open` · `yesno` · `list`(리스트·드롭다운·지도) — 번호 있음 / `info`(안내 박스) · `text`(본문 줄) · `table`(참고 표, `rows` 첫 행이 머리) — 번호 없음 |
| `text` · `note` | 문장 · 줄바꿈 뒤 부연 (`* …`). 인라인 `**굵게**` `__밑줄__` `[#파이핑#]`(`[#연도별]` 처럼 닫는 # 없어도 됨) `==노란 형광==`(사람이 채울 자리) |
| `options` | `["남성", "여성"]` 또는 `{"text", "terminate", "exclusive", "other", "note", "no"}` — `기타` 는 기입란이 자동으로 붙는다. `columns` 를 함께 주면 보기×열(연도) 체크 표 |
| `options_table` | 묶음 보기 `[{"group": "아시아", "options": [...], "cols": 4}]` (번호는 묶음을 넘어 이어서 매긴다). 단일·복수·순위 모두 쓸 수 있다 — 대분류에 따라 소분류를 보이는 단계형 문항은 묶음 표 + `[PROG: SQ1 응답에 따라 해당 대분류만 제시]` |
| `options[].note` | 보기 뒤에 붙는 짧은 부연 (`→ 판매업/서비스업만`) |
| `cols` | 한 줄에 놓을 보기 수 |
| `rotation` · `ordinal` | `true` · `false` · 직접 문구 / 순서형 보기(로테이션 검사 제외) |
| `max` · `min` | 복수 선택 개수 제한 |
| `rank` | `{"required": 1, "optional": 3}` |
| `scale` | `{"preset": "만족"}` 또는 `{"labels": [...]}` · `"extra": ["모름"]` |
| `rows` · `columns` · `per_item` | 행렬 행 / 선택형 행렬 열 / `[항목별 1개 선택]` |
| `unit` · `range` · `columns` · `fields` | 숫자 입력 단위 · `[RANGE:]` · 연도별 칸 · 여러 칸 입력 `[{"label", "unit", "answer", "sum"}]` — `answer` 를 주면 기입란 문구를 그대로 쓴다(`( ) – ( ) – ( )`) |
| `box` · `lines` | 서술형 빈 박스(기본) · 기입 줄 직접 (`a. 회사 근무 기간 : ___년`). **`1)` 로 시작하지 않는다** — 파서가 보기로 읽는다 |
| `base` | `"A1=1 | 현재 이용자"` → `[BASE: …]` |
| `prog` · `prog_before` | 보기 아래 / 문항 위의 `[PROG: …]` 목록 |
| `quota` | 번호 뒤 `[쿼터]` |
| `boxes` | 문항 바로 아래 안내 박스(정의 등) |
| `marker` | 응답 표기를 직접 줄 때만 |
| `src` | 근거 구조화 행 `["구성안!12"]` — **모든 문항에 단다** (추가 문항만 비움) |
| `review` | 사람 확인이 필요한 이유 → 번호가 노란 형광 |

예시 전체: `engine/tools/questionnaire_fixture/sample_spec.json` (모의 조사, 모든 kind(text 포함)).

## 5. 사람에게 넘기는 것 (지어내지 않는다)

- 담당자 이름·연락처·사례품 금액·조사 기간·쿼터 수치 — 구조화·제안서에 없으면 묻는다
- 구조화에 보기가 없어서 **새로 지은 보기** · 상식으로 둔 RANGE · 추론한 BASE → `review`
- 구조화 셀 색·빨간 행의 뜻, 고객 메일 요청 중 구조화에 반영되지 않은 것
- 구조화끼리 충돌(응답대상과 응답 로직이 다름), 척도 방향을 뒤집은 곳, 번호를 새로 매긴 곳 → `meta.notes`
- 전반 평가의 `모름` 허용 · 조사 중단 기준 · 쿼터 문항 — 의뢰인 합의 사항

## 6. 검수

`check_questionnaire.py` (Q-01~Q-16) 가 기계로 본다: 번호 형식·중복·접두 · BASE/파이핑 참조와 순서 · BASE 코드 범위 · 유형별 필수 요소 ·
기타 위치 · 배타 보기 · 척도 방향 · RANGE · 로테이션 결정 · **구조화 행 누락** · 조사 중단 장치 · 지시문 속 겹친 대괄호 · **파서 왕복**(docx → `parse_questionnaire`).
치명 0 이 수용 조건이다. 기계가 못 보는 것(문장 자연스러움 · 겹질문 · 유도 · 보기 MECE · 조사 목적 대비 빠진 질문)은
`questionnaire-adversary` 에이전트가 반증 시도로 본다.
