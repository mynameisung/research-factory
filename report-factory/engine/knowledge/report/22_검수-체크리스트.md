## A. 치명 — 하나라도 걸리면 납품 금지

### A-1. 멘트 수치 환각 `MENT-NUM`
멘트에 나오는 **모든 숫자**를 통계표 원본과 1:1 대조한다. 목표는 **0건**이다.

```python
# 멘트에서 숫자 추출 → 해당 표의 표시값 집합에 있는지 확인
nums = re.findall(r'-?\d+\.?\d*', ment)
```

실측 사고: SKEE 가이드 C163 `761.4%` (71.4% 오타)

### A-2. 미기입 마커 잔존
덱 전체를 문자열 검색한다.

| 마커 | 실측 |
|---|---|
| `???` | LG 제작본 s26~29 — `【TOP2】 ???%`, `【BOT2】 ??? %` |
| `내용을 입력하세요` | LG 제작본 s2(목차), s14(결론) |
| `텍스트를 입력` | 템플릿 잔재 |
| `Data 입력` | 제작팀 메모가 안 지워졌거나 안 채운 슬라이드 |

**`Data 입력` 메모는 채운 뒤 반드시 삭제한다.**

### A-3. Base n 오기
각 슬라이드의 `[Base: …(n=NN)…]` 을 통계표의 `Base for %` 값과 대조한다.

실측 사고: LG 제작본 s6 `[Base : 전체 응답자(n=1,000), Unit : %]` — 실제 n=100이고 포맷도 다른 장과 불일치
(콜론 앞 공백 / `/` 대신 `,`).

정상 형태: `[Base: 전체(n=100)/ Unit: %]`

## B. 기계 검사

### B-1. 소수점
| 대상 | 자릿수 | 확인 |
|---|---|---|
| % | 1 | `33` 이 아니라 `33.0` — 뒤 0을 살린다 |
| 평균 | 2 | `4.2` 가 아니라 `4.20` |
| NPS | 2 | |

반올림은 **ROUND_HALF_UP**. 통계표 저장값(무한소수)이 아니라 **서식 적용 후 값**을 썼는지 확인한다.

### B-2. 합계 정합
- 단일선택 표: 데이터 행 합 = `계` = 100.0 (±0.1)
- 척도: `【BOT】 + 【SoSo】 + 【TOP】` = 100.0 (±0.1)
- 순위 1순위 표: 합 = 100.0
- 중복응답 · 1~N순위: 합 100 초과가 정상. **`계` 행이 없어야 한다**

### B-3. 센티널 라벨 정확 표기
| 문자열 | 확인 |
|---|---|
| `Base for %` | 앞 공백 없음 |
| `      계` | **앞 공백 6칸** |
| `【BOT2】` `【SoSo】` `【TOP2】` | 전각 렌티큘러 `【 】` |
| `【BOT3】` `【TOP3】` | 7점 척도 |
| `[5점 평균]` `[7점 평균]` | **반각 대괄호 `[ ]`** |
| 보기 라벨 | 앞 공백 2칸 (`  4) …`) |

전각/반각 혼용이 가장 흔한 실수다.

### B-4. `그래프 상단 Text` 배치
- `【TOP】` 행과 `[N점 평균]` 행에 **있어야** 한다
- `【BOT】`·`【SoSo】` 행에는 **없어야** 한다
- 제작가이드 `본문` 시트에서는 조건부서식으로 **글자가 빨개진다.** 안 빨개지면 오타

누락되면 Top·평균이 그래프 위에 안 나온다.

### B-5. 정렬
| 표 종류 | 기대 순서 |
|---|---|
| 단일선택 · 척도 | 보기번호 오름차순 |
| 중복응답 | 전체 값 내림차순 |
| 순위 | **1~N순위 값 내림차순** (1순위 값이 아니다) |
| 시계열 · 고정 보기순서 | 원래 순서 유지 |

### B-6. 문항 텍스트
`Qu: ` 접두 + 설문지 원문 그대로. 순위 문항은 꼬리표 포함 (`…_1+2+3순위 (중복응답)`).

## C. 눈으로 보는 것

### C-1. 문항코드 오타
실측 사고: LG 제작본 s63 소제목 `BB1-5)` — 시나리오 4번 블록이므로 `BD1-5)` 가 맞다.

블록 인덱스와 코드 접두가 일관된지 순서대로 훑는다.

### C-2. 멘트 보기명 = 데이터 행 라벨
실측 사고: SKEE 가이드 C744 `'타건설사 대비 …'` vs 행 라벨 `타 건설사 대비 …` (띄어쓰기 불일치)

### C-3. 따옴표 짝
실측 사고: SKEE 가이드 C762 `소통 원활'` — 여는 따옴표 누락

### C-4. 문체
- 개조식 `~임 / ~함 / ~순임`
- **마침표 없음**
- 보기 라벨은 작은따옴표
- 수준어가 사다리와 맞는가 (<50 미흡 / 50%대 보통 / 60%대 약간 긍정 / 70%대 긍정 / ≥80 우수)

### C-5. n<30 처리
- Base/Unit 둘째 줄에 각주 (LG 덱은 `*Too small base(n<30)`)
- 멘트는 패턴 D (**퍼센트 쓰지 않음**)
- 배너 선별 후보에서 제외

⚠ 각주 문자열은 프로젝트마다 다르다. LG 덱은 이 하나뿐이고,
`* 소수 응답 생략` · `* 1+2+3순위 기준 10% 미만 제외` 는 SKEE 가이드 쪽 문자열이다.

### C-6. 차트가 지시대로 나왔는가
`guide/12 §6` 역산표로 대조한다.

⚠ **불일치가 곧 오류는 아니다.** 제작팀이 판단으로 바꾼 경우가 있다.
LG 79장 중 7장이 불일치였고, 그중 3건은 **연구원 쪽이 틀렸다**:
- s25~29: 등급형 사다리를 기본형으로 지정 → 제작팀이 누적 100%로 (같은 가이드의 요약 블록엔 올바르게 적혀 있었다)
- s17: 보기 4개짜리를 원그래프로 지정 → 제작팀이 가로막대로
- s93: 일반 단일선택에 `전체 : 표` → 제작팀이 기본형으로

불일치는 `TYPE` 태그로 뽑아 두고 **규칙 후보로 승격**시킨다.

### C-7. 제목 변경
제작팀이 슬라이드 제목을 바꾸기도 한다.
실측: `2. 건설사 대비 당사 수준` → `2. 경쟁사 대비 당사 수준`

**제작본이 가이드와 100% 일치한다고 가정하지 않는다.** 제목 불일치는 오류가 아니라 변경 이력일 수 있다.
목차와 간지의 표기도 함께 바뀌었는지만 확인한다.

### C-8. 목차 · 간지 정합
- `목차(보고서용)` 의 Part/항목 ↔ 실제 슬라이드 순서
- 첫 페이지 목차에는 **Part만**, 간지에는 **세부 목차만** (`목차(보고서용)!C1` 지시)
- 페이지 번호

## E. 실패 태그

골든셋 채점과 검수 리포트가 공유한다.

| 태그 | 뜻 | 심각도 |
|---|---|---|
| `MENT-NUM` | 멘트 수치 오류 | **치명** |
| `BASE` | Base 문자열·n 오류 | 높음 |
| `TOPTEXT` | `그래프 상단 Text` 누락/과다 | 높음 |
| `TYPE` | 차트 타입 불일치 | 중간 (규칙 후보로 승격) |
| `SORT` | 정렬 오류 | 중간 |
| `QA` | 문항 텍스트 불일치 | 중간 |
| `MENT-STYLE` | 문체 위반 | 낮음 |
| `MENT-PICK` | 배너 선별 타당성 | 낮음 |
| `MAP` | 매핑 실패 | 별도 집계 |
