## 1. 프로세스 5단계

```
[입력] 조사개요·RFP·To Know List  +  설문지  +  통계표
                    ↓
        ① 목차 설계  (슬라이드 타이틀 / 서브 타이틀)                    ← 우리
                    ↓
        ② 제작가이드(.xlsm) 작성                                      ← 우리 · 업무 A
           본문 블록 전량 + 멘트 + 요약·결론 배치 지시
                    ↓  연구원 → 제작팀 (완전 수작업, AI 미사용)
        ③ 제작본(.pptx) 회신                                          ← 제작팀
                    ↓
        ④ 반복 장표 채우기 + 멘트 보강 + 수치 검수                      ← 우리 · 업무 B
                    ↓
        ⑤ 연구원 전달 → 과업 종료
```

> "제가 전달드린 시장 개요 파일이랑 그다음 설문지 파일 통계표 파일을 가지고 제작 가이드를 만들어 줘야 돼요.
> 제작 가이드를 만들어 준 다음에 (…) 던져주면 내가 그걸 제작팀에 넘기고 (…) 회신을 주면
> 이제 반복 장표라는 걸 작업을 하고 멘트나 이런 거 좀 넣고 그다음에 결론 요약 장표 이런 걸 작성을 하고
> 나한테 다시 던져주면 돼요." (00:05~00:21)

### ★ 핵심 효율화 — ②에서 멘트까지 쓴다
> "이거를 후작업하지 말고 제작 가이드 할 때 멘트를 같이 쓰면 걔네가 멘트도 넣어줘요." (15:14)
> "만약에 그렇게 하면은 제작본에 넘어올 때는 이제 그 반복 장표 채워주세요만 나오겠죠." (52:58)

②에서 멘트를 다 써 두면 ④가 **빈칸 채우기**로 줄어든다.
실측으로도 확인된다 — 멘트가 비어 있던 **LG 제작본은 99장 중 71개의 빨간 메모**가 붙어 왔고,
멘트가 다 채워져 있던 **SKEE 제작본(126장)에는 메모가 0개**다.

### 요약·결론은 업무 B가 아니라 A에 들어간다
요약·결론 장표도 제작팀이 만든다. 그러므로 제작가이드에 **배치 지시로 써 넣는다**.
> "이거 만들어줘요." / "응 요약 결론을 쓰는데" (38:31~38:41)

## 2. 등장인물

| 주체 | 역할 |
|---|---|
| **발주처** | 조사를 발주한 클라이언트. 무엇을 알고 싶은지가 `To Know List` 에 있다 |
| **마크로밀엠브레인 (MME)** | 수행사 |
| **연구원** | 설문 설계 · 테이블 가이드 작성. 제작가이드~보고서 구간을 우리에게 넘긴다 |
| **우리** | 제작가이드 작성 (업무 A) + 제작본 후작업 (업무 B) |
| **DP팀** | 테이블 가이드를 받아 **통계표를 생성**한다 |
| **제작팀** | 제작가이드를 받아 **PPT를 만든다. 완전 수작업, AI 미사용.** PPT를 모르는 사람도 알아볼 수준의 지시가 필요하다 |

> "걔네들이 정말 수작업으로 하는 거야. 제작(팀)" (34:21)
> "그 PPT 아예 모르는 애들도 할 수 있게 설명해 주는" (53:43)
> "얘네 AI 안 쓰거든요. 얘네 이거 직접 지들이 꾸미는 거거든요." (40:17, 음성인식 오류 원문 "AI in스거든요")

**제작팀이 사람이라는 사실이 이 업무의 모든 규칙을 설명한다.**
- 차트 타입이 통제 어휘가 아니라 자유 서술인 이유
- `그래프 상단 Text` 같은 조직 내부 신호가 존재하는 이유
- 빈칸을 `-` 로 치환하는 이유 (빈칸을 오해하지 않게)
- 반복 장표를 대표 1장만 만들고 나머지를 우리에게 넘기는 이유

## 3. 용어 사전

| 용어 | 뜻 | 근거 |
|---|---|---|
| **테이블 = 통계표** | 완전히 같은 말. DP팀이 뽑는 문항별 집계표 | "통계표가 테이블이에요. 똑같은 말"(05:25) / "테이블이라는 단어가 우리 리서치만 쓰는 단어라 모를까 봐 통계표라고"(05:29) |
| **테이블 가이드** | 통계표를 어떻게 뽑을지 DP팀에 주는 지시서. **사실상 표 목차 = 보고서 페이지 목차** | "이 테이블 가이드를 DP 팀에 주면 DP 팀이 테이블을 주는 거야"(04:42) / "테이블 가이드 이 목차로 나올 거라"(04:44) |
| **제작가이드** | 통계표 → PPT를 어떻게 만들지 제작팀에 주는 지시서(`.xlsm`). **우리의 주 산출물** | I-013 |
| **제작본** | 제작팀이 만들어 회신하는 PPT | 00:21 |
| **배너 (Banner)** | 통계표의 **열** = 교차분석 축 | "이거를 배너라고 한다 했잖아요. 열을"(07:44) |
| **베이스 (Base)** | 해당 문항에 응답한 사람 수(n) | "이 문항에 응답이 몇 명인지를 적는 거거든요"(23:20) |
| **반복 장표** | 양식이 동일한 슬라이드. 제작팀이 대표 1장만 만들고 **나머지는 우리가 채운다** | "얘랑 얘랑 양식이 똑같잖아요. 그래서 얘는 안 만들어줘요"(11:38) |
| **Top2 / Bottom2 / SoSo** | 척도의 상위2점 합 / 하위2점 합 / 보통이다. 7점 척도면 Top3·Bottom3 | "탑 3는 5 6 7점", "밑에 3개 1 2 3점, 소소는 보통이다"(32:29~32:36) |
| **그래프 상단 Text** | 제작팀 통제 어휘. Top·평균 행 라벨 옆에 **이 말을 적어야** 그 값이 그래프 위에 표시된다 | "저걸 빼는 방법은 이 앞에 그래프 상단 텍스트 이렇게 적어놓으면 쟤네가 위에다 빼놔요"(33:10) / "안 쓰면 (…) 안 나와 이게 안 나와요"(33:52) |
| **간지 / 표지 / 목차** | Part 구분 슬라이드 / 표지 / 목차. Chart type 칸에 이 단어만 적는다 | 실측 (LG 6개 / SKEE 10개) |
| **PM / FM** | 자산관리(Property Management) / 시설관리(Facility Management) | 00:55~01:00 |
| **NPS** | Net Promoter Score. 추천 의향 점수. 소수 2자리 | SKEE 본문 C1974 `추천 의향은 -17.86점(NPS 점수)으로 미흡한 수준임` |
| **IPA** | Importance-Performance Analysis. 중요도×만족도 매트릭스 | SKEE Chart type `좌 : IPA, 우: 가로 겹침 막대` |

## 4. 산출 형태 2종과 입력물

| | **업무 A · 제작가이드** | **업무 B · 보고서작성** |
|---|---|---|
| 언제 | 통계표 입고 후 ~ 제출 마감 | 제작본 회신 후 |
| 입력 | 조사개요·RFP·To Know List / 설문지 / **통계표** | 제작본 `.pptx` + 통계표 |
| 하는 일 | 목차 설계 → 본문 블록 전량(차트타입·베이스·QA·멘트) → 요약·결론 블록 → 검증 | 반복 장표 채우기 → 멘트 보강 → 수치 전수 검수 |
| 산출 | `.xlsm` + `_제작팀송부본` | 최종 `.pptx` + 검수리포트 |
| 지식 문서 | `guide/10~15` | `report/20~22` |

## 5. 제작가이드 `.xlsm` 은 사내 RPA 템플릿이다

파일은 두 층이다. **아래층은 절대 건드리지 않는다.**

### 층 1 — 사내 RPA 템플릿 (수정 금지)
| 시트 | 상태 | 내용 |
|---|---|---|
| `Cover` | 보임 | 보고서 설정 + `검수 실행` 버튼(`[0]!RPA_logic_chk`) |
| `PPT_data` `목차` `한글_data` | 숨김 | RPA 작업 영역 |
| `ItemCheck_PPT` `ItemCheck_한글` | 숨김 | 연쇄 드롭다운 소스 + `초기화` 버튼 (`[0]!Verification_init1/2`) |
| `Verification_PPT` | 숨김 | **339행 공식 차트 분류 체계**. `A1 = "Verification (수정금지, 시트삭제 금지)"` |
| `Verification_한글` | 숨김 | 148행 |
| `Coding No` | 숨김 | 5자리 코드북 |
| `Basic_Set` | 보임 | 슬라이드 레이아웃 범례 + `A40:A45` 에 6개 라벨 원본 + `A5 = Ment` |
| `xl/vbaProject.bin` | — | `Sub lovelySeoyeon()` (Module1) |

- `검수 실행` 버튼은 **외부 애드인 매크로**를 호출한다. 애드인이 없는 PC에서는 동작하지 않는다.
- `Basic_Set!F8` 은 RPA 픽커 검증식이다. 예시 파일에서 실제로 `FALSE` — **연구원이 RPA 픽커를 쓰지 않고 차트 타입을 한국어 산문으로 직접 타이핑했다는 증거**다.
- **`Sub lovelySeoyeon()`** = 선택 영역의 눈에 빈 칸을 전부 문자열 `-` 로 치환하는 매크로. 제작팀이 빈칸을 오해하지 않게 하려는 용도다. SKEE 본문에 `-` 가 수백 개 박혀 있다.

### 층 2 — 우리가 쓰는 부분 (작업의 100%)
`목차(보고서용)` · `part 3 목차(연구부 확인용)` · `본문`(LG는 `본문_제작용`)

### 우리 템플릿
`engine/templates/TEMPLATE_제작가이드.xlsm` — SKEE 예시를 **zip 레벨로 복제**해 층 1을 바이트 그대로 보존하고,
층 2만 비운 뒤 `_치트시트` · `_스니펫` 두 시트를 얹었다.
`_` 로 시작하는 시트는 제작팀 송부본을 만들 때 삭제한다.

## 6. 이 업무의 어려움은 분업 때문이다

> "이거 다 그냥 설계단에서 그냥 다 이미 결정된 거네. 많은 것들이. 지금 이게 분업이 너무 과도하게 되다 보니까 이렇게 일이 어려워 보이는 거지."
> "맞아요. 표 나올 때 PPT가 나와요." (37:56~38:13)

통계표가 나오는 순간 PPT의 내용은 사실상 결정돼 있다.
남은 것은 **① 어떤 차트로 그릴지 ② 어떤 숫자를 읽어줄지 ③ 무엇을 인사이트로 뽑을지** 셋뿐이고,
①은 규칙으로 100% 결정되고 ②는 대부분 결정되며 ③만 판단이 남는다.
