## 원칙 (PPT 팀과 공유)

1. **생성은 스크립트, 판단은 에이전트, 결정은 사람.**
2. **문장의 정본은 가이드 팀이다.** 멘트·제목·base_label 은 여기서만 짓는다.
   소비자(PPT 팀)가 결함을 발견하면 고치지 않고 반송한다.
3. **시야 분리가 에이전트 분리보다 먼저다.** 검증관·심사관에게 제작 경위를 주지 않는다.
4. **문장 생성을 에이전트에 맡길 때는 기계 검증기가 뒤를 막는다.**
   실증: 본문 멘트 50장 병렬 재작성 — 초안은 에이전트, 수용은 검증기
   (줄 ≤60자 · ㅁ종결 · 보기명 라벨 원문 일치 · 수치 부분집합)가 결정한다.

## 정본 스키마 (slide_facts.json) — 소비 계약

PPT 팀이 읽는 필드(변경 = breaking, 사전 통지):
`order · question_code · slide_title · sub_title · qu · title_full · base_unit ·
base_note · ment · chart_type · grid.{banner_group_row, banner_label_row, base_row,
rows[].label/label_clean/kind/cells, rank_overlay, rank_columns}`

1단계 확장(2026-08-22 반영): `slides[].base_label`(군 이름 — base<전체 장 필수) ·
`slides[].short`(문항 약칭 단일화). base_unit 은 `[Base: {base_label}(n=…)…]` 로 재생성.
2단계(요약 몸통 착수 전): `summary_map`(꼭지·패널·claims: 문장↔근거셀) ·
`conclusion_map`(결론 항목 ↔ 요약 꼭지 ↔ ToKnowList).

## 문장 정책 (정본 소관 — 2026-08-22 확정)

- **모든 멘트 줄 ≤60자** (멘트 상자 한 줄 실측 74자 · 여유 14자), 개조식 ㅁ받침 종결
- 요약 헤드라인은 수치 없는 판단문 **≤40자 권장** (R-130 유지)
- **보기명은 행 라벨 원문 그대로** — 축약·의역 금지 (금지 사고 유형). 압축은
  나열 절단·줄 분할·주어부 압축으로만
- 요약 패널 주제명은 역할을 말하되 **측정을 왜곡하지 않는다** — 한정구 보존
  (「무엇이 중요한가」✗ → 「관리 업무 중요도」), 표본 단위 명시 (「한 사람이…」✗)
- 주장을 쓰기 전에: 그 주장을 지지할 **문항이 설문에 존재하는가** → 근거 셀은 어디인가
  → 반대 증거가 같은 정본에 없는가

## 세션 간 규약 (2026-08-22 양 세션 합의)

- **한 파일 한 주인.** 소유권: 가이드 산출물·정본 데이터·engine = 가이드 세션 /
  PPT 산출물·setup_deck/build_body·`2_보고서작성/HANDOVER.md` = PPT 세션.
  상대 파일에 쓸 것이 있으면 수정 대신 메시지.
- 재빌드는 정본 변경을 **모아서 한 번에** 통지 → 소비자가 그때 빌드한다.
- **반송은 양방향** — 쓰는 쪽이 파일 주인:
  · PPT → 가이드: `2_보고서작성/work/반송_가이드팀.md`, ID `R-PPT-NNN`
  · 가이드 → PPT: `1_제작가이드/work/반송_PPT팀.md`, ID `R-GD-NNN`
  처리 기록은 받은 쪽이 자기 로그에 (가이드: `반송처리_로그.md`).
- **검증 findings 공용 규격** (회고 스킬이 소비): 에이전트 산출은
  `findings[]`(격추) · `verified[]`(쳤으나 못 깬 검사) · `not_checked[]` 로 남기고
  가이드 쪽은 `1_제작가이드/work/검수/` 아래 저장한다. "안 봤음" ≠ "봤는데 못 깼음".
- **회고는 공동으로** — 각 세션은 관찰만 내고(규칙 후보 아님) 한쪽이 취합한다.
  만든 세션이 자기 회고를 단독으로 돌리면 전제를 그대로 갖고 간다. 같은 결함을
  서로 다르게 기억하면 그 불일치 자체가 관찰이다.
