# 18. 오케스트레이션 — 제작가이드 스킬의 파트별 담당 구조

v2 2026-08-22. v1 을 guide-judge 가 심사해 findings 23건을 냈고(원문:
`02_비상주/1_제작가이드/work/검수/judge_guide18_v1.json`) 전부 반영했다.
사용자 문제 제기: 한 에이전트가 다 하면 컨텍스트 이슈로 품질이 떨어진다 —
목차·맨처음 장·본문 문항별·요약결론에 담당이 필요하고, 각 담당은 축적된
함정·노하우를 참조하며, 프로세스가 돌 때마다 개선되어야 한다.

## 0. 무엇이 분업의 근거이고, 무엇이 아닌가

**정직한 원인 분류** (17호·23호의 확정 분류를 그대로 쓴다 — v1 은 이를
"컨텍스트 열화"로 갈아 끼웠다가 심사에서 격추됐다):

| 사고 | 확정 원인 | 처방 |
|---|---|---|
| Base 「전체」 28장 | 스키마·규칙 부재 | base_label 필드 + 기계 검사 |
| 멘트 184자 | 한계 미측정 (길이 정책 부재) | ≤60자 정책 + 기계 게이트 |
| 주제명 카피화 | 명명 규칙 부재 + 판단 | 명명 원칙 + 심사 |
| 「의사결정자 개인 1인」 | 판단 결함 — **반대 증거(B2)를 못 봄** | claims 근거셀 의무 + 반증 |
| 998) 잔존 | 도구 가정 미검증 | 자릿수 무제한 수색 정례화 |
| 워크플로 배치 무반환 14장 | 암시적(계산식) 배정 | 명시적 ID 배정 (§3-1, 기록: `work/검수/observations_260822.md`) |

따라서 **시야 축소는 콘텐츠 정확성 장치가 아니다.** 과잉해석 사고는 "너무 봐서"가
아니라 "덜 봐서" 났다. 시야 축소가 유효한 자리는 둘뿐이다 —
① 검증자의 **독립성** (judge/adversary 가 제작 경위를 안 보는 것)
② **불필요 컨텍스트 절약** (멘트 담당이 다른 장 90표를 들 필요가 없는 것).

**분업의 실제 근거 네 가지**:
1. **규칙 팩 집중** — 카드 129장(실측; 82장은 도구·통계표·report 소관)을 통짜 로드하면
   희석된다. 담당은 자기 팩(12~20장)만 로드한다.
2. **컨텍스트 총량** — 70장 × (팩트+문장+검증)을 한 컨텍스트가 끝까지 들면 후반이
   흐려진다는 사용자 관찰. 장 단위 샤딩이면 각 샤드는 항상 초반 품질이다.
3. **병렬 처리량** — 본문 70장·재작성 50장급 작업의 실측 병목.
4. **게이트 명확화** — 담당·산출 계약이 갈리면 수용 기준을 기계로 박을 수 있다.

**콘텐츠 정확성은 시야가 아니라 산출 계약이 지킨다**: 근거셀 의무(claims) ·
기계 검증기 · 독립 반증. 이것이 이 문서의 제1원칙이다.

> 23호(PPT 팀)와의 관계 — 같은 관찰("하나가 다 하려니 못 한다")에서 23호는 "에이전트가
> 답인 곳은 2곳뿐"이라 결론했다. 모순이 아니다: 업무 B 의 생성은 결정적 배선(스크립트)이
> 가능하지만, **업무 A 의 생성물은 문장과 설계 그 자체**(목차·멘트·요약)라 생성 계층에도
> 에이전트가 필요하다. 대신 수용은 똑같이 기계가 결정한다.

## 1. 구조 — 스킬 하나 + 담당 정의, 서브스킬 분할은 하지 않는다

오케스트레이션(순서·배정·병합·재시도·사람 게이트)은 SKILL.md 하나가 갖고,
시야·팩이 다른 자리마다 `.claude/agents/guide-*` 담당 정의를 둔다.
스킬을 쪼개면(`/제작가이드-목차` 식) 순서 책임이 사람에게 넘어가고 문서가 N벌이 된다.

## 3. 오케스트레이션 규약

1. **배정은 명시적 ID 목록.** "인덱스 i%N" 계산 배정 금지. 반환 ID 를 검산하고
   누락분은 재발주한다. 근거: 본 세션 실측 — i%4 배정으로 1개 배치 14장 무반환,
   명시 seq 목록 재발주로 14/14 회수 (`work/검수/observations_260822.md`).
   선례: 멘트입력_1~5.json 도 명시 페이지 구간 배분이었다.
2. **수용은 기계가 결정한다.** 스키마(StructuredOutput)로 받고 검증기 통과분만 정본에.
   재시도는 반려 사유를 붙여 1회, 2회 실패면 사람 큐. 무한 루프 금지.
3. **파트 팩** — `engine/learning/packs/` 를 make_packs.py 가 RULES.md 에서 생성
   (구현됨). 분류 태그 + **명시 카드 목록**(태그 경계와 안 맞는 카드용) 2중 지정.
   손으로 두 벌 유지하지 않는다.
4. **관찰 환류.** 담당 산출 스키마는 17호 공용 3필드(findings/verified/not_checked)에
   `decisions[]`(사람 결정 필요)와 `observations[]`(관찰 — 규칙 후보 아님)를 더한 5필드다.
   ⚠ `engine/learning/observations.jsonl`(훅 자동 포착)과는 **동명이물** — 담당 관찰은
   `{프로젝트}/work/검수/` 아래 파일로 쌓인다. 이 규격 확장은 PPT 팀에 통지한다.
   고리: 검수 산출 → /회고(사용자 승인) → RULES 갱신 → make_packs 재생성 → 다음 실행.
5. **사람 게이트 (닫힌 목록 아님)** — 목차 확정 · 인사이트 방향 · 예외 승인 · 규칙 등재 ·
   **첫 5장 포맷 승인(R-101)** · 배너 범위/장분리(종료 조건이 곧 첫 5장 리뷰 — Q-002·Q-MAP-01).
6. **신뢰도 `가설`·`검증중` 카드** — 담당은 적용하지 말고 `decisions[]` 로 올린다.
   사용자 확인은 오케스트레이터가 받는다 (담당은 사용자와 대화하지 않는다).
7. **룰엔진 공백 경로** — chart_type null·미구현(Q-011·Q-021 류) 팩트를 받은 담당은
   문장화하지 않고 `decisions[]` 로 올린다. R-088: 「미구현」과 「해당 없음」을 구분해 적는다.

## 4. 담당 간 인터페이스 — 한 파일 한 주인, 팀 안에서도

| 산출물 | 주인 | 포맷 계약 |
|---|---|---|
| work/목차.md | **guide-toc → 메인이 확정본 관리** | `build_guide.parse_toc` 고정 포맷 (펜스 목차 블록 · 배정표 · Part Ⅱ 설계). 자유 서술 금지 — 파서가 죽는다 |
| Part Ⅰ 내용·Cover 값 | guide-front 는 **제안 JSON** 만 낸다 | 메인이 목차.md(Part Ⅰ 항목)와 빌드 인자(--title/--date/--cover)에 병합 |
| slide_facts.json ment | guide-body-ment (샤드별) | 검증기 통과분만 메인이 병합 기록 |
| summary_map/claims | guide-summary | 17호 2단계 스키마 (§5-2 에서 구현) |
| work/검수/*.json | 각 검증·심사 실행 | 공용 5필드 규격 (§3-4) |

**샤딩 단위 (양방향)**: 표 N장 → 장 1개(순위 `_1순위`+`_1~N순위`, 매트릭스)는 그 묶음이
한 샤드. 장 N개 ← 표 1개(R-089 배너 분리)도 **같은 표에서 갈라진 장들은 같은 샤드** —
다른 담당이 같은 표를 두 번 문장화하는 것을 막는다.

   rules.yaml 개정이라 **사용자 승인 사안**.

6. SKILL.md 배선 (Step 2·2'·3·4 에 담당·게이트·재시도)
7. 파일럿 **병행**: TA Pool 은 toc(기확정안 대조)·body 만 부분 가동 / **guide-summary 와
   claims 게이트는 비상주 요약 구간 재실행으로 검증** (정답이 있어 대조 가능).
   TA 단독은 부적격 — 요약 없음·목차 기확정·응답자 특성 표 부재·본문 21장.

## 6. 열린 문제

- 팩 커버리지: 129장 중 82장(63.6%)은 도구·통계표·report 소관이라 팩 밖 — 의도적이나,
  향후 카드 추가 시 "어느 팩에도 안 실림" 목록을 make_packs 출력에서 정기 확인.
- guide-summary 전수 스캔의 컨텍스트 비용 — 90표 전수는 무겁다. 완화책(표별 요약 통계로
  1차 선별 후 후보 표만 원본 정독)은 파일럿에서 측정 후 결정.
- 병렬 샤딩의 문체 미세 불일치 — 게이트가 문형은 못 잡는다. 파일럿 1회 후 판단.
