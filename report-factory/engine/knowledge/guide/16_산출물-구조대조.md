# 16. 산출물 구조 대조 【업무 A】

> 이 문서는 **사고 하나에서 나왔다.** 제작가이드를 만들어 "검수 치명 0"까지 통과시켰는데,
> 사용자가 파일을 열어보고 **표지·목차·간지·조사개요·요약결론 블록 33개가 통째로 없다**는 걸
> 즉시 알아챘다. 검수기는 여러 번 통과시켰다. (I-022)

---

## 1. 왜 못 잡았나 — 원인 4겹

| # | 무엇 | 왜 위험한가 |
|---|---|---|
| ① | **복제 원본을 만들기 편한 기준으로 골랐다** | "구조가 비슷하다 / 참고 시트가 남아 있다"는 *제작자의 편의*다. 골라야 할 기준은 **실제 제출 양식**이다 |
| ② | **산출물을 예시와 통째로 대조한 적이 없다** | 블록 목록만 나란히 뽑았으면 3초 만에 보였다. 부분 검사만 촘촘히 했다 |
| ③ | **검수기가 제작자의 사각지대를 물려받았다** | 검사 항목은 제작자의 머릿속 모델을 옮긴 것이다. 빠뜨린 것은 검사에서도 빠진다 → `치명 0` 이 반복 통과 |
| ④ | **골든셋 채점 범위를 좁힌 것 자체가 사각지대였다** | 모수를 "본문 79장"으로 잡으면 표지·목차·간지는 원리적으로 채점 대상이 아니다. 루프를 몇 라운드 돌려도 안 걸린다 |

**한 줄로**: 자기가 만든 것을 자기가 정한 기준으로만 검사하면, 빠뜨린 것은 영원히 안 보인다.

---

## 2. 교정 ① — 복제 원본은 "제출 양식" 기준으로 고른다

예시가 여러 개일 때 우선순위:

1. **사용자·연구원이 지정한 것** — 지정이 있으면 그게 끝이다. 다른 기준을 앞세우지 않는다
2. 같은 클라이언트의 최신 건
3. 그래도 갈리면 **묻는다.** 임의로 고르고 넘어가지 않는다

**고르면 안 되는 기준** (전부 제작자 편의다)
- "우리 조사와 문항 구조가 비슷하다"
- "참고용 시트가 살아 있어 편하다"
- "파일이 더 깨끗하다"

> 이번 건: 비상주가 5점척도라 SKEE 와 구조가 같고 `Basic_Set` 범례가 남아 있다는 이유로 SKEE 를
> 골랐다. 실제 제출 양식은 **LG 홈로봇**이었다.

---

## 3. 교정 ② — 산출물 ↔ 예시 **스켈레톤 대조**를 필수 단계로

빌드 직후, 검수 전에 **한 번 돌린다.**

```
예시 제작가이드            우리 산출물
─────────────────         ─────────────────
시트 목록·순서·탭색     ↔   같은가
시트명 (본문_제작용)     ↔   같은가
블록 종류 시퀀스         ↔   빠진 종류가 있는가
목차(보고서용) Part 수   ↔   같은가
part 3 목차 헤더         ↔   같은가
Cover 설정 항목          ↔   같은가
```

**블록 종류 시퀀스**가 핵심이다. 예시에서 블록을 `Chart type` 기준으로 종류만 뽑으면:

```
표지 → 목차 → 간지 → (본문) → (본문) → (본문) → 간지 → (본문)… 
```

우리 산출물에서 같은 걸 뽑아 **종류 집합을 비교**한다. 예시에 있는데 우리에게 없는 종류가
하나라도 있으면 **빌드를 통과시키지 않는다.**

### 왜 "종류"인가
개수는 조사마다 다르다(챕터 14개 vs 3개). 하지만 **종류**는 같아야 한다 —
표지가 있는 보고서와 없는 보고서가 따로 있지 않다.

---

## 4. 교정 ③ — 검수에 **구조 완결성** 검사군을 둔다

`verify.py` 의 기존 검사(V1~V13)는 전부 **블록 내부**를 본다. 블록이 아예 없으면 볼 것이 없다.
그래서 **블록 바깥**을 보는 검사가 따로 있어야 한다.

| 검사 | 무엇 |
|---|---|
| 구조 블록 존재 | 표지 · 목차 · 간지(Part) · 간지(챕터) 가 있는가 |
| Part 완결성 | `목차(보고서용)` 에 Part Ⅰ·Ⅱ·Ⅲ 가 다 있는가 (요약결론이 없는 조사는 Ⅱ 제외) |
| 목차 ↔ 본문 정합 | 목차의 챕터가 본문의 챕터 간지와 1:1 인가 |
| 시트 스켈레톤 | 시트 목록·순서·탭색·시트명이 예시와 같은가 |
| 템플릿 무결성 | 숨은 시트 9종 · VBA · CF 가 살아 있는가 (기존 V8) |

**설계 원칙**: 검사 항목을 만들 때 "내가 만든 것을 확인하는 검사"만 쓰지 말고,
**"예시에는 있는데 내게 없는 것을 찾는 검사"** 를 반드시 하나 둔다. 전자는 자기 확인이고
후자만이 사각지대를 연다.

---

## 5. 교정 ④ — 골든셋 채점 범위를 좁히지 않는다

역검증 하네스의 모수를 "본문 N장"으로 잡으면 그 밖은 **영원히 채점되지 않는다.**

- 기본 모수는 **전 슬라이드**다
- 특정 종류를 빼야 한다면 **뺐다는 사실과 이유를 스코어카드에 명시**한다
- "채점 불가"와 "채점 대상 아님"을 구분해 적는다 — 전자는 다음 라운드의 숙제이고 후자는 결론이다

> 이번 건에서 차트타입 100%(74/74)를 두 라운드 연속 달성했지만, 그 74장은 전부 본문이었다.
> 구조 블록은 애초에 모수 밖이라 만점과 결함이 공존했다.

---

## 6. 실행 체크리스트 (빌드 → 제출 사이)

- [ ] 복제 원본이 **지정된 제출 양식**인가 (편의로 고르지 않았는가)
- [ ] 시트 목록·순서·탭색·시트명이 예시와 같은가
- [ ] **블록 종류 시퀀스**에 예시에 있고 우리에게 없는 종류가 없는가
- [ ] `목차(보고서용)` 에 Part 가 전부 있는가
- [ ] 목차의 챕터 ↔ 본문의 챕터 간지가 1:1 인가
- [ ] Cover 의 프로젝트 값(제목·제출일)이 이번 건으로 바뀌었는가
- [ ] **Cover 의 로고·테마글꼴·차트색이 이전 클라이언트 것이 아닌가** ← 복제하면 그대로 따라온다
- [ ] 숨은 시트 9종·VBA·CF 가 살아 있는가

> 마지막 두 항목이 복제 방식의 대가다. 복제는 서식을 공짜로 얻는 대신
> **이전 클라이언트의 흔적도 같이 가져온다.**
