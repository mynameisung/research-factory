## 0. 대전제 — 통제 어휘가 아니라 자유 서술이다

`Chart type` 칸에 들어가는 문자열은 드롭다운이 아니다. 제작팀이 사람 눈으로 읽는다.

> "저거 그냥 그 제작팀이 알아보게 쓰면 돼요. 그래프 위에 텍스트 써주세요 이렇게" (녹취 34:16)

그래서 실측에서 띄어쓰기가 제각각이다 — `배너 : 표` / `배너: 표`, `가로막대` / `가로 막대` / `가로 막대 그래프` 가 한 파일 안에 섞여 있다.
**비교할 때는 반드시 정규화한다** (`chart_rules.yaml#normalization`).

`.xlsm` 안에 사내 RPA 픽커(`Verification_PPT` 339행 분류 체계)가 있지만 **연구원은 그걸 안 썼다** — `Basic_Set!F8` 이 `FALSE` 다.
우리도 산문으로 직접 타이핑한다.

## 3. 판별 신호 — 통계표에서 읽는다

문항 유형은 설문지(`questionnaire.json#response_type`)가 아니라 **표(`tables.json#hints`)로 판정한다.**
설문지는 의도이고 표는 실측이기 때문이다. (예: 비상주 설문지의 `척도` 9 + `행렬` 3 → 실제 척도 표는 11문항)

| 신호 | 필드 | 뜻 |
|---|---|---|
| `【BOT2】`·`【SoSo】`·`【TOP2】` 행 | `has_scale_rows` | 척도 |
| `[5점 평균]` / `[7점 평균]` | `has_mean_row`, `scale_points` | 척도 점수 |
| 제목 `…_1순위` / `…_1~3순위 (중복응답)` | `is_ranking`, `rank_scope`, `rank_is_first_only` | 순위 |
| 제목 `(중복응답)` | `is_multi` | 복수응답 |
| 제목 `…_TOP2 Summary` / `…_Mean Summary` | `is_summary`, `summary_kind` | 요약표 |
| `      계` 행 | `has_total_row` | 단일선택 |
| 첫 표 `응답자 특성` | (표 인덱스 1) | 응답자 특성 |

> "전혀 공감하지 않는다, 이 바텀투 소소 탑 얘가 있으면 척도 문항이에요." (32:20)

## 4. 유형별 상세

### 4-1. 척도 — `전체 : +-세로막대 그래프`
보통이다를 0선으로 놓고 부정은 아래(회색), 긍정은 위(밝은색)로 뻗는다.

> "보통이다를 기준으로 마이너스 부정적인 애들은 회색으로 뽑고 긍정적인 애들은 밝은 색으로 뽑고" (31:30)

**행 순서**: 보기번호 오름차순 → `      계` → `【BOT】` → `【SoSo】` → `【TOP】` → `[N점 평균]`
**`그래프 상단 Text` 를 `【TOP】` 행과 `[N점 평균]` 행에만 붙인다.** BOT·SoSo에는 붙이지 않는다.

> "바텀이랑 소소는 안 중요하잖아요. 탑이 중요하잖아요." (32:47)
> "소소까지는 필요가 없어요." (34:40)

제작본 실측:
- 7점 척도 → `COLUMN_STACKED`, 7계열, valAx `-100 ~ 100`, 부정 계열 음수 입력, numFmt `0.0;0.0;\ `
- 5점 척도 → `COLUMN_STACKED_100`, 5계열, valAx `-1 ~ 1`

### 4-2. 순위 — `전체 : 가로겹침막대, 배너 : 표`
1순위 표와 1~N순위 표가 **한 페이지**가 된다.

> "테이블 두 개를 합쳐서 만드는 건데 (…) 얘가 이 아예 흐린 애들로 들어가고 이 앞에 진한 애는 얘로 들어가요." (28:46)
> "이 얘는 1순위보다 1 2 3순위가 더 중요하잖아요. 얘는 1 2 3순위의 내용으로 들어가면 돼요. 그래서 1순위에서 가져올 건 이 전체밖에 없어요." (28:46~29:04)

- **정렬**: 1~N순위 값 내림차순
- **1순위 표에서는 전체 열만** 가져온다 (배너는 1~N순위 표 것을 쓴다)
- 1순위는 사람당 1개라 합이 100, 1~N순위는 중복이라 최대 N×100 (28:27~28:41)
- 두 표의 보기 순서는 원래 다르다 — DP가 각각 자기 값으로 내림차순 정렬해 주기 때문 (29:04)

제작본 실측: `BAR_CLUSTERED` 2계열, 긴 값(1~N순위)이 먼저(뒤·흐림), 1순위가 나중(앞·진함).

**★ 판별을 계열 수로 하면 틀린다.** `BAR_CLUSTERED + 2계열 + overlap=100` 을 기준으로 잡으면 **오탐 8건**이 난다.
여분 계열이 순위 오버레이가 아니라 **특정 보기만 다른 색으로 칠하려고 쪼개 놓은 더미**인 경우가 있기 때문이다
(실측된 더미 계열명: `do not know`, `열2`, 배너 그룹 헤더 문자열).

올바른 기준은 **두 계열이 카테고리를 공유하는가** 다.
- 순위 오버레이 → 두 계열이 **전 카테고리를 공유**한다 (같은 보기에 1순위 값과 1~N순위 값이 나란히 붙는다)
- 색분리용 더미 → 카테고리를 **하나도 공유하지 않는다** (한 계열이 값을 가지면 다른 계열은 빈칸)

### 4-3. 예/아니오 — `전체 : 원그래프, 배너: 표`
> "예/아니오라는 질문에만 원 그래프를 때리면 돼요." (36:34)
> "원 그래프는 대부분 예/아니오만 써요." (37:19)

선택 기준은 설득력이 아니라 미관이다.
> "설득을 위한 게 아니고 그냥 보기 예쁘면 그렇게 쓰는 거예요." (37:34)

보기가 3개 이상이면 쓰지 않는다 — LG s17이 반례이자 확증이다(아래 §5 D-002).
제작본 실측: `DOUGHNUT`.

### 4-4. 응답자 특성 — `전체 : 표`
> "전체 표는 응답자 특성이에요. 전체가 다 표로 들어가." (30:46)

차트 없이 표만. 전체 값만 쓴다. **이 슬라이드 전용이다.**

### 4-5. 척도 요약 KPI — `top2 : 세로막대 그래프, 5점평균 : 상단 표`
척도 문항이 **연속 5개 이상**일 때 Top2·평균만 모아 한 장으로 만든다.

> "척도 문항이 하나 있을 때는 서머리를 넣을 필요가 없잖아." / "척도 문항이 한 5개 이상 있으면 위에 탑2 민을 넣어요." (51:26~51:34)
> "이 탑투랑 민은 본문에 넣는 게 아니고 보고서 요약 결론을 쓰려고 넣은 거라" (50:24)

**본문에 넣지 않는다. 요약·결론용이다.**

#### ★ TOP2 Summary 와 Mean Summary 는 한 슬라이드로 합쳐진다
문자열 자체가 그렇게 말한다 — `top2 : 세로막대 그래프` **+** `5점평균 : 상단 표`.
Top2는 세로막대로 그리고, 평균은 그 위에 표로 얹는다.

SKEE 실측 (본문 449~467행, 블록 21 `6. 관리자 역량`):

```
Chart type   top2 : 세로막대 그래프, 5점평균 : 상단 표
Base/Unit    [Base: 각 관리자별 관련 업무 경험자/ Unit: %, 점]     ← n 을 생략한다
Data
             관리자 역량
                        E456 그래프 상단에 평균 표 표기   F456 각 그래프마다 base 표기
             D457 top2   E457 5점 평균
             C459 현장소장    D459 76.19   E459 4.19   F459 [Base: 21]
             C460 설계담당자  D460 65.38   E460 3.92   F460 [Base: 26]
             …
             C471 하단에 1/3 공간만 만들어주세요
```

- **C열** 항목명 / **D열** top2 / **E열** 5점 평균 / **F열** 행별 base
- 행마다 base 가 다르므로 `Base/Unit` 에서 `n=` 을 생략하고 행마다 `[Base: NN]` 을 붙인다
- 행 수식어 `그래프 상단에 평균 표 표기` (평균 열) · `각 그래프마다 base 표기` (패널)

**⚠ Mean Summary 표에 `top2 : …` 문자열을 붙이면 안 된다.**
Mean Summary는 슬라이드를 따로 만들지 않고, 짝이 되는 TOP2 Summary 슬라이드의 한 열이 된다 (**CT-061**).
비상주 실측 짝: 표19(A8_TOP2) ↔ 표20(A8_Mean), 표65(D6_TOP2) ↔ 표66(D6_Mean).

`hints.summary_kind` 값은 `top2` / `top3` / `mean` 이다 (`top` 아님).

통계표에 요약표가 아예 없으면 각 척도 표의 `【TOP2】`·`[5점 평균]` 행을 긁어 **직접 만든다** (50:50). → `guide/14`

## 5. ★ 가이드 ↔ 제작본 불일치 — 정답은 제작본이다

연구원이 적은 문자열과 제작팀이 만든 차트가 어긋난 자리가 있다.
**제작팀이 판단으로 바꾼 것이므로 제작본이 정답이고, 불일치 자체가 규칙 후보다.**

LG 79장 중 **72장 일치 / 7장 불일치**. SKEE는 매핑된 57장 중 56장 일치 / 1장 불일치.

| ID | 슬라이드 | 가이드가 쓴 것 | 제작본이 만든 것 | 진단 |
|---|---|---|---|---|
| **D-001** | LG s25~29 (A10-1~5) | `전체 : 가로막대, 배너 : 표` | `BAR_STACKED_100` (누적 100% 가로막대) | 보기가 등급 사다리(일상적/간헐적/드물게/절대 비허용)이고 합이 100 → **CT-050 (가설)**. 아래 참조 |
| **D-002** | LG s17 (A1) | `전체 : 원그래프` | `BAR_CLUSTERED` + 표 | 보기 4개짜리를 원그래프로 지정. 원그래프는 2개 전용 → **CT-040 확증** |
| **D-003** | LG s93 (C1) | `전체 : 표` | `BAR_CLUSTERED` + 표 | `전체 : 표` 를 일반 단일선택에 사용 → **CT-010 확증** (응답자 특성 전용) |
| **D-004** | SKEE 10점 척도 | `+/- 5점 척도 (9,10점을 0보다 위로…)` | `COLUMN_STACKED_100` | 자유 서술이 표준형으로 실현. 불일치가 아니라 매핑 |

### D-001 — 가이드가 스스로 모순된다

이건 제작팀이 판단으로 바꾼 게 아니라 **연구원이 본문에서 실수한 것**이다.

같은 LG 가이드 파일의 **요약 블록(row 128, 인라인 Chart type row 153)** 에는 `A10-1` 이
`전체 : 가로 누적 100% 막대 그래프` 로 **올바르게** 적혀 있다.
연구원은 맞는 타입을 알고 있었는데 본문 5개 블록에는 기본값 `전체 : 가로막대, 배너 : 표` 를 복붙했고,
제작팀이 바로잡았다.

→ 그래서 판별의 핵심은 척도 행(`【TOP】`/`【BOT】`)의 유무가 **아니다.**
**보기가 등급/빈도 순서를 이루고 각 행의 보기 합이 100인가** 로 판단한다.

**연쇄 사고**: 차트가 누적 100%로 바뀌면서 `【TOP2】`·`【BOT2】` 자리가 붕 떴고,
s26~29에 `【TOP2】 ???%` `【BOT2】 ??? %` 가 그대로 남았다. 차트 타입 오지정 하나가 미기입 4장을 만들었다.

#### 판별을 어떻게 구현했나
의미상의 기준은 "보기가 등급/빈도 사다리를 이루고 각 항목의 보기 합이 100인가" 다.
그런데 **라벨 키워드로 등급형을 추측하면 오탐이 많다.** 그래서 실행 가능한 구조 신호로 대리한다:

```
척도 행 있음(has_scale_rows) + 평균 행 없음(has_mean_row=false) + 매트릭스(is_matrix_item) + 보기 ≤ 4
```

- 평균이 없다 = 등간 점수가 아니라 **순서 범주**라는 뜻
- 매트릭스다 = **항목 간 비교**가 목적이라는 뜻 → 누적 막대로 나란히 놓는 게 맞다

**비상주 전수 적용 결과: 해당 표 0장.**

| 문항 | 판정 | 근거 |
|---|---|---|
| A4 공실 수준 | 해당 없음 | 라벨은 정도 사다리(거의 만실 / 일부 / 다소 / 많은 편)로 보이지만 **척도 행이 없고 매트릭스도 아니다**. 사람이 한 번 볼 가치는 있어 `OPEN_QUESTIONS` 에 올렸다 |
| C2 외부 전문업체 지원 방식 | 해당 없음 | 매트릭스이고 계 100이지만 보기가 등급이 아니라 범주형(전체 위탁/부분 위탁/단건/컨설팅/미정)이고 DP가 값 내림차순으로 정렬해 왔다 |
| A2 건물 준공연도 | 해당 없음 | 순서형이지만 시간 구간이다. 사다리가 아니라 분포 |
| A5 입주사 수 | 해당 없음 | 수치 구간 + 평균 행 존재 |

**신뢰도 `가설`.** 근거가 예시 1건(5개 항목)뿐이다. **적용 시 사람 확인을 받는다.**

## 7. 배너 — ★ 열 수는 고정이 아니다

절단선을 **위치가 아니라 그룹명으로** 판정해야 한다.

DP가 표마다 base 0 인 배너 범주를 통째로 빼기 때문에, 같은 조사 안에서도 표마다 열 수가 다르다.

비상주 실측:
- **전체 배너 열 15~45** (41열이 58표로 최빈, 최소 15열, 최대 45열)
- **보고서 IN 열 6~17** (17열이 61표, 나머지는 6~16열)
- 표42(B8)·표56(C4-1)에는 오히려 배너군이 **하나 더** 붙어 있다 (`가장 중요한 위탁 서비스`, `우선 도입 희망 업무` — 각 7표)

```
IN  = [전체, 용도, 권역, 관리 운영 방식]                       ← 그룹명 화이트리스트
OUT = [건물 연면적, 소유 형태, 지역지구, 건물 준공연도, 입주사 수,
       가장 중요한 위탁 서비스, 우선 도입 희망 업무]
```

**열 인덱스로 자르면 깨진다.**

### 물리 상한 — ★ 고정 상한은 없다

> "PPT로 하는 거니까 열에 제한이 있을 거잖아요." (07:59)

제한은 실재하지만 **숫자로 못박을 수 없다.** 고정된 것은 **표 전체 폭 32.0cm** 뿐이고,
열 너비는 제작팀이 슬라이드마다 다시 잡는다.

LG 제작본 실측:
- 본문 표의 **열 수가 8 / 9 / 11 / 12 / 15 / 16 / 17 / 24 로 제각각**
- 표 전체 폭은 32.0cm 고정
- 선두 열 너비 프로파일 5종

"1.5cm × 14열" 은 상한이 아니라 **흔한 한 경우**일 뿐이다.
지식 문서에도 룰 엔진에도 열 수 상한을 박지 않는다.

실무 판단은 "열이 많아 좁아 보이면 열폭 축소, 그래도 안 되면 장분리" 이고,
**최종 결정은 첫 5장 리뷰에서 연구원·제작팀과 맞춘다.**
제작팀 메모 `장분리` 가 그 협의의 흔적이다.

## 9. 제작본을 정답으로 읽을 때의 주의

골든셋 채점기와 `verify.py` 가 제작본에서 정답을 역산할 때, **두 덱이 서로 다르다.**
한쪽에서 통한 가정이 다른 쪽에서 깨진다.

| # | 함정 | 실측 | 대응 |
|---|---|---|---|
| DP-001 | **placeholder idx 를 믿으면 안 된다** | SKEE는 sub=idx13 / ment=idx12 인데 **LG는 79장 전부 반대** (idx12 = sub_title at T=2.62, idx13 = 빈 ment at T=3.42) | idx가 아니라 **위치(top_cm)** 로 판정 |
| DP-002 | **SKEE 덱에는 문항코드가 아예 없다** | 본문 슬라이드에 `소제목` shape 자체가 없고 덱 전체에서 문항코드 매치 0건. LG는 79장 전부 있음 | 조인 키 = 문항코드 우선, 없으면 **slide_title + sub_title 폴백** |
| DP-003 | **제작팀 메모가 없을 수 있다** | LG 71건 / **SKEE 0건** | `Data 입력` 메모가 항상 있다고 가정하지 않는다 |
| DP-004 | **Base 박스 위치가 고정이 아니다** | 다단 슬라이드에서는 T=17.13 우측정렬이 아니다 | 텍스트 패턴 `[Base:` 로 찾는다 |
| DP-005 | **제작팀이 제목을 바꾸기도 한다** | `2. 건설사 대비 당사 수준` → `2. 경쟁사 대비 당사 수준` | 제작본이 가이드와 100% 일치한다고 가정하지 않는다. 제목 불일치는 오류가 아니라 변경 이력 |

Base 각주도 프로젝트마다 다르다. **LG 덱의 각주는 `*Too small base(n<30)` 하나뿐**이고,
`* 소수 응답 생략` · `* 1+2+3순위 기준 10% 미만 제외` 는 SKEE 가이드 쪽 문자열이다.
한 덱에 전부 있는 게 아니다.

### 8-2. 언제 어떤 그래프가 효과적인가 — 데이터 모양이 정한다

차트는 취향이 아니라 **데이터의 모양**이 정한다. 아래는 「무엇을 보여 주려는가」로 먼저 가르고, 그 안에서 문항 유형으로 좁힌다.

**① 구성비 — 전체를 100으로 쪼갠다**
| 언제 | 그래프 | 왜 |
|---|---|---|
| 보기 2개(예/아니오) | **원** | 두 조각은 원이 가장 빨리 읽힌다. 3조각까지는 무리 없다 |
| 보기 3~5개, 합 100 | **100% 세로누적막대** 또는 가로100%누적막대 | 원은 4조각부터 각도 비교가 어렵다 |
| 집단마다 구성비를 비교 | **가로100%누적막대**(행 = 집단) | 막대마다 100%라 집단 간 구성 차이가 그대로 보인다 (R-145 전치) |
| 보기 6개 이상 | 구성비를 포기하고 **가로막대**(값 내림) | 조각이 얇아져 못 읽는다. 합이 100이라는 사실은 표로 남긴다 |

**② 순위·크기 비교 — 무엇이 큰가**
| 언제 | 그래프 | 왜 |
|---|---|---|
| 다보기(중복응답)·자유응답 코딩 | **가로막대** (값 내림) | 라벨이 길어 가로가 유리하다. 우리 최빈형(CT-900) |
| 순위 문항(1순위 + 1+N순위) | **가로겹침막대** | 한 막대 안에 1순위를 겹쳐 「먼저 꼽힌 것」과 「언급된 것」을 함께 본다 (CT-030) |
| 집단별로 같은 보기를 비교 | **가로묶음막대**(행 = 집단) | 합이 100이 아니므로 누적을 쓰면 거짓이 된다 (R-153) |
| 항목이 8개를 넘음 | 상위 N 절단 + 가로막대 | 값이 뚝 떨어지는 자리에서 끊는다(절대 임계 아님 — 코퍼스 실측) |

**③ 척도 평가 — 얼마나 긍정적인가**
| 언제 | 그래프 | 왜 |
|---|---|---|
| 척도 문항 1개 | **+ - 세로누적막대** | 보통을 0선에 두고 긍정을 위, 부정을 아래로 갈라 방향이 한눈에 보인다 (CT-020, LG 36·SKEE 42) |
| 척도 문항 5개 이상 연속 | **TOP2 Summary + 5점 평균** (100% 세로누적막대 + 평균) | 개별 그래프 5장은 비교가 안 된다. TOP2 한 줄로 세운다 (CT-060) |
| 척도 여러 개를 한 패널에 | 표당 1행(TOP2 또는 100점 환산)으로 압축 | 코퍼스 실측 — 척도가 패널을 단독으로 차지하면 전행 유지, 여럿이면 압축 |
| 중요도 × 만족도 | **IPA**(산점도 4분면) | 두 축을 곱해 「중점 개선」을 뽑는 것이 목적 |
| 항목이 5~8개이고 프로파일을 보여줌 | **방사형** | 모양 자체가 인상이 된다. 단 항목 순서가 결과를 바꾸므로 축 순서를 고정한다 |

**④ 변화·흐름 — 어떻게 달라졌나**
| 언제 | 그래프 | 왜 |
|---|---|---|
| 시점이 3개 이상 | **꺾은선** | 추세는 선이 가장 정직하다 |
| 시점이 2개(전년 대비) | **가로/세로 묶음막대** | 두 점은 선으로 그리면 과장된다. 코퍼스 SH 청안주가 2024·2025 를 묶음막대로 씀 |
| 단계마다 모수가 좁아짐(인지→이용→만족) | **Funnel** 또는 base 가 다른 패널 3분할 | 같은 100%가 아니라는 것을 보여 주는 것이 요점. 패널마다 Base 를 따로 적는다 |
| 양이 다른 두 지표를 같은 장에 | **막대 + 꺾은선** | 축이 둘이면 막대는 양, 선은 비율·평균을 맡는다 |

**⑤ 가격 — 얼마가 적정한가**
| 언제 | 그래프 | 왜 |
|---|---|---|
| 가격 4문항(싸다/비싸다/너무 싸다/너무 비싸다) | **PSM** | 네 누적곡선의 교점이 최저·최고·적정 가격이다. 이 문항 세트가 없으면 못 그린다 |
| 수용률 + 성공/확신 Zone | **IRP 분석** | 가격대별 볼륨을 함께 보여 판매 구간을 고른다 |
| 가격 구간 분포 | 구간형 **가로막대** + 평균 Text | 구간은 사다리 순서를 지키고 평균은 그래프 위 텍스트로 얹는다 |

**⑥ 두 변수 이상의 위치 — 어디에 놓여 있나**
| 언제 | 그래프 | 왜 |
|---|---|---|
| 브랜드·대상의 상대 위치 | **Map_Brand**(산점도) | 축 두 개로 지도를 만든다 |

### 8-3. 고르기 전에 확인할 것 (실패가 나온 자리)
1. **합이 100인가.** 누적 계열은 합이 100일 때만 쓴다. 중복응답·TOP2 요약·행 선별한 표를 누적으로 쌓으면 거짓이 된다 (R-153 · 실측 171.5 · 124.8 · 198.2).
2. **행이 집단인가 보기인가.** 집단 비교를 그리려면 표를 전치해 행 = 집단으로 둔다. 표와 차트의 방향이 어긋나면 PPT 가 틀어진다 (R-145).
3. **보기 수와 패널 폭.** 묶음 막대는 계열 수만큼 막대가 서므로 1열 폭(6cm)에는 보기 4개까지다. 5개 이상은 전폭에 놓는다 (R-145 ⑥).
4. **저베이스 집단.** n<30 은 별표를 달아 남긴다(R-128). 빼는 것은 규칙이 아니라 연구원 판단이다(C-022).
5. **평균·TOP2 는 그래프 위 텍스트**로 올린다 — 안 적으면 안 나온다 (guide/15 §1-1).
