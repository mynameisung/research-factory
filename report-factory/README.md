# report-factory

엠브레인 리서치 프로젝트의 **통계표 → 제작가이드 → 보고서(PPT)** 파이프라인 플랫폼.

특정 프로젝트 전용이 아니다. 조사가 들어올 때마다 `projects/` 아래에 폴더가 하나씩 늘고, `engine/`은 그때마다 조금씩 똑똑해진다.

---

## 이 업무가 뭔가

리서치 회사는 통계표(테이블)를 뽑고 → 그걸 PPT 보고서로 만든다. 그런데 PPT를 만드는 건 **제작팀**이고, 연구원은 직접 만들지 않는다. 대신 **"이 표를 이렇게 그려달라"는 지시서(제작가이드, `.xlsm`)** 를 쓴다.

```
설문설계 → 실사 → [DP팀] 통계표 → ★제작가이드★ → [제작팀] 제작본 PPT → ★보고서작성★ → 납품
                                     업무 A                              업무 B
```

우리 담당은 **★ 표시된 두 구간**이고, 그 사이에 제작팀이 끼어 있다.

**핵심 효율화**: 업무 A에서 **멘트까지 미리 써두면 제작팀이 멘트도 넣어준다.** 그러면 업무 B가 "빈칸 채우기"로 줄어든다.

---

## 산출 형태 2종

| 스킬 | 업무 | 언제 | 하는 일 |
|---|---|---|---|
| `/제작가이드` | **A** | 통계표 입고 후 | 목차 설계 → 본문 블록 전량 → **요약·결론 블록** → 검증 → `.xlsm` |
| `/보고서작성` | **B** | 제작본 회신 후 | 반복 장표 채우기 → 멘트 보강 → 수치 전수 검수 → 최종 `.pptx` |
| `/회고` | 학습 | 마일스톤마다 | 이번 건에서 배운 규칙을 `engine/`에 역류 |

> **요약·결론은 업무 B가 아니라 A에 들어간다.** 요약·결론 장표도 제작팀이 만들기 때문에 제작가이드에 배치 지시로 써 넣는다.

### 모든 스킬의 Step 0 — 오리엔테이션 (예외 없음)

작업 전에 **반드시** 먼저 한다:
1. `00_공통/`의 조사개요·RFP·킥오프 회의록·**To Know List** 정독
2. 읽은 것을 요약해 사용자에게 제시 (조사 목적 / 의뢰인이 알고 싶은 것 / 조사 성격 / 요약·결론 필요 여부)
3. 방향성 질문
4. 답변을 `ORIENTATION.md`에 기록한 뒤에야 본작업

보고서는 결국 **의뢰인이 알고 싶은 것에 답하는 문서**다. 방향을 잘못 잡으면 뒤 작업이 전부 무의미해진다.

## 폴더 구조

```
report-factory/
├─ INSTRUCTIONS.md          사용자 지시사항 원문 로그 (append만)
├─ handover/                인수인계 녹취록 — 모든 도메인 규칙의 1차 출처
├─ engine/                  ── 재사용 자산 (프로젝트 무관) ──
│   ├─ knowledge/           규칙 문서
│   │   ├─ 00_업무개요.md · 01_통계표-읽는법.md      (공통)
│   │   ├─ guide/           【업무 A】 목차·블록포맷·차트타입·멘트·요약결론·제작팀지시어
│   │   └─ report/          【업무 B】 반복장표·멘트보강·검수
│   ├─ learning/            학습 루프 — RULES.md · OPEN_QUESTIONS.md · observations.jsonl · retro/ · eval/
│   ├─ templates/           TEMPLATE_제작가이드.xlsm · TEMPLATE_프로젝트/
│   ├─ tools/               Python 파이프라인
│   └─ refs/                예시 원본 6종 + ANALYSIS.md (해부 결과 + 멘트 코퍼스)
└─ projects/                ── 건별 작업 ──
    └─ {연도}_{클라이언트}_{프로젝트명}/
        ├─ README.md · ORIENTATION.md
        ├─ 00_공통/          조사개요·RFP·회의록·To Know List
        └─ {NN}_{조사명}/
            ├─ input/       설문지 · 통계표 · 기타 원자료
            ├─ 1_제작가이드/  work/ out/     ← 업무 A
            └─ 2_보고서작성/  in/ out/       ← 업무 B
```

## 파일 네이밍

`{구분자}_{내용}_{일자}.{ext}`

| 구분자 | 대상 |
|---|---|
| `공통_` | 프로젝트 전체 공유 (조사개요·RFP·회의록·To Know List) |
| `{조사약칭}_` | 조사별 (예: `TA_`, `비상주_`) |
| `예시_` | 레퍼런스 (`engine/refs/`) |

---

## 신규 프로젝트 시작하기

1. `engine/templates/TEMPLATE_프로젝트/` 를 복사 → `projects/{연도}_{클라이언트}_{프로젝트명}/` 로 이름 변경
2. 입력물을 네이밍 규칙에 맞춰 배치
3. `/제작가이드 projects/{프로젝트}/{조사}` 실행 — 오리엔테이션부터 시작한다
4. **`engine/`은 건드리지 않는다.** 새로 배운 규칙만 `/회고`로 역류시킨다

## 학습 루프

프로젝트마다 플랫폼이 똑똑해지도록 설계돼 있다. **암묵지가 드러나는 순간**을 자동으로 붙잡아 형식지로 승격시킨다.

| 드러나는 순간 | 포착 |
|---|---|
| AI 산출물을 사람이 손으로 고침 | `out/.baseline/` 스냅샷 vs 최종본 diff ← **가장 값진 신호** |
| 제작팀이 제작본에 빨간 메모를 붙임 | `fill_deck.py`가 메모 전량 수집 |
| 새 차트타입·문항유형 등장 | 룰엔진 매칭 실패 로그 |
| AI 멘트를 지우거나 다시 씀 | 멘트 diff = 유의차 임계 학습 |

포착 → `/회고`가 규칙 후보 제시 → **사람이 승인한 것만** `engine/learning/RULES.md` 등재 → 다음 실행에 즉시 반영.

규칙 신뢰도 3단계: `가설` → `검증중` → `확정`
